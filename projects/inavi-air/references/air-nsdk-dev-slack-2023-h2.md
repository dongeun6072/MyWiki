# Slack #001_air_nsdk_dev 개발 대화 (2023 하반기)

에어·NSDK 앱 개발자 비공개 채널의 2023년 7~12월 대화다. 프로젝트 개요는 [[inavi-air]], 이전 기록은 [[air-nsdk-dev-slack-2022]]와 [[air-nsdk-dev-slack-2023-h1]]을 본다. 하반기에는 팀장, iOS 리드 개발자, 신규 iOS 개발자, Android 개발자(저장소 소유자 이동은)가 주로 대화했다. 버전별 변경은 [[air-app-version-notes-2023]], 기능 스크럼은 [[air-feature-upgrade-scrums-2023]]에 있다.

## AI 횡단보도·보행자 신호 요청 로직 (07~11월)

iOS 리드 개발자가 공유한 로직을 Android가 같이 맞췄다. 프로젝트 맥락은 [[air-ai-crosswalk-scrums-2023]], [[air-daegu-crosswalk-signal-2023]], [[air-right-turn-pedestrian-alert-test-2023]]에 있다.

- **회전 방향 판별(07-03)**: 좌회전 계열 guide code(`GCODE_LEFTWAY`, `GCODE_LEFT_TURN`, `GCODE_TIME7WAY`~`TIME11WAY`, `GCODE_ROTARI_7`~`11` 등)는 좌회전, 우회전 계열(`GCODE_RIGHTWAY`, `GCODE_TIME1WAY`~`TIME5WAY`, `GCODE_ROTARI_1`~`5` 등)은 우회전, 나머지는 직진으로 본다. 좌회전이면 요청하지 않는다. 7/6에는 신호등 1·2코스 로그 주행에서 특이사항이 없었다.
- **방위 코드(07-11)**: 진행 각도를 8방위 코드로 바꾼다(북 10, 동 20, 남 30, 서 40, 북동 50, 남동 60, 남서 70, 북서 80, 45도 구간). 직진이면 같은 축 두 코드(예: [10,30])를 요청한다. 요청 거리는 직진 100m, 우회전 50m이다. 처음에는 TBT 거리가 70m를 넘는 우회전을 직진으로 봤고, 우회전 범위는 시계 방향 배열에서 현재 코드 다음 4개를 썼다.
- **방향 판별 변경(08-30)**: 신호등 노드와 다음 회전 지점 거리가 20m 이상이면 직진으로 본다(70m 규칙 대체). 응답은 요청 방위 코드로 거른 뒤, 우회전이면 횡단 여부와 좌·우 보행자·대기자 플래그 중 하나라도 있을 때, 직진이면 횡단 여부가 있을 때 GUI를 띄운다. 노드당 1회만 요청하고, 신호등 설정이 꺼져 있으면 상태를 초기화한다.
- **우회전 코드 역산(10-05)**: 우회전 범위는 북(10)을 기준으로 방향 코드를 반대로 도는 배열에서 현재 코드부터 4개를 쓰는 방식으로 고쳤다.
- **우회전 25m 재요청(10-18)**: 우회전이면 요청 횟수를 2회로 두고 25m 이하에서 다시 요청한다. 팀장 지시로 50m 요청에서 안내가 나오면 25m 요청은 하지 않고(응답 처리에서 남은 요청 횟수를 0으로), 안내가 없을 때만 25m에서 다시 요청해 갱신한다. 11/1 빌드 때 "신호등 50m 두 번 요청" 사양과 안내 엔진을 함께 반영하라는 팀장 답이 있었다.
- **대구시 테스트(09월)**: 9/11 대구시에 개발 서버 전용 테스트 APK를 전달했다. 9/14 대구시 영상 구간에서 표시되지 않는다는 보고는, iOS 강제 모의주행에선 정상이고 영상에선 교차로에 신호등 핀이 없어 안내 쪽 신호등 체크가 안 된 것으로 봤다. 전달본이 개발 서버 접속 버전이 맞는지도 확인 대상이었다. 당시 대구 교통정보 버전은 상용 0.2, 개발 0.31이었다. Android는 앱 실행 시 저장된 데이터 버전과 서비스게이트의 신호등 버전을 비교해 다르면 서버에서 받아 Guidance에 넣는다. 9/26 사업부와 업체가 테스트했고 서버 수집 로그와 영상을 받았다. 10/6에는 개선 버전 APK(개발 서버 접속)를 다시 전달했다.
- 개방 데이터 API 인증키와 샘플 요청 주소가 원본에 있음(미수록).

## 후면 단속 카메라·마을주민/장애인 보호구역 (07월)

- 7/17 새 카메라 타입이 develop에 들어왔고, 개발 서버에서 후면 과속(21), 후면 신호 과속(22), 장애인 보호구역(23), 마을주민 보호구역(24)으로 내려오는 것을 두 OS에서 확인했다. 음성 안내도 타입에 맞게 나왔다.
- 이전 버전 영향도 확인(07-19): 새 안내 서버에 예전 안내 엔진으로 붙으면 두 OS 모두 기본 음성·효과음·GUI가 나오지 않았다. 7/24 iOS 서비스 버전으로 상용·개발 서버를 다시 확인했을 때 개발 서버 기준으로는 내려오지 않았다.
- iOS는 후면 단속 카메라 배경에 제한속도를 넣고(처음 PR에서 빠져 리뷰로 보완), 지도 핀 enum은 `MAPICON_CAM_CHILD_SILVER`에서 +1씩 늘려 추가했다. CarPlay·대시보드 레이아웃과 CarPlay HUD 화면 과속 표시도 함께 맞췄다. 이미지는 svg로 바꿔도 문제가 없었다. 핀 크기는 Android가 알려 준 값(높이 49, 폭 29, 상단 여백 22)에 맞췄다.

## 메인 화면 리디자인과 툴팁 (07월)

- 메인 에어캐시 카드 뷰를 없애고 하단 탭바 아이콘에 Lottie를 적용했다. 툴팁 시나리오의 첨부 이미지 일부는 스펙아웃됐다. 스펙아웃된 카드 관련 파일은 디자인 리소스가 바뀔 때 같이 정리하기로 했다.
- 툴팁은 캐시 구간별 이미지와 문구를 서버에서 받는다. 문구는 구분자로 흰색·주황색 텍스트를 나눈 한 문자열로 받는다. 구간은 미로그인(로그인 후 첫 주행 +1,000캐시), 0~1,599(음료), 1,600~2,999(편의점), 3,000~4,499(커피), 4,500~4,999(아이스크림), 5,000~10,000(주유소) 쿠폰이다. "캐시가 도착했어요" 같은 문구는 앱이 판단한다. 툴팁은 5초 후 사라지고, 미로그인 상태에서 하단 팝업을 띄운 뒤에는 툴팁을 띄우지 않는다. 다른 화면에 갔다 오면 툴팁이 남던 문제는 화면 전환 전에 숨기도록 고쳤다.
- 하단 팝업: 신규 배너는 1회만, "일주일간 보지 않기" 버튼 없이 표시한다. 하단 팝업 중 푸시가 오면 팝업이 닫히고 다음 실행까지 안 뜨는 문제를 푸시 진입부(`ExternalApiManager`)에서 고쳤다(공통 함수는 건드리지 않음). 배너를 눌러도 자동 스크롤이 돌던 문제도 고쳤고, 안전운행 모드로 바뀌면 하단 팝업을 숨긴다.

## 7월 릴리즈(3.5.7)와 크래시

- iOS 03.05.07은 371이 심사 중이던 상태에서 372로 교체했고, 최종 스토어 버전은 373이었다.
- **373 크래시(07-31)**: 하단 팝업 `autoScroll()`이 다음 셀로 이동할 때 범위를 벗어나는 경우를 처리하지 않아, 배너를 켠 채 오래 두면 크래시가 났다. 범위를 벗어나면 무한 스크롤 가운데로 되돌리게 고쳤다. CarPlay HUD 화면에서 돌아올 때 하단 팝업이 남는 문제도 같이 고쳤다. 크래시 세션의 사용자 키 값이 원본에 있음(미수록).
- 가로 모드 메인 하단 배경이 회색으로 보이던 것은 좌우 기준이 safeArea라서였고 superView 기준으로 바꿨다. 최근 목적지 편집 목록에서 w3w·영문 POI의 g 아래가 잘리는 것도 고쳤다.
- **구글 광고 타국가 노출(07-21)**: 아랍·러시아·일본 광고가 가끔 나온다는 문의에, 앱에서 지역을 고르는 기능은 없고 AdMob admin도 카테고리 차단만 가능하다고 답했다.
- **CarPlay 음성 VOC(07-05)**: 운영팀이 넘긴 이슈로, 안전운전 모드에서 과속 시 화면만 빨개지고 경고음이 없다, 음악 앱을 오가면 안내 음성이 안 들린다는 등 CarPlay 사용 중 음성 문의가 여러 건 들어왔다.

## 요금·검색·기타 버그 (07월)

- **마창대교 요금(07-10)**: 2종 할인율 19354839가 정수 변환 과정에서 19%로 계산돼 2,510원이 나왔다(정상 2,500원). 실수로 계산하면 맞다. 특대형은 3종까지만 할인하는 예외가 있었고, 탐색 프로토콜이 첫 번째 할인 시간대만 내려 주고 있어 추가 시간대 사양을 요청했다. 명지·을숙도대교는 하이패스 할인 예외 목록에 있어 시간대 기준 할인이 적용된다(7/24 1종 오후 7시 테스트에서 할인 요금 확인).
- **통합검색 mode(07-04)**: Android 주변검색의 `searchSQE` mode를 1에서 3으로 바꾸고 통합검색도 3으로 고정했다(iOS는 원래 3 고정).
- **더보기 무한 재요청(07-07)**: 서버가 결과 없음(903)을 주는데 Android가 이를 성공으로 처리하고 목록을 갱신해 `onScroll`이 다시 요청하는 반복이 생겼다. 903을 실패로 처리하는 방안에 Android가 동의하고 영향도 테스트 후 적용하기로 했다. 두 OS 더보기 실패 처리 개선은 별도 티켓으로 잡기로 했다.
- **로그 주행 timestamp(07-13)**: 로그 주행에 timestamp 필드가 있으면 신규 탐색·재탐색(이탈) 요청에 넣도록 개발한다.
- **내비 인증 API(07-07)**: iOS가 인증 서버 값으로 분기하는 부분이 있어 규격서 갱신을 물었고, 팀장은 인증 서버 값 대신 패키지명으로 Agent가 앱을 구분하는 방안을 검토 중이라고 했다. 이후 논의는 다른 채널로 넘어갔다.

## 음성광고 iOS 재생 문제 (07-14)

iOS 재생 버튼에 반응이 없었는데, `AVAudioPlayer`가 ogg를 공식 지원하지 않아 플레이어 초기화가 실패한 것이었다(지원 형식: aac, aiff, m4a, mp3, wav). mp3로 바꾸면 정상 재생됐다. 업체가 준 원본은 wav였고 용량 때문에 ogg로 바꿨던 것이라, 서버에 wav를 올리기로 했다.

## 삼성중공업 SDK (07~11월)

NSDK의 삼성중공업(SHI) 에디션 작업이 이 채널에서도 진행됐다. 상세는 [[inavi-sdk-ios-guide-shi-edition-differences]], [[inavi-sdk-android-shi-edition-diff]], [[orbis-sdk]]를 본다.

- iOS도 기존 저장소 기준으로 진행하고 iOS 가이드를 현행화했다(07-05). iOS에 회원 정보 입력 인터페이스를 추가해 Android도 맞추게 했다(07-19).
- **이탈 재탐색(07-20)**: 실차 로그로 두 OS 모두 정상 동작을 확인했지만, 삼성중공업 요청은 이탈 재탐색을 없애 달라는 것이었다. iOS 리드는 제거하고 이탈 후 종료까지 관제 데이터의 경로 이탈 여부를 "Y"로 보내겠다고 했으나, 팀장은 검토만 요청한 것이고 그날 삼성중공업과 다시 협의해 지원 여부를 정한다고 정정했다. ^[ambiguous]
- **관제 데이터(08-01)**: 제한구역 진입 여부는 현위치와 통제 목록의 mapid·linkid·dir 매칭으로 판단한다. 1초에 1회 수집해 20개씩 묶어 보낸다(10개로 바뀔 수 있음). 사용자 정보는 사용자 ID와 운전자 톤수만 받는다. 주행 시 안전운행 자동 전환 속도를 20km에서 5km로 낮추라는 요청이 있었다.
- 10/4 SHI용 안내 엔진 라이브러리가 공유됐다. 10/13 삼성중공업 Agent 상용 반영 전에 SDK 배포를 먼저 진행하기로 했다.
- **과속 기준 변경 요청(11-16)**: 현행 20/30km 도달 시 앱 경고와 위반 내역 수집을 21/31km로 바꿔 달라는 신규 요청이 들어왔고, 다음 timestamp 작업과 함께 반영하기로 했다(팀장: iOS 리드가 판단해 진행).
- 11/15 경유지 핀 이미지가 전달됐다. 11/20 iOS는 주기가 겹치는 문제를 DP에서 고쳐 적용하고, Android는 수정된 경로 다시 그리기 반영 여부를 물었다. timestamp 건은 그 주 수요일 배포 예정이었다.
- **통신형 지도 데이터 적용 절차(11-22)**: 개발 서버 → QA → 상용(에어와 같은 방식)과 상용 즉시 적용 후 삼성중공업 검증, 두 방안이 제시됐다. 이후 업데이트 정책은 팀장 출장 후 결정하기로 하고, 이번 지도 변경분은 내부 테스트 후 상용에 바로 반영했다.

## 베스텔라랩 연동 (07-06)

인천공항 주차장 관련 업체와 회의해 native 라이브러리가 아닌 webview 라이브러리를 받아 처리하기로 했다. 자료가 오기 전까지 SDK 검토는 미뤘다.

## 제보하기·에어 연구소 리뉴얼 (08~09월)

- **CarPlay 경로선(11-09)**: 대시보드만 `setRouteWidthRatio`를 3.5에서 2.5로 줄였다. 심사가 끝난 빌드를 내리고 다시 빌드했으며, 스토어는 03.05.10(394), TestFlight는 03.05.11로 올렸다.
- **SKP 광고 이벤트(11월)**: 앱은 모바일 웹에 로그인 여부 등을 넘기고 나머지는 웹이 처리한다. 푸시 웹뷰·하단 팝업 아웃링크에 PD·SN을 GET으로 넘기는 구조를 그대로 쓴다. 11/27 Android 심사가 먼저 끝나 28일 이벤트를 위해 Android부터 출시했고, 상용 이벤트 URL이 아직 없어 SKP 버튼은 숨겼다. 스탬프 조회 API의 `skpEventInfo`는 서버가 2024년 제거를 물었지만 다음 이벤트를 위해 유지하기로 했다(앱이 기간을 확인해 노출). 이후 흐름은 [[air-skp-ad-scrums-2024]].
- 에어캐시 화면에 "교환권 등록하기" 버튼(상황에 따라 숨김)이 추가됐다.
- 신규 안내 음성 내부 테스트용 APK(03.05.32, 음성 3종)를 만들었다(11-13). 선호도 조사는 [[air-new-voice-preference-2023-09]].
- 11/20 iOS DP가 주기 겹침 문제를 고치면서 context를 정리하게 되어, 의심하던 메모리 문제도 함께 사라졌는지 확인했다. 수정된 DP로 15~30분 이상 여러 번, Instruments 프로파일로 약 30분 측정했을 때 메모리 문제는 보이지 않았다. 이 DP 수정분은 timestamp 건과 함께 그 주 수요일에 발행하기로 했다.
- 11/8 Android 지도 터치 처리(`TouchControl`) 타이머에서 NullPointerException 로그가 공유됐다(통신 불가 상황).

## HUD(로드피아) 연동 (09~12월)

외주 업체 라이브러리로 HUD 단말과 BLE 연동했다. 사양·시리얼·시험 결과는 [[air-hud-integration-2023]], [[air-hud-data-class-and-bluetooth-spec]], [[air-hud-and-stabilization-scrums-2023-12]]에 있다.

- **샘플 검토(10-06)**: 공유 규격으로 `sendData`가 추가됐고 연결·전송 코드는 동작하지만 실단말이 없어 콜백은 확인하지 못했다. Android aar은 71KB였다. 9/11에 iOS 리드가 Android 기준 BLE 데이터 규격 초안을, 9/18에 라이브러리 사용 예시를 만들었다.
- **권한(11-07~09)**: aar을 넣으면 위치 권한 팝업이 뜨지 않았다. BLE 권한만 같게 넣으면 정상이라 라이브러리 쪽 권한 설정이 원인으로 보였다. Android 11 단말은 연결되지 않았다.
- **연결 상태 콜백(11-20)**: 연결 시도 시 바로 Connect가 오지 않고 Disconnect가 먼저 온다(iOS 1회, Android 2회). 연결 시도 후 30초 동안 상태 변화를 계속 보고, 그래도 안 되면 실패로 처리하기로 했다. "디바이스 연결 해제하기"는 BLE 연결·해제로 연동하고, 차량 탑승 시 자동 실행은 앱 실행 시 HUD 자동 연결(앱 내부 설정값)로 바꿨다(11-17). iOS는 블루투스 권한이 없으면 설정으로 보내는 팝업이 필요하다고 기획에 공유했다. 11/24 iOS 라이브러리(231116·231121)는 연결 중 HUD 전원을 끄면 실패를 2번 받는 문제가 있었다(Android는 없음).
- **S/N 검증(11-20)**: 서버 인증 전에 앱에서 유효성을 검사한다. 앞 3자리 유형 접두어(상용·테스트)와 영숫자로 된 9~10자리 형식을 정규식으로 확인한다. iHUD 앱 로직을 가져온 것이고 Agent 서버 처리는 그대로다.
- **데이터 표시 차이(11-10~14)**: 위치 속도를 보내도 표시되지 않거나 TBT 코드가 두 번째 전송에서야 나오는 등의 문제가 있었다. 모의주행 240km에서 HUD 속도 표시가 OS마다 달랐고(AOS 40, iOS 199), 신호과속(1114) 뒤 남은 거리 0m가 계속 나왔다. Android는 같은 과속 카메라 타입을 다시 보낼 때 아이콘이 안 켜짐, 구간단속 시작 시 신호과속·구간단속 아이콘 동시 점등 등도 문의했다.
- **QA 1차 시험(12월)**: Mantis로 이슈를 관리했다. 라이브러리 수정 요청 항목은 연결 직후 0.5~1초에 끊었을 때 연결 상태로 남는 문제(AOS), 신호 과속 카메라 심볼 미점등, TBT 코드 0일 때 거리 미표시(AOS), 단말 모델별 안전거리 표시 차이였다. 블루투스가 꺼져도 연결되는 문제는 Android 7·9·12에서 재현되고 10·13에선 안 돼(13은 2회 이상 요청 시 비정상 종료) OS 버전 문제가 아니라 라이브러리 동작으로 봤다. 한 단말 모델은 터널(42)일 때 직진으로 표시하는 것 외에 회전 방향을 점등하지 않았다. 음영 지역에서는 HUD 속도 0km를 보내도록 고쳤다(iOS 확인).
- **Android 12 이상 근처 기기 권한(12-13~15)**: Auto 실행 중 근처 기기 권한을 끄고 다시 실행하면 비정상 종료됐다. Android 개발자는 초기 권한 체크에 근처 기기 권한을 넣는 방안을 냈고, 팀장은 Auto 권한 체크 로직을 앱이 고치라고 했다. 12/15 기준 Auto 상태에서는 근처 기기 권한을 확인만 하고, Auto가 아닐 때 권한 요청까지 하도록 바꿨다.
- **라이브러리 교체(12-12~15)**: 새 iOS 라이브러리로 구간단속 시작·종료 거리, 버스 전용차로 표시, 블루투스 OFF 시 연결 페이지 갱신 문제가 고쳐졌다. 다만 BLE가 꺼진 상태에서 연결을 시도하면 실패 응답이 즉시 와서 시스템 팝업이 반복되는 문제가 새로 생겼다(전에는 약 10초 뒤 응답). 연결 페이지 미갱신 이슈 중 HUD 전원 종료 케이스는 다른 HUD 단말에 연결된 탓이었다. Android는 12/13 최신 라이브러리로 블루투스 OFF 시 연결 해제 토스트 미표출, 목적지 TBT가 HUD에 안 나오던 문제, 연결 페이지 미갱신이 고쳐졌다. 외부 테스트 QA용 배포는 회의에서 나온 라이브러리 요청분을 받은 뒤 하기로 했다. 이어 신호 과속 심볼과 TBT 거리 0 처리 수정도 확인했고, Android 9에서 BLE 체크·권한 요청이 되는 것을 보고 버전 체크 로직을 없앴다. Xcode 15.1에서 예전 라이브러리의 swiftmodule이 다른 컴파일러 버전이라 빌드되지 않았고, 12/14 라이브러리로 develop에 넣었다. 이후 라이브러리는 코드로 받기로 했다.
- 11/21 HUD는 적용 단말 안내 등이 부족해 이번 패치에서 beta로 내기로 하고 사업부에 공유했다. 12/28 Android Firebase에서 HUD BT 라이브러리 크래시가 보여 업체 수정을 요청했다.

## 12월 릴리즈(3.5.12~3.5.13)

- 항목: 최근장소·내장소 중간어 검색, 똑똑한 신호등 상세 안내 변경, 내장소 화면 전환 지도 사양 수정, 단축어 지원, 3D Touch 목적지 검색, HUD 검증 이슈 수정, 3D Touch 이미지 누락 수정. iOS 03.05.13은 400, 401로 빌드했다.
- **단축어(12-01)**: 티맵은 집·회사·최근 목적지 단축어를 지원한다. 에어는 집·자주가는곳 단축어를 만들었고, 3D Touch "내장소"가 리뉴얼 전 화면으로 가던 문제도 고쳤다. 401 업로드 후 custom intent(`GoHome`, `GoFavorite`, `GoDriveMode`)의 한국어 제목이 없다는 ITMS-90626 경고를 받아 다음 업데이트 과제(AIR-1497)로 등록했다.
- 12/26 iOS 스토어가 오픈했고, Android는 퇴근 전까지 문제가 없으면 100% 출시할 예정이었다.
- **iOS 15 이하 크래시(12-28~29)**: 중간어 검색의 `indexOfWordInString`에서 24시간에 101건/22명, 이후 418건/82명이 발생했다. iOS 개발자는 소문자 문자열로 구한 range를 원문 문자열 distance에 쓰는 문제로 봤고, iOS 리드는 `distance` 계산이 특정 OS에서 정렬 중 문제를 일으키는 것으로 보고 `NSString` range(대소문자 무시)의 location을 쓰는 코드를 줬다. iPhone 6s(iOS 15.7.3)에서 재현과 수정 코드 동작을 확인하고 커밋·PR하기로 했다.
- 결빙 구간 핀 아이콘은 메인 이미지 크기를 단말 배율(2x·3x) 기준으로 적용해 CarPlay 배율이 다를 때 커지거나 작아졌다. 3x 테스트를 빠뜨린 탓이었고 수정하기로 했다.
- **사당역 비정상 종료(12-08)**: iOS 17 개인 단말에서 첫 탐색 이후 탐색마다 종료됐고, 개발폰(iOS 16·15, Android 10·13)에선 발생하지 않았다. 그 단말의 지도 데이터를 다른 iPhone에 넣으면 재현됐고, Android 단말에선 실행 직후 종료되거나 2회 중 1회 종료돼 엔진 담당에게 넘기기로 했다.
- CarPlay에서 음악 앱과 함께 쓸 때 묵음이 된다는 VOC는 시뮬레이터와 실차 단말(iOS 17.1.1)에서 재현되지 않았다. 에어 앱의 안내 볼륨 음소거 옵션이 CarPlay에서 안 먹는 현상은, CarPlay에 별도 음소거 옵션이 있다는 답을 받았다.
- Android에서 탐색 중 경유지 추가 화면의 추천어에서 최근 목적지를 누르면 경유지로 추가되지 않고 그 목적지로 바로 길찾기가 되는 문제가 보고됐다(12-01).
- 테스트용으로 Auto 로그 저장 APK(03.05.33, 전체경로 선택 시 저장·종료), 출발지를 회사로 고정한 APK를 만들었다. 12/22 Android 수정 항목(경유지 추가 상세화면에서 다른 마커 클릭 시 버튼 변경, 추천어 동순위 등록순)은 Jira 백로그에 올렸다.
