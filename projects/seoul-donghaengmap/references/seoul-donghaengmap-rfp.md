# 서울동행맵 고도화 제안요청서(RFP)

㈜티머니가 발주한 제안요청서다(76쪽). 입찰 공고는 2026-05-07~05-28, 제안 평가는 06-02부터, 협상과 계약은 06-04부터 진행됐다. 사업 전체 맥락은 [[seoul-donghaengmap]]에 있고, 협상 결과는 [[seoul-donghaengmap-negotiation-kickoff]]에 있다.

## 사업 개요

- **사업명**: 서울시 교통약자지원 통합플랫폼(서울동행맵) 고도화 구축 사업
- **기간**: 착수일로부터 12개월
- **예산**: 23억 원(VAT 별도)
- **목적**: 동행맵을 기초로 구축, 교통약자 대중교통 접근성과 편의성 증진, 음성 AI와 실시간 API 연계 등 최신 기술로 편의성 개선
- **운영**: 서울시 데이터센터에서 운영 가능해야 한다.

## 과업 범위 8개 영역

| 영역 | 핵심 요구 |
|---|---|
| 가. AI 음성인식·안내 | STT(소음·방언 대응), NLU(의도 분석), TTS(다국어), 교통약자 특화 명령("몇 정거장 남았어?", "하차 알림 해줘"), 긴급·우회 상황 자동 음성 안내 |
| 나. 앱 교통약자 지원 고도화 | 저상버스·승강설비 우선 경로 옵션, 예약·탑승·하차 단계별 실시간 안내, 고대비 모드와 텍스트 확대, 다국어 |
| 다. 시각장애인 지원 | 전용 음성 가이드 모드, 시계방향·지형지물 안내 문구, 하차 시점 자동 인식, 실내외 다단계 알림 |
| 라. 버스 정보 연계 | BIS(운행정보), BMS(차량 위치), BIT(정류장 표출) 실시간 연계, MQTT 기반 예약·탑승 정보 송수신, 차량 단말기에 우선 탑승 알림 표출, 관제센터 연계 |
| 마. 역사 내부 보행 내비 맵 | 대형 환승역 내부 보행 경로 DB화(엘리베이터·경사로·점자유도선), 실내 맵 기반 AI 경로 탐색과 음성·진동 안내 |
| 바. 버스 플랫폼 안내 개선 | 플랫폼별 도착 예정 버스와 우선탑승 정보, 2정류장·1정류장·도착 다단계 알림, 저상·만차·지연 표시, 운전자 단말 연계 |
| 사. 보행 네트워크 현황 관리 | 시민 불편 신고 접수·검증·중복 확인, 마일리지 정책(신고 유형별 차등 지급), 관리자 웹(신고 조회, AI 분석 결과, 승인·반려, 통계) |
| 아. 교통약자 의견 수렴 | 자문회의 등 의견 수렴 절차 운영과 개발 반영 |

## 앱·서버 구성 요구 (요약)

- 앱 쪽: 음성 녹음 UI, 음성·진동 피드백, 승·하차 예약·변경·취소 UI, 실시간 예약 상태, 고대비/글자 크기/다국어, 이용 이력, 시각장애인 모드, Wi-Fi/BLE 기반 실내 위치
- 서버 쪽: STT·NLU·TTS 엔진, 서비스 로직 수행, 긴급 상황 감지(BIS 연동), 예약 정보 DB 관리, 실내 지도와 전파 지도(Radio Map) DB, MQTT Broker, 전용 데이터 구축 앱(별도)
- 관리자 웹: 대시보드(실시간 접속자, 예약 현황), 사용자·문의 관리, 예약 현황 관리

## 요구사항 분류 체계

요구사항 ID는 분류 약어로 부여한다: ECR(시스템 장비 구성), SFR(기능), PER(성능), SIR·UIR(인터페이스), DAR(데이터), TER(테스트), COR(제약사항) 등. 이후 산출물의 `SIR-001`, `DAR-006` 같은 ID가 이 체계다. ([[seoul-donghaengmap-lbs-collaboration]])

## 목차 구성

1. 사업 개요(범위, 추진 일정) → 2. 사업 수행 내역(제안 요청 개요, 요구사항 상세) → 3. 입찰 일반 사항과 자격, 제안서 제출 → 4. 평가(개요, 방법, 기준, 선정 방법) → 5. 제안서 작성 지침 → 서식(가격 제안서, 참여인력, 유사 사업 실적, 공동수급 협정 등)

## 해석

RFP는 AI(STT·NLU·TTS)와 폐쇄망 설치형 엔진, 실내 위치, 버스 단말 연계처럼 **서로 다른 외부 시스템이 많은 사업**이다. 이후 감리와 협상에서 반복해서 일정 위험으로 지적된 항목이 이 의존성에서 나온다. ^[inferred] ([[seoul-donghaengmap-design-audit]])
