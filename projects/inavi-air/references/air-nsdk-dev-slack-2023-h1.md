# Slack #001_air_nsdk_dev 개발 대화 (2023 상반기)

에어·NSDK 앱 개발자 비공개 채널의 2023년 1~6월 대화다. 프로젝트 개요는 [[inavi-air]], 이전 기록은 [[air-nsdk-dev-slack-2022]], 하반기는 [[air-nsdk-dev-slack-2023-h2]]를 본다. 상반기에는 팀장, iOS 개발자(책임급, iOS 담당 리드), Android 개발자(저장소 소유자 이동은)가 주로 대화했다. 안내 엔진 적용은 팀장이 직접 했다. 5월 4일 새 iOS 개발자와 Android 개발자 한 명이 채널에 들어왔고, 기존 iOS 개발자 한 명과 다른 멤버 한 명이 나갔다. 6월에는 또 다른 Android 개발자도 하단 팝업·리소스 작업으로 대화에 참여했다. 같은 해 버전별 변경은 [[air-app-version-notes-2023]], 기능 개편 스크럼은 [[air-feature-upgrade-scrums-2023]]에 있다.

## 01월: 크래시와 CarPlay·Auto 표시 차이

- **iOS 크래시(01-02)**: 길찾기 후 10초 카운트다운 중(8~9초쯤) 앱을 위로 밀어 종료하면 크래시가 높은 확률로 재현됐다. 타이머를 Lottie로 바꾸면서 종료·백그라운드 진입 시 애니메이션이 강제 종료되고, 그때 안내 시작 프로세스가 돌며 창이 사라진 시점에 레이아웃을 조정해 생긴 문제로 분석했다. 토스트 표시 중 레이아웃 에러로 간헐 발생하던 이슈였고, 디버깅에서 재현돼 수정하기로 했다.
- **교통정보 바(01-19)**: iOS에서 교통정보 바 갱신은 지도 경로 갱신과 같은 방식이다. 다만 CarPlay를 주로 쓰면서 폰이 잠김·백그라운드일 때 교통정보 UI가 갱신되지 않는 경우가 있어 개선 가능한지 검토하라는 지시를 받았다.
- **시간 표시(01-20)**: 하단 도착 시간이 이상하게 나왔다. formatter로 바꾸면서 단말의 24시간제 설정이 반영된 탓이라 수정하기로 했다.
- **거리 소수점(01-18)**: Android Auto 경로 선택은 100km 이상에서 소수점을 숨기는 사양인데 표시되는 버그가 있어 고칠 예정이었다. CarPlay는 OS 템플릿 사양에 따라 10km 이상에서 소수점을 숨긴다.

## 02월: 음성광고(온에어) POC

- **우선순위 변경(02-03)**: 광고 소재 파일이 들어와 음성광고, 더보기 메뉴 리뉴얼, 실험실 리뉴얼의 우선순위를 올리고 주행 전체경로·그룹주행 화면 리뉴얼을 내렸다.
- **효과음(02-13~14)**: 음성광고 시작 효과음을 develop에 머지했다. 처음 안내한 상수는 `VoiceDef.SOUND_AD_SOUND`였고, 다음 날 ogg 파일을 바꾸면서 `VoiceDef.AD_START_SOUND`로 바뀌었다.
- **POC 사양 변경(02-22)**: 안전운행 3km 사양을 제거했다. 온에어 ON/OFF 설정 I/F는 이번 POC에서 빼 앱이 호출하지 않게 하고, 다음 패치에서 앱 실행 후 초기 환경설정 동기화 때와 경로 선택 버튼 클릭 때 호출할 예정이었다.
- **발화 조건(02-23)**: Android는 `#all` 태그 발생 후(사용자가 재생하지 않은 상태) 자동 발송 조건이 들어오면 음성광고를 발화하도록 개발돼 있었다(10분 경과 전이라도 발화하는지에 대한 질문의 답).
- **빌드(02-23~24)**: 음성광고가 상용 서버에 적용됐다. 02-23 16시 빌드는 내부 배포만 하고 테스트는 상용 서버에서 했다. 02-24 POC 배포 빌드도 16시에 했고, iOS는 빌드 후 TestFlight 대기 상태였다.
- **볼륨 기준(02-24)**: iOS는 단말 볼륨 기준으로 발화한다. Android도 우선 단말 볼륨 기준으로 진행하라는 지시가 있었다.
- **테스트 모드(03-08)**: Android는 이후 음성광고 테스트를 위해 개발 모드에서 온에어를 무조건 켜는 로직을 넣었다. iOS는 개발 모드 설정 후 앱을 한 번 재시작해야 온에어가 켜진다.
- **무한 요청 버그(03-30, iOS)**: develop 개발 모드에서 온에어 off인데도 로그 주행 시 광고 요청이 10분 단위가 아니라 실시간으로 계속 나갔다. 경로 선택에서 온에어를 켠 뒤 에어 연구소에서 끄고 주행할 때 생기는 문제로 파악했다. `AudioAdManager`의 해시태그 생성 함수 초입에서 온에어 사용 여부로 return하도록 고쳐 새 브랜치 `bugfix/onAirInfiniteFuncCall`에 push했다.

## SKP 인벤토리 광고 (02-16)

새로 추가한 인벤토리 광고가 Android에서 표시되지 않아 SKP에 문의했지만 SKP는 정상이라고 답했다. iOS에서 확인하니 `inavi_coupon_01`, `inavi_cash_03` 같은 인벤토리는 실패하고 `adx_coupon_01`, `adx_cash_03`처럼 adx 인벤토리만 성공했다. 하드코딩하면 두 OS 모두 성공했고, 원인은 서버가 내려주는 인벤토리 문자열에서 `/`가 빠진 것이었다. SKP 광고 흐름은 [[air-skp-ad-scrums-2024]]로 이어진다. ^[inferred]

## 02월: Android 공통 코드·화면 정리

- **kotlin-android-extensions 제거(02-07)**: 다른 Android 개발자가 작업한 제거 브랜치를 develop에 머지했다.
- **NaviBottomSheet(02-07)**: 주·야간 모드(`showRadioBottomSheet`의 `dayMode: Boolean = true` 파라미터)와 라디오 항목 아이콘(`BottomSheetRadio`의 `icon: Int = -1`)을 추가해 develop에 머지했다.
- **연구소 화면 문구(02-10)**: 디자인·기획과 구두로 협의한 문구를 반영했다. 화면 캡처에는 "일부 지역에 한함"이 볼드였지만 Regular 굵기가 맞다.

## 03~04월: 빌드·스토어 운영

- 정해진 요일 없이 수~금 중에 빌드했다(14시 또는 16시). 03-03 주 빌드는 취소하고 다음 주 수요일(03-08)로 미뤘다. 빌드 후 내부 배포만 하고 스토어 등록은 다음 날 하거나, 같은 날 스토어 업로드까지 하기도 했다. 베타 테스트 이슈는 공유 시트로 관리했다.
- **03-09 빌드**: AOS는 전날 발견된 이슈를 고쳐 14시에 빌드하고, iOS는 특이사항이 없어 AOS 빌드 시점에 앱스토어 제출을 준비하기로 했다.
- **안전운행 가변 제한속도(03-14)**: iOS 개발자가 `feature/safe_variable_speed` 브랜치를 push했고 팀장이 그 브랜치에 안내 엔진을 적용했다. 06-09에는 팀장이 가변 제한속도 DB 로딩 예외 처리를 넣은 안내 엔진을 각 OS develop에 push하고, 기본 카메라 테스트를 요청하며 TC에 가변 제한속도 항목을 추가했다.
- **야간 전체경로(04-03)**: 야간 상태에서 전체경로를 보면 지도는 주간인데 맵 버튼은 야간으로 나왔다.
- **크래시(04-05)**: 한 Android 단말에서 `GLSurfaceView` EGL `createContext failed` 크래시가 났다. 같은 날 iOS에는 캐시 적립 후 비정상 종료 로그가 공유됐다.
- **04-05 점검**: 스프레드시트 항목을 iOS·AOS 모두 테스트 완료했다. 중복처럼 보이던 두 항목은 더블 탭 진입과 퀵메뉴 진입으로 나눠 보기로 했다.
- **04-06 스토어 빌드**: 스토어 업로드까지 진행한 빌드다. 주변검색 나침반 이미지가 옛 이미지로 들어간 것, 가로 모드 초기 이미지 팝업 너비를 고쳐 재빌드했다.
- **Auto 핫패치(04-13)**: 자동 볼륨 조절을 끄면 음성이 나오지 않던 문제를 설정 제거(항상 자동 볼륨 조절 동작)로 고쳤고, 턴 직전 레벨 변경 사양에 3D/2D 구분을 넣었다. 폰 사양과 무관한 Auto 전용 변경이다.
- **MXi 인수인계(04-18)**: Android 개발자(이동은)가 MXi 인수인계를 하기로 했다. 기존 포팅 단말 인수인계는 나중에 하고, 신규 포팅부터는 다른 담당자가 맡는다.

## 04월: 카카오 비즈보드와 iOS 타깃 OS 상향 검토

카카오 비즈보드 광고 때문에 iOS 타깃을 13으로 올리려 했다. iOS 11·12 사용자가 업데이트를 못 받게 되므로 생길 문제를 iOS 개발자가 1차로 정리했다(04-13).

- 업데이트 팝업이 계속 뜰 수 있다(admin에서 버전 처리 가능한지 확인 필요).
- 음성광고 서비스 시작 후 문제가 생겨도 대응할 수 없다.
- 앱 삭제 후 재설치가 안 된다(클라우드로는 가능).
- 캐시 정책이 바뀌면 해당 사용자는 따라오지 못한다(예: 에어마일 → 에어캐시).

04-18에 iOS 비즈보드 화면 스크린샷이 공유됐다. 06-20에는 iOS 13 미만 사용자에게 에이전트가 `appver_info`를 빈 값으로 내려 강제·선택 업데이트를 띄우지 않도록 예외 처리돼 있다는 설명이 나왔다. 05-30에는 카카오가 Objective-C SDK 지원을 끝낸다는 공지가 공유됐다.

## 05월: w3w(What3Words) 검색

- **`/w3w/wordSearch` 호출 시점(05-04)**: Android 개발자가 "최근 검색어에서 `///`가 붙은 단어를 누를 때만 호출하는지"를 물었고, 답은 허들로 이어져 채널에는 남지 않았다. ^[ambiguous]
- **개발 서버 키 한도(05-08)**: 개발 서버 w3w 요청이 한도를 넘어 결과가 오지 않았고, 팀장이 상용 키로 바꿔 테스트하도록 승인했다. 키 값은 대화에 없다.
- **지도 (0,0) 이동(05-09)**: w3w 검색 시 지도가 (0,0)으로 가는 보고가 있었다(상용 서버, 버전코드 301323). Android 개발자 단말에서는 재현되지 않았고, 이전 버전에서 같은 문제를 이미 고쳤다고 설명했다. ^[inferred]
- **지도 롱클릭 비정상 종료(05-09)**: 배포된 Android 버전에서 지도 롱클릭 시 앱이 종료된다는 보고가 들어왔다(처리 완료 표시).
- **추천어만 내려올 때(05-11)**: 팀장이 w3w API 호출 플래그 외에 "추천어만 내려오는 경우"도 정상 동작하도록 요청했다. 검색 실패 후 추천어의 0번 항목 좌표·주소가 유효하지 않으면 그 추천어로 `wordSearch`를 다시 호출하고, 성공하면 w3w 화면으로, 실패하면 실패 문구를 띄운다. 추천어만 내려오는 상황이면 추천어 리스트의 해당 레이아웃 두 개를 숨긴다(Android 검토안).
- **거리 표시(05-04)**: 더미 데이터의 x, y 좌표로 계산한 거리는 서버가 주는 Distance 값과 같은 것으로 확인했다(현위치 차이만 있음).
- **키워드 판별(05-11~12)**: 기획이 키워드 기준을 `.`으로 바꾸면서 나온 검토다. `팅크.`, `팅크.부산`처럼 w3w GUI가 뜰 수 있어도 통합검색이 가능한 입력은 통합검색으로 보내고, 최근 목적지에서 `.`이 두 개 미만이면 통합검색으로 처리한다. Android는 `///`뿐 아니라 `단어.단어.단어` 형태도 w3w 검색 플래그로 바꾸고, 최근 장소·내 장소에서 해당 형태면 API 요청과 내 장소 버튼을 숨기는 안을 냈다(1일). iOS는 정규식을 두 번 바꿨다가, 팀장이 w3w 공식 정규식을 검토했는지 묻자 그 정규식을 테스트했고(한국어·영어·아랍어) AOS·iOS 공통으로 쓰기로 했다. 판별 순서는 `///` 키워드를 먼저 보고, 없으면 정규식으로 본다. 최근 장소·내 장소에도 같은 판별을 넣는다. w3w 검색어는 항상 `///`를 붙여 최근 검색어에 저장한다(예: `a.a.a` → `///a.a.a`). 공식 정규식에서는 `///!단어.단어.단어`는 추천어 목록을 주고, `!단어.단어.단어`는 일반 검색으로 간다(두 OS 동일). 두 OS 모두 1일 소요로 잡았다.
- **05-12 빌드**: 16시에 빌드했다. 개발 서버에서는 새로 추가된 w3w 플래그 Y/N에 따라 데이터가 들어오는지 테스트해야 했다. iOS는 특이사항 없이 내부 배포했다. 전날 팀장은 앱은 05-12에 개발 완료·스토어 등록, 에이전트는 다음 월요일 완료 예정이라고 공지했다.
- **특정 단말 화면 전환(05-14~15)**: 다른 채널에서 상위 관리자가 Galaxy A5 단말에서 새 w3w 검색결과(+지도) 화면으로 전환되지 않아 길안내가 안 된다고 알렸고, 오전에 DP 엔진 확인 내용과 함께 재빌드 등록 여부를 정하겠다고 했다. 팀장은 월요일에 원인 분석을 지시했다. 05-15에는 이번 발행이 끝나면 `setOnFocusChangeListener`가 왜 그렇게 호출됐는지 원인을 파악하라는 지시가 따로 나왔다.
- **기타(05-04, 05-10)**: 회전 화살표 두께 조절 건으로 DP 발행을 늦어도 월요일까지 요청했다. Android는 Android App Bundle 빌드 방식을 검토했다.

## 05월: 기타 이슈

- **iOS 추천어 "정보없음"(05-15)**: 개발 테스트 후 커밋 때 else 문이 실수로 지워져 생겼다. 마지막 테스트를 빠뜨린 탓이었다.
- **오퍼월 GUI(05-15)**: 에어캐시 화면은 오퍼월 제공 여부에 따라 GUI가 바뀌는데, 피그마에는 제공할 때 화면만 있어 가이드를 요청했다.
- **스탬프 API(05-17)**: 전날 요청한 적립 스탬프 조회 API에 `currentMonth` 파라미터가 추가됐다.
- **푸시 테스트(05-17~18)**: FCM 테스트용 curl 명령이 공유됐다. FCM 서버 키와 기기 토큰이 원본에 있음(미수록). curl 본문의 `notification` 필드는 iOS용이며, 있으면 Android가 푸시 데이터를 구성하지 못한다. 서버는 OS별 필수 파라미터를 다르게 보낸다. 팀장은 서버 개발자에게 실제 발송에 `notification` 필드가 있으면 빼 달라고 확인을 요청했다. 상세는 [[air-push-notification]].
- **VOC(05-23)**: 에어캐시 화면에서 적립했는데 메인에 적립 가능 캐시가 남아 있다는 iOS VOC는 이미 등록된 메인 화면 갱신 이슈로 수정돼 있었고, Android는 이상이 없었다.
- **캐시 적립 사용성 개선 TC(05-24)**: 새 iOS 개발자가 Android 개발자와 함께 iOS 1차 확인을 마쳤다. 재현 방법을 모르는 일부 항목은 비워 두었다.
- **iOS 업무 재배정(05-26)**: 처음 새 iOS 개발자에게 줬던 카카오 관련 작업은 기존 iOS 개발자가 다시 맡고, 새 iOS 개발자에게는 "적립 스탬프 고도화(랜덤 룰렛 + 에어연구소)"와 "메인 하단 팝업(공지/이벤트)"을 맡겼다. 개발 시작일은 5월 30일이고, 디자인 일정상 6월 1일부터 스탬프 개발을 할 수 없어 하단 팝업을 먼저 하도록 WBS를 다시 짰다(working days 오류도 수정).

## 06월: 하단 팝업(공지/이벤트)

- iOS는 모달 방식(`InvBottomPopupViewController`)에서 뷰를 올리는 방식(`InvBottomPopupView`)으로 바꿔 표시 문제를 해결했다(06-15). 페이지 번호는 배너 이미지가 아니라 화면 자체에 표시한다.
- "일주일간 보지 않기 > 신규 공지 표출" 사양에서 마지막 idx만 저장해 비교하는 안(Android 개발자 제안, 06-16)은 기각됐다. idx는 admin 등록 시 정해져 크기 순서를 보장할 수 없고, 기존 배너가 업데이트 형식으로 다시 올라오기도 하기 때문이다.
- 배너는 무한 페이징한다(1→2→3→1, 역방향도 같다). 배너가 하나면 페이지 표시 UI와 무한 페이징을 없앤다. 기획서에 명시되지 않아 채널에 따로 공유된 사양이다(06-16).
- 06-19 중간 보고: 무한 페이징, 다시 보지 않기, 신규 배너 존재 시 호출 등 UI·기능 구현을 마쳤고, 튜토리얼·이전 경로 이어주행 때 초기 팝업 미표출이 시나리오대로 동작함을 확인했다. 배포 전 최종 보고에서 `AIR-1125-ios-stamp-advance`, `AIR-1131-ios-bottom-popup-add` 브랜치를 PR 후 머지했고, 외부 연동으로 진입하면 팝업을 숨기는 코드를 넣었다. 머지 후 develop에서는 팝업 표시 관련 코드를 주석 처리해 두었다. cocoapods 불필요 경고 제거 옵션도 develop에 넣었다(`pod install` 필요).

## 06월: 에어캐시 페이지·스탬프 개편

적립 스탬프가 에어캐시 메인 화면으로 옮겨지면서 에어캐시 정보와 스탬프 정보를 두 번 호출해야 하는 문제가 생겼다(06-02). 기존 API 영향 때문에 시나리오가 확정되면 필요할 때 통합을 요청하기로 했고, iOS는 갱신 요청 시 두 API를 동시에 호출한다. 프로그레스바 이미지는 가로 기준 비율로 키우고 `scaleAspectFill`로 맞췄다. 스탬프 룰렛 이용권 조회가 실패하면 Android처럼 팝업 후 확인을 누르면 화면을 나가도록 iOS도 맞추기로 했다(06-21). 새 iOS 개발자가 06-14~16에 UI 디자인 리소스를 여러 차례 반영했고, 다른 Android 개발자도 AOS 이미지 리소스를 반영한 뒤 Auto 차로 이미지를 확인했다. 릴리즈 흐름은 [[air-cash-stamp-release-2023]]에 있다.

- **광고 노출 측정(06-22)**: 캐시 페이지 광고를 스크롤 하단으로 옮길 때 `enableManualImpressions`가 필요한지 확인했다. 수동 노출수 계산은 Ad Manager 직접 트래픽(직영업·하우스 광고)에만 맞고 AdX 등 백업 광고를 받을 수 있는 광고 단위에는 쓸 수 없다. 지금은 직영·하우스 광고 노출이 없고 AdX로 호출해 설정이 필요 없다고 봤다. 팀장은 AdX로 호출해도 하우스 광고가 내려올 수 있다고 지적했고, 광고 타입을 구분할 수 없어 직영 광고가 붙으면 별도 unit id로 나눠야 한다고 정리했다.
- 06-22 머지 과정에서 스탬프 팝업 닫기 버튼 인자(`bCloseButton`)가 바뀐 부분을 바로잡았다.
- **오퍼월 구매적립(06-26)**: iOS 오퍼월 구매적립 탭에 "광고 정보가 없습니다"가 표시됐다(상용도 동일). 업체가 CPS 캠페인 노출 선정 중이라 임시로 꺼 둔 상태였고, 다시 열린 뒤 정상 노출을 확인했다.

## 06월: w3w 최적 탐색·업데이트·좌표 이슈

- **w3w 경로 탐색에 최적 탐색 API 사용(06-13)**: API로 받은 첫 번째 좌표를 `rpx`, `rpy`로 써서 기존 로직 변경 없이 탐색한다. 최근 장소·경유지도 같은 좌표로 탐색할 수 있다. 처음에는 멀티 입구점 탐색을 검토했지만 최근 장소·경유지 탐색에서 처리할 수 없어 바꿨다. 기존에 탐색된 최근 장소는 최적 탐색되지 않고, 외부 연동은 논이슈로 둔다.
- **강제 업데이트 미동작(06-19)**: 사업부가 AOS 03.05.24, iOS 03.05.02로 강제 업데이트를 등록했는데 팝업이 뜨지 않았다. iOS에서 `appver_info`가 03.05.02로 내려오면 03.05.01은 강제 팝업이 뜨고 03.05.02는 뜨지 않았다. 즉 "특정 버전 미만"을 강제 업데이트하는 방식이라, 03.05.24·03.05.02 이하를 막으려면 AOS 03.05.27·iOS 03.05.04로 등록을 요청해야 한다고 정리했다(중간에 03.05.25·03.05.03 안도 나왔다). 06-20 버전을 낮춘 단말에서 선택 업데이트가 두 OS 모두 정상 표시됐다.
- **FCM SDK(06-21)**: Firebase FCM API·SDK 변경 공지와 관련해 iOS는 9.0.0을 쓰고 있어 영향이 없다고 봤다(문제 대상은 7.0.0 미만).
- **w3w 공유 링크(06-22)**: 공유 링크를 누르면 앱이 열리면서 웹에서 스토어도 같이 열렸다. `w3w://` 스킴 호출은 마지막 "에어에서 시험해 보기" 버튼에 반응이 없어 w3w 쪽 호출 방식 확인이 필요했다. 내부 웹뷰라면 Safari 같은 외부 앱으로 열어야 한다.
- **롱탭 위치 지정 오차(06-23)**: iOS 2D·3D 모두 좌표가 조금 위로 올라갔다. 메인 지도가 노치(상태바) 영역까지 그려져 그 영역 기준으로 잘못 계산하는 것으로 보고 DP 측 검토를 요청했다. iOS 주변검색처럼 타이틀바 아래로 지도를 배치한 화면은 정상이다. Android 개발자는 비교용으로 Android 위치 지정 로직(화면 좌표를 DP 좌표로 바꾼 뒤 x를 1.2로 나눠 주소 조회)을 공유했다.
- **위치 공유 핀(06-23~27)**: 웹이 요청 좌표가 아니라 역지오코딩 결과 좌표에 핀을 찍어 생긴 웹 문제로 확인했다. 길찾기는 요청 좌표로 정상 호출된다. 요청 URL과 좌표 예시가 원본에 있음(미수록).
- **릴리즈 계획(06-22)**: 6/23 빌드(주말 테스트 버전, Android는 내부 테스트까지), 6/26~27 내부 이슈 수정, 6/28 빌드와 스토어 업로드. 6/21 빌드는 AOS·iOS 16시에 했다. 06-23 iOS develop 기준 TC 재테스트, 정규식 변환 수정(앱·CarPlay), CarPlay 지도 모드 버튼 이미지셋 변경을 확인했고, 06-28에는 금요일 빌드를 앞두고 에어캐시 메인 문구, CarPlay 버튼 이미지(n/p 둘 다), 롱탭 이슈를 다시 확인했다.
- **iOS 저장소 정리(06-23)**: 새 iOS 개발자가 `Images.xcassets` 아래 이미지를 `inv`, `airre` 대분류 폴더로 옮기는 PR(`feature/image-move`)을 올렸다(삭제·수정 없음).

## 06월: AI 횡단보도·신호등 준비

- 사업부가 횡단보도 UI 설계서와 인터페이스 정의서를 전달했다(06-27, 인터페이스 정의서 원본에는 서비스 키 등이 있어 위키 원본에서 삭제됨). 새 iOS 개발자가 AI 횡단보도 iOS 일정 초안을 냈는데(06-29), 첫 안에 신호등이 잘못 들어가 마을주민 보호구역 안내, 후면 단속 카메라, 하단 팝업 배너 앱 분기, 메인 에어캐시 레이아웃 개선으로 다시 짰다. 이후 팀장이 만든 CF 개발 문서 티켓 일정도 추가했다. 개발 문서는 일반 개발 가이드를 줄이고 에어 관련 내용 위주로 쓰라는 피드백을 받았다. 같은 항목의 일정이 초안마다 크게 달라 다시 조율하기로 했다.
- **신호등 실차 이슈(06-29~30)**: 06-30 16시 신호등 실차 이슈 공유 회의가 잡혔다. 신호등 4코스 로그 주행에서 직진 정보 없이 좌회전만, 또는 보행자만 오거나 빈 목록이 오는 경우가 있었다. 다음 주 사업부와 대구시 회의에서 데이터도 물을 수 있어, "직진 정보가 빠질 수 있는지", "진행 코드 상황별 샘플과 그때 신호등 표시 방법(예: 좌회전만 올 때 직좌로 볼 수 있는지)"을 정리해 사업부에 전달했다. 상세는 [[air-daegu-crosswalk-signal-2023]].
