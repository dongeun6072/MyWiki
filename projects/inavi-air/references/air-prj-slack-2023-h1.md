# Slack #10_prj-inaviair 대화 (2023 상반기)

아이나비 에어 프로젝트 공개 채널(`#10_prj-inaviair`)의 2023-01-02~06-28 기록이다. 사업팀(에어캐시·마케팅), 앱 개발팀, 서버·검색엔진팀, 디자인팀이 한 채널에서 일정·이슈·요청을 주고받았다. 프로젝트 개요는 [[inavi-air]], 같은 기간 다른 채널은 [[air-channel-slack-2023-h1]]·[[air-nsdk-dev-slack-2023-h1]], 버전 기록은 [[air-app-version-notes-2023]], 스탬프 상세는 [[air-cash-stamp-release-2023]], w3w API는 [[inavi-air-api-w3w]]를 본다.

사람 이름은 역할로 적었고, 서버 주소·전화번호·계정·키·링크는 옮기지 않았다. 스레드 답글은 개별 시각 대신 부모 메시지 날짜 아래에 묶어 적었다(스레드의 마지막 답글 날짜는 별도 표기). 첨부는 파일명과 종류만 기록한다.

## 1. 2023-01

- **01-02 마케팅 대행(REVU) 1회차 캠페인 종료** (마케팅 담당): 22-12-30 종료, 주요 지표(누적·기간·상위 노출·유입 키워드) 보고서(PDF) 공유, 2회차 준비 중(총 10회차 예정). 임원이 "보고서가 무엇을 의미하는지(다른 서비스 대비 조회수, 회차별 기대 변화, 검색어 노출 방안, 블로그에서 앱 다운로드 유입 규모)" 정리가 필요하다고 지적했고, 마케팅 담당은 REVU 제공 주요 지표 위주라 2회차 준비하며 금주 내 후속 리포트를 다시 공유하겠다고 답했다.
- **01-03 입장 알림** 1건.
- **01-04 주소 검색 결과 불일치 문의** (앱 서버 담당): 스텝형 주소검색(충청북도→충주시→신니면(지번)→용원리→314-9)과 통합검색(용원리 314-9) 결과가 다름. 검색엔진 담당 답변: 스텝형 지번 검색 API는 행정계 좌표(용원리 대표 좌표)와 지번 좌표 두 개를 모두 리턴하는데 클라이언트가 행정계 좌표를 표시 좌표로 쓰는 것으로 보이며, 기능상 지번 좌표 사용이 맞다. 구주소 검색 API 사양상 `jibun`을 입력하지 않으면 단순 행정계 검색으로 처리되어 결과에 지번 좌표 필드(`jposx`, `jposy`)가 없고, 앱 시나리오(스텝형)는 항상 지번을 입력하므로 항상 유효한 값을 리턴한다. 앱 수석이 "지번좌표가 항상 유효한지, 클라이언트 예외처리가 필요한지" 확인을 요청했다.
- **01-05 설 프로모션 논의 시작** (에어캐시 사업 담당, 스레드 26건, ~01-17): 설 연휴 매일 특정 거리(예: 일 10km) 이상 연속주행 시 캐시 일괄 추가 지급, 기존 프로모션(추석 무제한 적립, 11월 X2 적립)과의 혼합 가능 여부를 문의. 01-06 한시상품(예: "2023캐시 구매상품")에 인당 1회 구매 제한 가능 여부를 추가 문의. 01-10 개발팀 조율: 앱 업데이트가 이날 나가 핫패치 외에는 설 연휴까지 앱 반영이 어려워 서버 작업 선에서 준비. 앱 책임자는 "일정 거리 주행", "무제한 적립", "2배 적립" 중 어느 시나리오인지, 신규 사용자 확보 홍보가 병행되지 않으면 기존 사용자 혜택에 그칠 수 있다고 의견. 사업 담당은 12월부터 트래픽이 하락해 우려된다며 "무제한 적립 + 2,023캐시 특별상품(또는 설 연휴 매일 주행 시 추가캐시)" 방향이라고 설명. 앱 책임자는 무제한 적립은 가능하나 상품은 구매 프로세스와 연관되므로 구체안을 요청. 01-10 사업 담당이 "2,023캐시로 구매 가능한 할인상품(예: 아메리카노 4,500원)을 특정 기간만 오픈하고 인당 1회 구매"안을 제시했으나 01-11 구매 제한 조건을 걸기 어렵다고 판단해 초안 작성: "2023년 설 에어캐시 세(3)배 이벤트"(참여대상 에어 로그인 고객, 참여기간 1/21(토)~1/24(화), 당첨자 발표 2/3(금), 주행 거리만큼 무제한 적립(1km=1캐시), 설 연휴 4일간 매일 10km 주행 시 2023캐시 추가 지급, 같은 조건 추첨으로 23분께 5만원 주유상품권(1만원 모바일 쿠폰 5개 분할), 2023캐시는 1/31까지 일괄 지급). 서버 개발자 의견: 10km 주행 + 캐시 적립을 조건에 추가하는 것이 취지에 맞는지, 오퍼월로 주행 없이 적립 가능한 채널이 있어 "주행 후" 문구를 추가하자. 최종안은 "10캐시 적립" 기준. 서버는 이벤트 적용/해제 시점 공유 요청, 설 시작 시 선작업 항목은 "에어캐시 적립 제한 해제". 01-16 앱 책임자가 개발 건도 상용 작업이 필요하고 디자인은 한 가지 안으로 진행하는 방향으로 검토, "세(3)배"가 x3배 적립으로 오해될 수 있다는 의견이 있어 타이틀은 숫자 없이 "세배 이벤트"로, 서브 텍스트에 혜택을 명확히 언급하기로 합의(한(1)배: 1일 무제한 적립, 두(2)배: 매일 주행 시 2023캐시 추가, 세(3)배: 23분께 5만원 주유 상품권). 01-17 앱 책임자가 2023캐시 구매 상품이 제외되었다고 들었다며 확인을 요청. 사유: 품의 기간을 고려해 개발 검토 의견이 정확히 전달되지 않은 미스커뮤니케이션이며, 서버 작업은 설 이후 별도 일정으로 진행(기프티콘 상품 추가 후 에어캐시 할인율 적용, 1회 구매 제한 구조). 사업 담당은 슬랙으로 의사전달이 더 명확했어야 했다고 양해를 구하고, 개발된 캐시 할인상품 구매는 향후 프로모션에 활용하겠다고 함.
- **01-09 약관/공지 웹페이지 변경 요청** (앱 서버 담당→웹 개발, 스레드 14건, ~01-17): 공지사항/이벤트, 제보하기, 이용약관 페이지 변경 필요: 1) 웹페이지 상단 컬러 제거, 2) 'X' 버튼 제거. 웹 개발은 첨부 예시대로 적용하면 되는지, 공지/제보하기 리스트 진입 시에도 동일 적용인지 문의. 앱 개발 담당은 제보하기는 항목 선택에 따라 페이지가 전환되므로 X 버튼을 유지하자고 의견, 앱 수석은 'X' 버튼은 제거하기로 정리. 01-17 개발서버 확인 중 이용약관 상세 페이지에서 뒤로가기 버튼이 보이지 않는 현상 발견(스크린샷), 캐시 삭제·앱 재설치 후에도 동일, 웹 개발이 수정 후 정상 확인, 01-18 상용서버 반영 예정.
- **01-10 경로선택·환경설정 리뉴얼 버전 스토어 출시** (앱 개발 총괄, 스레드 26건, ~02-08): Android 03.05.17(90% 단계 출시, 01-11까지 이상 없으면 업데이트 팝업 요청), iOS 03.04.15. 내용: 경로 선택·환경 설정 화면 개편(에어 추천 경로와 다양한 경로를 한눈에 비교, 설정을 기능별로 정리), "에어 연구소" 메뉴 추가. 스레드 요지: 에어캐시 사업 담당이 업데이트 내용을 모은 공지 페이지 제안 → 공지 제목 "아이나비 에어 사용선 개선 업데이트 안내"로 01-11 공지·안내 배너 오픈. Android 버전이 03.05.18로 변경되어 문구 수정 요청. 01-13 업데이트 팝업 등록 및 전체 푸시(iOS부터 발송, Android 포함 14시 45분까지 발송). 사업 담당이 리뉴얼 후 무료도로/유료도로 비교가 더 타이트해진 듯하다고 문의했고 개발팀은 비교 조건 로직은 변경 없다고 답함. 01-12 사업 담당이 출근길에서 40분 거리에 7분 차이가 나는데 '에어 추천'이 무료도로였다는 점, 추천 경로가 '가장 빠름'과 같아야 하지 않은지 제기. 01-13 탐색 엔진 담당 분석: (1) 현재 Air 경탐 서버는 3초마다 교통정보를 요청하므로 서버 간 최대 3초의 교통정보 갱신 오차가 있을 수 있음, (2) 요청한 경로옵션 3개가 Air 서버 3대에 각각 요청됨, (3) 최소시간/최단거리가 처리된 서버는 경탐 결과 처리 후 1초 뒤 교통정보가 갱신, (4) 추천 경로가 처리된 서버는 탐색 요청 1초 전에 교통정보가 갱신되어 더 나쁜 교통 정보로 주행 시간이 늘어남. 결과적으로 서로 다른 교통정보가 반영되어 시간 오차가 발생. 앱 개발 총괄: 사용자별 요청이 한쪽 서버로 갈 수 있는 방안 추가 검토, 엔진 쪽은 교통정보 동기화 검토 병행 요청. 사업 담당: 사용자 입장에서는 이해가 어려우니 '에어 추천' 경로 생성 과정을 고려한 개선 요청. 02-07 사업 담당이 '무료경로 선호 에어 추천' 진척을 문의했고 02-08 탐색 엔진 팀장이 해당 히스토리가 있으면 전달을 요청(사업 담당이 기존 멘션 스레드를 안내).
