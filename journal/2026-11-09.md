### 서울동행맵 컨소시엄 → [[seoul-donghaengmap-consortium-slack-2026]]

- **LBS테크 R&R 회의(10:26 허들, 13:18 회의록)**: 이동은도 참석했다. PM 회의록 요지:
  - LBS테크는 멀티모달 경로 탐색 백엔드(실내 제외)를 맡고, SDK는 도보 구간 데이터만 준다(UI·음성 없음). 아이나비가 도보·버스·지하철·실내의 안내 UI, 음성, TBT, ETA, 번역을 모두 맡는다. 10-30에 SDK 몫으로 정했던 버스 안내도 메인 앱으로 옮겼다.
  - LBS테크는 멀티모달 서버와 SDK가 줄 수 있는 데이터를 모두 넘기고 쓸지는 아이나비가 정한다. lane(노선 선형)은 멀티모달 응답에 합쳐 한 번에 준다. SDK는 안내 시점에 맞춰 잘라 주지 않고 위치 변화마다 모든 데이터를 넘기며, 데이터 의미와 사용법을 적은 규격서를 함께 준다.
  - 개발 문의: iOS SDK GPS 미갱신과 모의주행·실보행 음성 차이는 2차 전달 때 확인 후 회신, 회전 예고와 노드 근접 안내는 같은 항목으로 본다(기획 확인), 11-06 백엔드 추가 규격 문의는 LBS테크가 메신저로 회신.
  - 후속: LBS테크가 2차 SDK를 데이터 전용 형태로 전달하고 규격서를 준다. 이후 문의는 회의 없이 Slack에서 담당자끼리 한다.
  - LBS테크 API 담당은 API 통합·전체 데이터 구조 변경을 정리해 그날 안에 보내겠다고 했고, 서버 담당이 ODsay `loadLane`처럼 따로 내리지 말고 경로선에 포함해 한 번에 내려 달라고 하자 단일 콜에 모든 데이터를 내리는 방식으로 바꾸겠다고 답했다.
- **실시간 도착 필드 요청(14:33, 14:52)**: 서버 담당이 브로디언에 앱 요청을 전달했다. 실내 안내 중 승강장 대기→열차 탑승→하차역 도착, 정류장 대기→버스 탑승→하차 정류장 도착을 판별하려면 도착 건과 운행 차량을 이을 값이 필요하다.
  - 지하철(`GET /app/transits/stations/{stationId}`): 지금은 방면·행선지·남은 시간만 있고 ODsay에 실시간 도착이 없어 `arrivalFailedYn = true`로 내린다. 열차번호, 상행/하행(내선/외선), 도착 코드(진입·도착·출발), 정보 생성 시각을 요청했다(서울 열린데이터 지하철 실시간 도착정보 항목 참고).
  - 버스(정류장 도착·노선 상세 운행 차량 위치): 차량 식별값(차량 ID·차량번호)과 도착 여부를 요청했다.
  - 이달 말~다음 달 말에 받는다던 데이터가 어디서 오는지와 위 값이 있는지 확인되면 규격에 필드를 추가해 서버 저장소에 올리고 매핑을 맡길 예정이다. 브로디언은 BMS(버스) 일정이 아직 안 잡혔다고 답했다.
- **회원 토큰 테스트(14:54)**: 브로디언이 받은 회원 토큰이 동작하지 않는다며 다른 토큰을 요청했다(토큰 값은 원본에 있음, 미수록).
- **다국어 5종 확정(16:23)**: PM이 아로 이사와 KO·EN·JA·CN(간체)·TW(번체) 5종으로 확정했고 백엔드와 앱에 같이 적용한다.
