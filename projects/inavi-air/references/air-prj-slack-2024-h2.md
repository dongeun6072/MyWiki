# Slack #10_prj-inaviair 대화 (2024 하반기)

아이나비 에어 프로젝트 공개 채널 `#10_prj-inaviair`의 2024-07-01~12-31 기록이다. 프로젝트 개요는 [[inavi-air]], 앱 버전 정리는 [[air-app-version-notes-2024]], 직전 구간은 [[air-prj-slack-2024-h1]]을 본다. 이 채널은 `#01_inavi_air`([[air-channel-slack-2024-h2]])와 별개 채널이다. 사람 이름은 역할로 적었다. 서버 주소·링크·개인정보는 싣지 않았다.

이 구간 최상위 메시지 74건(입장·퇴장 알림, 허들 알림 포함)을 읽었고, 답글이 달린 스레드 53개를 모두 열어 답글 450건을 읽었다. 첨부 파일은 이미지·엑셀·PDF·텍스트로 이름과 종류만 확인했다.

## 7월

### 07-03 안전운전 업데이트 후 길찾기 오류
- 앱 개발 담당이 안전운전 업데이트 후 에어 앱 개발 환경에서 검색 후 길찾기 시 간헐적으로 "서버와 통신이 원활하지 않습니다. 다시 시도해 주십시오.(2006)" 오류가 발생한다고 보고. 서버 담당이 개발서버의 의심 설정을 변경했으니 재테스트 요청 → 정상 작동 확인.

### 07-10 광고 Refresh 적용 지면
- 마케팅 이사: SKP와 Planet AD 관련 지속 커뮤니케이션 중 앱종료, 경로취소 지면에서 Refresh 적용 여부를 문의받고 있다. 메인은 적용하지 않는 것으로 알고 있는데 나머지 지면은 아니라고 인지한다고 함.
- 앱 담당 답변: 앱종료·경로취소는 기존 구글광고와 동일하게 표출 후 재갱신하고 있다. 내부적으로 갱신이 안 되는 부분이 있는지 추가 확인하겠다. 이후 AOS에서 재갱신 관련 오류가 있어 7월 패치에 수정 반영하겠다고 하고, CTA 표출은 GUI 검토 예정(디자인 담당 참조).
- 마케팅 이사: SKP가 지속 요청 중인 '클릭하면 1캐시 바로 적립'을 더 잘 보이게 할 수 있는지(분석 리포트상 SKP는 더 눈에 띄는 CTA 색상 도입이라 함)에 대해 의견 요청. 이전 구글 광고 시 Refresh 설정이 있었는지 문의 → 구글 광고는 갱신하는 사양이었고 SKP 광고로 바뀌며 기존 광고 로드 flow가 변경되면서 발생한 오류.

### 07-17 전체 푸시 발송율 저하
- 마케팅 이사: 에어 전체 고객 대상 푸시 진행 중 발송율이 50%대로 저하(최근 전체 푸시에서는 95% 이상). 서버 담당 답변: 로그 확인 시 FCM 측 서버 오류로 실패율이 발생한 것으로 판단, 이후 지속 여부 확인 필요. 마케팅 이사는 차주 월요일 광고 푸시 발송 예정이라 염려.

### 07-22 신규 버전 (AOS 03.05.40 / iOS 03.05.18)
- 앱 담당이 스토어 검증 완료 공유. 내역: 캐시버튼 최신 버전(V3.0.4.304) 적용(AOS), 기관시스템(홍수통제소, 수자원공사) VVMS 연동, 환경설정 '자주 묻는 질문' 추가, 부드러운 음성 추가, HUD(로드피아) 목적지 거리 표출 사양 추가. 캐시버튼 내부 광고 적립 및 쇼핑 적립 피드에 내용이 표출되지 않고 있어 해당 버전 APK를 아바티 측에 전달, 추가 협의 필요 여부/선오픈 가능 여부 확인 요청.
- 스레드: 마케팅 이사가 공지 오픈 준비 요청(배포 후 공지). 앱 담당: `캐시버튼 - 피드적립`은 서비스 영향도가 없어 선오픈 후 아바티 피드백 받아 확인. 서비스 오픈 진행, 앱 모니터링 후 공지/선택업데이트 별도 요청. VVMS 건 때문에 선택 업데이트 오픈 시점 문의가 있었고 앱 담당 답변: 홍수 경보 관련 VVMS 기능은 이미 오픈. 단 AOS에서 Crash 이슈가 있어 AOS는 핫패치 준비 중, 선택업데이트는 AOS 핫패치 이후 별도 요청(빠르면 명일 완료). iOS는 이미 출시 완료. 마케팅 이사가 iOS 선택업데이트 먼저 진행 요청 → 서비스 담당이 iOS 선택 업데이트 오픈 완료.
- 앱 개발 담당이 중국 HUD 업체 테스트용으로 위 버전의 출발지 고정 버전 공유 요청, 앱 담당이 요청된 apk 공유(08-01에 채널에도 별도 공유). 같은 날 AOS 03.05.41도 스토어 검증 완료 오픈, 선택업데이트는 다음날 진행. 서비스 담당이 03.05.40 대기 상태에서 버전 처리 방법을 문의: 마케팅 이사는 .41 대기/.40 오픈으로 가자고 결정(.40 오픈된 지가 좀 되어서). 이후 선택 업데이트 진행.

### 07-25 스마일콘 서버 이전 서비스 중단
- 서비스 담당(C.P사업팀)이 쿠폰 연동사 서버 이전 및 고도화 작업 안내 공유: 2024-07-25(목) 23:00 ~ 07-26(금) 07:00, 스마일콘 DB 서버 고도화 및 데이터 이관, 전체 브랜드, 발행·교환 등 모든 서비스 불가. 일시 중단 공지 등록 예정.
- 마케팅 이사: 개발적으로 조치할 사항 문의. 앱 담당: 상품 구매가 불가능하면 admin에서 상품 노출을 제한해야 한다(해당 기간 노출되면 사용자 구매 실패 요청이 예상). 마케팅 이사: 전체 상품이라 페이지가 비어있을 듯해 고민, 퇴근시간인 6시부터 미노출로 거는 것도 부담, 차후 노출/미노출 외 판매일시중단 기능을 넣는 것은 어떨지 제안. 앱 담당: 공지만 되면 문제가 없을 듯하나 사용자 입장에서 상품이 노출되는데 구매가 안 되는 게 더 오류로 판단될 것. 작업 시간대가 비활동 시간대이므로 7시 이전까지 완료된다면 노출되어도 문제는 크지 않다. 서비스 담당: admin에서 미노출 예약/종료 시작일자를 설정할 수 있어 (1) 해당 시간 동안 예약 설정으로 미노출 (2) 비활동 시간대이므로 미노출 설정 안 함 중 택일 검토 요청. 마케팅 이사: 사용량이 적은 시간대에 1개 상품으로 잠시 테스트해 보고 가능하면 공지하고 1번으로 진행 또는 신규 상품 하나를 올려 공지하는 방식도 가능. 서비스 담당 결정: 쇼핑하기(모바일 쿠폰) 서비스 중단 기간(7/25 23:00~7/26 7:00) 동안 현재 노출 중인 쿠폰에 대해 미노출 예약 설정 진행, 상품란에 공지 등록.

### 07-26 메인 광고 Refresh 요청 (광고사업)
- 마케팅 이사 → 앱 담당: 금주 SKP와 광고사업 관련 논의 중 수익증대를 위한 메인 화면 광고(Planet AD, 구글) Refresh를 다시 요청받았다. 현재 Refresh를 하지 않는 것으로 아는데 서비스 부하나 캐시적립 관련으로 불가한지, 불가 이슈가 아니라면 차기 패치에 적용하면 어떨지 의견 요청.
- 앱 담당 답변: 검토해 보니 광고 Refresh 시 신규 광고가 없는 케이스가 많아 광고가 갱신되지 않으면 Refresh 의미가 없다. 서비스 부하나 캐시적립은 문제없다. 마케팅 이사: 해당 부분(Refresh 시 신규 광고)은 SKP에 체크해 전달하겠다, 테스트할 수 있도록 포함. 사업 임원: 현재 fillrate가 98% 수준이라 refresh해도 될 듯. 앱 담당: Refresh 시 신규 광고가 내려오지 않는 부분만 밝혀지면 문제 없어 보이며 앱 쪽에서도 추가 검토. 임원: 광고 mediation까지 포함해 정리된 내용으로 차주 즈음 논의하면 될 듯.
- 이후 마케팅 이사가 SKP가 보낸 AD 개선 방안(8P 이후 내용 검토 요청) 공유: 검토할 방안은 (1) 메인(Planet AD, 구글 지면) Refresh 적용 (2) 검색에 광고 인벤토리 추가 (3) 워터폴 방식의 SDK Mediation 적용 → 자사 개발 부분 여부. 광고 배너 위치는 첫화면 노출, Adfit 제외. 사업부문 주간회의 중 임원이 회의 끝나면 1, 3번에 대해 잠시 미팅 요청(10시 15~20분). 미팅 이후 마케팅 이사가 3번에 대해 SKP 의견을 메일로 공유.
- 앱 담당 정리(진행경과): 1번 항목은 8월 패치에 적용 예정이고 3번(광고 Mediation)은 검토 중이며 특별한 문제가 없으면 차기 패치에 적용. Mediation 적용을 위해서는 광고 실패 케이스에 다른 SDK를 로딩해야 하는 조건이 들어가는데, 이번 패치에 "메인 광고 refresh 사양"이 적용된 이후에는 현재 구성된 flow상 광고가 1회 이상 로드되면 이후 광고 미표출 이슈는 없을 것으로 보인다. Mediation은 최초 1회 실패하는 케이스에서만 효과가 있으나 그 가능성도 낮아져 일단 보류하고 문제 발생 시 재검토(현재 Flow 첨부).
- (참고: 마케팅 이사는 최종 확인 후 SKP와도 이야기해 보겠다고 함. 스레드 마지막 답글은 2024-09-13.)

### 07-29 개발서버 신호등 API
- 서버 담당(트래픽 연동): 에어 개발 서버에서 신호등 정보를 받아오기 위한 신호등 전체 리스트 조회 API(`/api/trftotal`)를 정상 호출하지 못하고 있어 개발 서버 이상 유무 확인 요청.
- 신호등 서버 담당 답변: 포트를 8080이 아닌 별도 포트로 올려 놓았고 8080으로 변경해 올리겠다고 했으나 서버 담당이 현재 사양인 별도 포트 유지로 정리하겠다고 하고, 해당 포트로 확인 시 데이터가 정상 확인된다고 회신.

### 07-30 서울시 신호등 테스트
- 앱 담당이 서울시 신호등 관련 개발서버 테스트 가능 시간 공유 요청(이동은 등 참조).
- 신호등 서버 담당: 서버는 전날부터 올라가 있는 상태이나 업체로부터 데이터가 계속 들어오지 않고 있다. 임원에게 전달받는 대로 테스트 시간을 공유하겠다. 이후 데이터 유입 확인, 지금부터 테스트 진행하면 됨.
- 이동은: 개발서버에서 서울시 보행자 테스트 결과 데이터는 정상 응답되나 보행자 정보에 대기·보행자 데이터가 존재하지 않아 UI에는 표출되지 않는다고 공유. 앱 담당이 현재 테스트 중인 데이터가 실제 데이터인지 가상 데이터인지 문의 → 사업/기획 임원: 가상 데이터이며 보행자가 있다는 정보로 변경 요청, 이후 변경해서 올려두었다고 해 이동은이 재테스트하여 보행자 데이터 정상 응답 및 UI 표출까지 확인.
- 서버 담당(신호등 연동)이 개발 서버에서 `/trflight` 호출 시 Internal Server Error 발생이라며 원인 확인 요청(요청 body `nodeID`). 신호등 서버 담당: trflight는 대구 신호등 관련 호출 API로 서울시 보행자 신호등은 해당 API 관련 데이터가 없기 때문이며 보행자 관련은 `trflightwalker`만 호출하면 된다.
- 사업/기획 임원이 보행자 데이터 정상 응답에 따른 UI 표출에 대한 동영상 제작을 부탁(교차로 2곳으로 2개 동영상). 앱 담당이 미래초교는 도로형상과 사양 때문에 데이터가 없으면 UI가 표출되지 않아 영상을 찍어도 의미가 없어 UI가 표출되는 신도림중학교만 영상을 찍어 명일 중으로 공유하겠다고 함. 가상데이터 담당자가 코드 이해에 한계가 있어 시나리오에 따른 일부 변경이 어렵다고 사업 임원이 설명. 이후 영상이 공유되어 사업 임원이 감사 표시.

### 07-31 개발 서버 지도 24.08a 반영 확인

### 08-05 privateKey 전달 확장 기능 상용 반영 협의
- 서버 담당 → 경로기술개발팀: 이번주 목요일(8/8) AGENT에서 신규 탐색엔진 규격인 privateKey 전달 확장 기능을 상용 반영하려 하니 일정 문제 확인 요청, 개발 서버 테스트·연동은 같은 스레드로 문의.
- 서버(신호등/연동) 담당: 에어 개발 서버에 privateKey 전달되도록 적용, 재탐색 시 타임아웃이 발생하는데 확인 필요, 데이터 정상 전달 및 특이사항 확인 요청.
- 탐색엔진 담당: 현재 적용된 개발기 포트의 엔진은 교체하지 않았는데 탐색 후 재탐색하면 생기는 현상인지 확인 → 맞음. 탐색 후 재탐색 시 탐색엔진이 죽는 현상을 확인했고 packet 구조 확인을 위해 최초 탐색·재탐색 send packet 요청. 서버 담당이 packet(recommendation, time_priority, real_traffic_freeroad 등 경로탐색 3건, 재탐색은 글자수 제한으로 파일 공유)을 공유. 탐색엔진 담당 결과: user private key를 받지 않는 탐색 엔진으로 탐색/재탐색 문제 없고, user private key를 받는 탐색 엔진으로도 탐색/재탐색 문제 없다. private key 로그 출력 확인. NULL 포함 20자 전송 확인, 탐색 엔진에서 17자 private key 출력 확인(private key 17자리 + NULL 3자리).
- 서버 담당: 개발 서버 적용 시 특이사항 없어 상호 테스트 완료, 명일 오후 상용 서버 반영 예정(최종 확인 요청). 이후 서버 담당이 금일 상용 반영하려는데 탐색 엔진에서 작업해도 무방한지 의견 요청. 탐색엔진 담당: 작일 에어 탐색 개발기에서 private key를 받는 엔진과 받지 않는 엔진 테스트 결과 이상 없었고 테스트 종료 후 다른 테스트를 위해 private key를 받지 않는 엔진으로 교체했으며 현 상용 탐색엔진도 private key 미적용 엔진이라 정상 동작할 것. 서버 담당: 금일 오후 중 작업 공지 후 작업 진행 요청.
- 08-19: 탐색엔진 담당 공지: user private key 전달받는 기능을 추가한 탐색 엔진을 상용 가오픈 서버에 적용(9월 오픈).
