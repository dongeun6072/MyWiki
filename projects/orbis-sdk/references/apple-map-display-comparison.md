# 아이나비 vs 애플지도 Display 비교 분석

아이나비 지도와 애플지도의 표현 차이를 항목별로 비교하고, 각 항목의 적용 가능 여부와 개발 필요 사항을 적은 문서(2025-05-21 수정)다. 원문 표는 열 제목이 "구분 / 구분 / 상태 / (빈 열)"로 되어 있어, 아래에서는 열 의미를 대분류 / 항목 / 비교 내용 / 검토 결과로 읽었다. ^[inferred] 상단에 "서비스 타겟"이라는 제목만 있고 내용은 없다. 타일 스타일 분석은 [[orbis-tile-map-style-analysis]], 목차는 [[orbis-design-and-review-hub]].

"Digital&Display팀", "CX", "A그룹"은 검토 의견을 낸 부서/그룹 표기다(원문 그대로). 원문은 한 칸에 여러 부서 의견을 붙여 써서, 아래에서는 부서별로 줄을 나눴다.

## 도로 표현

| 항목 | 비교(애플 vs 아이나비) | 검토 결과 |
|---|---|---|
| 도로색상 | 애플은 진한 회색·연한 회색·흰색으로 도로를 구분한다. 아이나비는 진한 노랑·연한 노랑·흰색으로 구분한다. | Digital&Display팀: 적용 가능. CX: 가능, 지도 스타일 변경으로 대응 가능(도로 레이어 정리 선행 필요). |
| 도로표출 여부 | 애플은 모든 도로를 표출하며 색상·테두리로 고가도로·하부도로를 표현하고, 해외는 골목길의 일부까지 표출한다. 아이나비는 교통섬과 차도 내 희미한 선을 이용해 비교적 간단히 구분한다. | Digital&Display팀: 적용 가능. |
| 지하차도 구분 | 애플은 분홍색 직사각형과 진한 회색으로 지하차도를 구분한다. 아이나비는 회색 직사각형으로 구분한다. | CX: 가능. 구분된 도로 속성에 스타일 적용 가능. |
| 테두리 표현 | 애플은 도로별 테두리 굵기를 다르게 표현한다. 아이나비는 도로별 테두리 굵기가 일정하다. | Digital&Display팀: 적용 가능. CX: 가능. 현재는 동일 두께의 외곽선을 적용하므로 스타일 구분과 함께 엔진 수정 개발이 필요하다. |
| 회전교차로 형태 표현 | 애플은 회전교차로에 진입·진출하는 도로를 분리하고 원형을 강조한다. 아이나비는 회전교차로와 인접 도로를 합치고 지하차도를 강조한다. | A그룹: 가능, 상세 기술 검토 필요. 회전교차로(일반도로) 레이어와 지하차도 레이어가 있고 그리는 순서가 설정 파일로 관리되는데, 순서를 바꾸면 지하차도 레이어가 일반도로 레이어에 가려지는 문제가 생긴다. 데이터 레이어 순서와 DP 렌더러 로직 수정 개발이 필요하고, 데이터 구조와 엔진 전반 수정이 필요하다(구현 방향성 수립 이후 일정 산정 예정). |
| 실시간 교통정보(CTT) | 애플은 실시간 교통량을 굵은 선으로, 아이나비는 얇은 선으로 표시한다. 애플은 대부분의 국가에서 유고 정보를 포함해 정체가 발생한 구간만 표시한다(노란선/빨간선). | CX: 가능, 개선 방향 검토 후 진행 필요. 표현 방식과 시인성 개선은 추가 논의가 필요하며, 단순히 애플처럼 굵기만 바꾸는 것은 효과가 없을 것으로 판단한다. |

## 배경 표현

| 항목 | 비교(애플 vs 아이나비) | 검토 결과 |
|---|---|---|
| 일반지도 배경 표현 | 애플은 강·산을 높은 채도로 표현하고 일정 줌 이상 확대하면 산이 흰색으로 바뀐다. 아이나비는 전체적으로 낮은 채도이며 확대해도 동일하다. | Digital&Display팀: 적용 가능. CX: 가능, 지도 스타일 변경으로 대응 가능(면형 폴리곤 상세화와 표출 레벨 정리 병행 필요). |
| 일반지도 고도 표현 | 애플은 (2D) 힐쉐이드 표현, (3D) 음영이 진해지는 효과. 아이나비는 (2D) 등고선 표현, (3D 확대 시) 등고선이 옅어지는 효과. | A그룹: 가능, 상세 기술 검토 필요. DP 엔진에서 Hillshade 및 DEM 기반 신규 구현이 필요하고, 데이터 컨버터와 DP 엔진 수정 일정 검토가 필요하다. 중장기 프로젝트로 진행해야 한다. |
| 위성지도 배경 표현 | 애플은 토지별로 선명한 채도와 고해상도 이미지를 제공하며 최대 줌 레벨이 낮다(국내 기준 최대 500m, 해외는 12m). 아이나비는 비교적 어두운 색감이고 최대 줌까지 확대할 수 있다(레벨 14). | A그룹: 가능. 14레벨 항공지도 표출은 검토한 이력이 있으며 데이터 구조 변경이 필요하고, 파일 크기 증가로 저장 공간과 트래픽 비용 이슈가 있다. 진행 시 데이터 구조 변경과 엔진 수정 개발이 필요하다(개발 기간 약 8주+). Digital&Display팀: 현재 타일링 레벨 제약으로 13레벨까지만 적용 중이며, 13레벨 이후 상세 레벨로 확장하려면 컨버터 수정이 필요하다. |
| 위성지도 고도 표현 | 줌 축소 시 애플/아이나비 모두 갈색으로 높은 고도를 표시한다. 줌 확대 시 애플은 갈색, 아이나비는 초록색으로 표시한다. | 색상 변경은 가능하나 일일이 작업해야 하는 수준이라 공수 대비 효과가 미비할 것으로 예상한다. |

## 행정구역

| 항목 | 비교(애플 vs 아이나비) | 검토 결과 |
|---|---|---|
| 행정구역 구분 | 애플은 빨간 선으로 행정구역을 구분한다. 아이나비는 별도 구분이 없다. | Digital&Display팀: 적용 가능. 단, 행정구분 표출이 필요한지부터 정리해야 한다. |

## 건물 표현

| 항목 | 비교(애플 vs 아이나비) | 검토 결과 |
|---|---|---|
| 일반지도 | 애플은 (2D) 테두리 음영 차이 표현, (3D) 건물 벽면 음영 효과로 입체감을 강조한다. 아이나비는 주거 단지를 옅은 붉은색으로 표현하고, (3D) 건물을 투명하게 표현하며 벽면 음영 효과를 준다. | 적용 가능하나 변경이 필요한지부터 정리해야 한다. |
| 위성지도 | (애플, 국내 기준) 최대 줌 레벨 500m, 틸팅 시 건물 3D 표현 없음. (애플, 해외 기준) 최대 줌 레벨 12m, 틸팅 시 건물 3D 표현 있음. 아이나비는 (2D) 주요 건물 모델링, (3D) 주요 건물 3D 표현. | 적용 가능하나 변경이 필요한지부터 정리해야 한다. |
| 랜드마크 | (애플) 일반지도는 각 랜드마크의 shape을 살려 입체감 있게 표현하고, 위성지도는 렌더링으로 실사와 동일하게 표현한다. (아이나비) 일반지도는 랜드마크를 별도로 표현하지 않고, 익스트림 에어 3D는 일부 랜드마크에 텍스처를 입힌다. | CX: 가능, 관련 투자 진행 여부 검토 필요. 3D 모델링 추가·개선이 필요해 구축 규모 기준 리소스 검토가 필요하다. 3D 모델링은 외주 진행 등을 검토할 수 있다(내부는 관련 업무가 중단되어 3D 그래픽스 디자이너를 운영하지 않고, 담당 1인 외에는 대응이 어렵다). A그룹: 가능. 3D 모델링 콘텐츠 추가에 따라 컨버터 개발이 생길 수 있고, 모델링 대상 선정 후 구축 포맷에 따라 컨버터 개발과 테스트가 필요하다(진행 규모에 맞춰 일정 산정 예정). |

## 판정 요약 (원문에서 읽히는 구분)
- 스타일 변경만으로 대응 가능(CX/Digital&Display): 도로색상, 도로표출 여부, 지하차도 구분, 일반지도 배경 표현.
- 엔진·데이터 구조 수정이 필요: 테두리 굵기, 회전교차로 형태, 일반지도 고도 표현(Hillshade/DEM), 위성지도 14레벨(약 8주+).
- 방향 논의 선행: CTT 시인성, 행정구역·건물 표현(변경 필요성부터 정리), 랜드마크(투자·외주 검토).
- 효과 미비로 판단: 위성지도 고도 색상 변경.
