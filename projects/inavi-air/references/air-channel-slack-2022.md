# Slack #01_inavi_air 대화 (2022)

아이나비 에어 x Auto x CarPlay 비공개 채널(2022-07 개설)의 2022년 기록이다. 프로젝트 개요는 [[inavi-air]], 같은 해 개발자 채널은 [[air-nsdk-dev-slack-2022]], 이듬해 버전 기록은 [[air-app-version-notes-2023]]를 본다.

이 기간(2022-07-01~12-28) 채널 메시지는 367건(입장 알림, 허들 시작 알림 포함)을 읽었다. 답글이 달린 스레드 220개를 모두 열어 읽었고 미열람은 0개다. 주제별 정리(1~10절)에 구간별 상세(11절)를 더했다. 배포 알림 봇 스레드의 답글도 포함했다.

## 1. 에어캐시 서비스 오픈 (7월)

- **일정**: 에어캐시 서비스 7/20(수) 오후 2~3시 오픈(약관은 최소 7일 고지 필요해서 7/5에 오픈일을 7/20로 조정), 핫패치 8/3, 오디오 광고 8/31로 계획했다. 7/12에는 개발서버 완료, 7/13 상용서버 적용, 7/13~15 내부 테스트, 7/15 또는 18 잔여이슈 수정 버전 배포 순으로 준비했다.
- **서비스 개념**: 주행 1km당 1캐시, 하루 최대 50캐시(공지 기준), 주행 후 캐시 아이콘을 눌러 적립, 쇼핑하기에서 모바일 쿠폰으로 교환. 기존 에어마일은 에어캐시로 전환(전환 이벤트는 8/21 종료). 스토어 앱 이름은 "아이나비 에어 - 돈 버는 내비게이션"으로 변경했다.
- **쇼핑하기 상품(7/1 결정)**: 편의점 상품권·커피·아이스크림·주유권 등 1,500~10,000원대 6종, 외부 쿠폰 연동사(즐거운)와 계약 진행. 11월 중 SK모바일 주유권이 판매 중지되어 제거를 검토했고, 현대오일뱅크 상품 추가 이미지를 요청했다.
- **정책**: 신규 약관에 에어캐시·상품권 취소/환불 불가와 재발송 조항 추가, 쿠폰함에서 교환·기프티콘 발송 이력 확인과 재전송(1~2회로 제한) 필요. 적립 후 2년이 지난 캐시는 자동 소멸(최초 적립분부터 사용) 문구를 적립내역 팝업에 반영했다.
- **서버 사양 합의**: 서비스 메인카드/캐시정보 조회 I/F에 최대적립캐시 필드 추가, 신규 응답 코드(캐시 부족, 마일 오류, 정합성 체크 실패), 로그인 시마다 주행이력·캐시 마이그레이션(미로그인 상태에서 "로그인 후 캐시 적립" 표시 혼란 방지), 회원 탈퇴 시 해당 단말과 연결된 모든 계정 정보까지 삭제되므로 안내 문구를 보강하자는 제안.
- **쿠폰 구매 테스트 이슈**: 쿠폰 구매/재전송 MMS 문구가 다름, 연동사 사양 변경으로 상용서버에는 구매가 성공 처리만 되고 실제 구매는 안 됨, iOS에서 MDN을 암호화하지 않고 전송하던 점, 쿠폰상세 필드명 불일치(imageUrl, tr_id) 등을 서버·앱이 맞췄다. 룰렛은 1000 마일 미만이면 1회만 돌아야 하는데 보너스 룰렛이 2회 가능하게 구현되어 있어 차기 패치에서 수정하기로 했다.
- **베타 테스터 의견 후 정리**: 7/18 베타 의견을 취합해 "서비스 항목(7/20)", "핫패치 항목", "오디오 광고 패치 항목"으로 나눴다. 핫패치에는 에어캐시 전체 화면 스크롤, 레이아웃 개선, 주행이력 연결 버튼, 적립완료 애니메이션(lottie)이 들어간다.
- **오픈 당일(7/19~20)**: 약관·업데이트 공지·일반공지·배너 준비, 상용 룰렛 난수 생성 블록 개선 후 재반영, iOS 스토어 이미지 갱신은 일정 협의, 서버는 AIR3 Agent 작업(매 로그인 시 이력·캐시 마이그레이션, 탈퇴 시 캐시 삭제)을 진행했다. 항공지도 노출 사양이 "마일리지 100 이상"이었으나 마일리지 개념이 사라져 사양 재정의가 필요했다.

## 2. 핫패치와 초기 안정화 (7~8월)

- 7/21 확인: 서비스 직후 주행 종료 후 주행거리·캐시 갱신 시점(최대 5분으로 알려졌으나 스레드에서 확인), 5km 주행에 4캐시만 적립되는 문의는 구간별 정수 적립 때문으로 보인다. ^[inferred]
- **주행이력 생성 조건(서버 확인)**: 주행완료 이벤트(userEvent)는 수초 내 생성, 안전운행은 최대 10분, GPS 미수신 시 15분. 경로취소·목적지접근안내·도착안내 이벤트는 즉시 생성 조건이며 앱 재실행 시에도 즉시 생성된다. 안내시작/경로취소는 앞뒤에 짧은 이력이 추가로 생기는 문제로 조건에서 삭제된 것으로 설명됐다. 주행완료 갱신 사례 2건(16분, 40분) 중 40분 건은 이벤트가 호출되지 않아 10분 후 생성된 경우였다.
- **거리 반올림 이슈**: 서버 4,993m 응답이 메인/캐시 화면에서 5.0km로 표출(주행이력 화면은 버림), 59,951m가 60km로 표출 등. 8/5 수정에서 거리계산 로직의 반올림을 제거했다(9/7에 iOS 03.04.09에서 재확인 요청 있음).
- **03.05.10 Android 크래시**: TextView 배경에 color 리소스를 사용해 Android 9 이하에서만 63명 266회 크래시. Drawable 리소스로 교체해 03.05.11로 배포했다.
- 에어캐시 진입 후 튕김(구글 리뷰) 확인, 에어캐시 푸시 발송 시 크래시 증가 가능성 사전 안내(8/5).
- iOS에서 간헐적으로 앱 실행 불가·'1003' 에러, iOS 경로탐색 null crash 로그 요청, iOS 16 사용자 크래시 모니터링.
- 오퍼월: 디바이더 디자인 합의, iOS에서 설치형 광고 노출 확인, Android 광고 영역 크기 조절 필요, 광고 SDK(딜로)는 8/3 Android에서 no_fill만 내려오는 문제가 있었고, 8/24 당분간 적용이 어려워져 **차기 업데이트에서 온에어(음성광고) 기능을 제외**하기로 했다. 대안(자체 구축 + 제휴)은 별도 공유 예정이었다.
- 앱 안정화 후 스크럼에 스토어 사용자 리뷰 세션 5분 할당(8/10).

## 3. 푸시 규격과 에어캐시 푸시 (8~12월)

- 9/8 푸시 규격 정리: **B형**은 브라우저 URL 연결, **D형**은 내부 WebView URL 연결(B형과 동일하게 URL 전송, URL이 빈 문자열이면 이벤트/공지로 이동), **E형**은 에어캐시 표출 푸시로 `subtype`으로 화면을 구분하며 정의되지 않은 subtype은 알림은 뜨되 확인 클릭 시 동작하지 않게 한다. 내부 WebView D형 URL에는 회사 도메인 문자열 검증이 있어 특정 문자열이 모두 들어가야 동작한다.
- 환경설정 "푸시 알림/정보 및 광고 수신" 값을 서비스게이트 응답(push_status, cash_push_status)에서 내려주고 앱 환경설정에 반영하는지 확인(9/15에 값 불일치 증상 확인 요청).
- **에어캐시 미적립 안내 푸시**: 주행 종료 1시간 후 미적립 캐시 있으면 발송, 1시간 내 다수 주행이면 마지막만, 23시 이후는 미발송, 23시 마지막 푸시는 1시간 경과 여부와 무관하게 발송. 22~23시 주행은 안내가 안 가는 문제를 개선 검토(9/22).
- 10월 서버 부하 대비로 21:00 일괄 대신 21:00~21:20 5분 간격 분산 발송을 제안했고, 이후 **일 1회(21시)** 로 확정됐다. 11/2 모니터링에서 적립 사용자가 약 10% 감소해 푸시 피로도는 줄었으나 도달·반응률 감소로 해석했고, 에어캐시 2배 이벤트에 맞춰 21시 푸시 문구를 "에어캐시 2배 적립, 적립을 놓치지 마세요" 취지로 바꿨다.
- 주행 완료 후 푸시 1회로 변경(10/25 상용 반영 목표), 에어캐시 활성화 푸시(10/31)는 미로그인 사용자 및 한 번도 적립하지 않은 사용자를 대상으로 하고, 로그인 시/최초 적립 시 1,000캐시 추가 적립 기획(적립 내역 문구는 "이벤트 참여"로 표시 여부 문의).

## 4. 신호등 안내 (9~10월)

- 9/21 기획 초안, 9/27 "디지털 신호정보 안내" 기획서 v1.0 배포. 대구시 신호등 정보 연동이 대상이다.
- 안내엔진 I/F(10/5): SetLightSignalDB(서버에서 받은 DB 세팅), ReadyLightSignalDB(안내 준비), CheckLightSignalExistDB(로컬 DB 존재 확인), GetLightSignalInfo(안내 정보). SignalInfo에 distance, lon, lat 필드 추가(10/13).
- 서버 I/F: 대구 신호등 전체 리스트 버전 응답 추가, 신호등 상태 조회는 교통엔진 규격 수정 후 반영. 전체 조회 I/F의 경도/위도를 정수형으로 바꾸기로 했으나 규격서는 double로 남아 있어 확인 요청(10/11). 일정: 신호등 정보 상용서버 반영 10/25.
- 앱 이슈: 신호 순서가 녹색 -> 황색(4~5초) -> 적색인데 황색 표출 사양이 없었다. 신호등 상태 조회가 상용에서 접속 지연(999)로 내려오고(10/20), operationInfo에 "정상"이 오는 점 확인, 일부 노드는 info_list가 빈 배열로 내려와 확인 요청(10/27). 모의주행에서도 신호등이 표출되도록 임시 발행(차후 제거 예정, 모의주행 후 앱 재시작 필요). 도로교통공사 담당자가 대구에서 테스트 시 신호등이 안 나온다는 보고가 있어 시간·위치 정보를 받기로 했다.

## 5. 음성광고(온에어)와 오퍼월 (7~11월)

- 7/22 컨셉: 운전 중 음성광고는 거부감이 커서 **옵트인** 방식으로, 온에어를 켜면 에어캐시를 더 적립한다는 개념. 중요도 높은 카메라 안내만 허용하는 옵션, 이후 위치 공개 등 소셜 요소 고려.
- 8/23 오디오 광고 1차 기획 리뷰, 10/27 리뷰 후 v0.5 기획서 배포. 11/4 서버 규격: 온에어 ON/OFF 설정, 음성 파일 조회, 수신 시작/완료 I/F 신규, 서비스 메인 응답에 `onAirStatus`, `onAirDailyLimitList` 추가(11/7부터 개발).
- 11/10 테스트 버전 사양: 5~15초 광고 음성 랜덤 재생, 서버 연동 없음, 모의주행에서도 발성(서비스에서는 제거 예정), 안내음성과 광고음성 겹침 개선 필요. iOS TestFlight 음성 테스트 버전은 03.04.12(333)~03.04.13(335)에서 이미 배포했고 03.04.14(338)이 음성광고 테스트 버전이다.
- 11/15 POC 보완 계획: 광고음성을 안내와 동일 개념으로 처리(안내볼륨 음소거 및 볼륨 포커싱 연동), 음소거 상태에서는 캐시 적립 안 함(OnAir 자동 Off 및 가이드 필요), 광고음성 앞에 효과음 추가, OnAir 버튼 시인성 개선, 안내엔진에서 회전·카메라 거리를 계산해 광고 타이밍 최적화. 광고 mp3를 ogg로 갈지 결정이 필요하다고 언급.
- 9월 오퍼월 광고(Native, Banner 조합) 디자인 확인, 8/19 오퍼월 미제공 시 에어캐시 화면 문구 가이드 요청, 11/14 오퍼월 어뷰징 보완 검토 진행 확인.

## 6. 경로선택·환경설정 리뉴얼과 차로정보 개선 (8~12월)

- **차로정보**: 8/24 검토 시안을 지도 스타일별로 적용 테스트. A/B안 중 주간 지도에서 B안(검정 계열)은 추천차로 시인성이 낮아 **A안(블루 톤다운)** 으로 진행하기로 했다. 추천차로 배경 톤다운, 버스전용차로 색 어둡게 여부 검토. 개선 시 마켓 이미지의 차로정보 아이콘도 함께 수정. 카플레이/오토 리소스는 9/28~11/8에 포켓차로 포함 단계적 전달했다. 11월 카플레이 차로정보 시인성 개선 리소스도 전달.

## 8-1. 추가로 읽은 스레드의 내용

- **상용서버 적용 직후(7/7)**: 에어캐시 서비스는 서버에 등록된 사용자만 이용 가능했고(테스트 번호를 스레드에서 등록, 값 미수록), 상품 구매는 연동사 변경으로 상용서버에 구현되지 않아 조건 없이 성공 처리만 됐다. 룰렛 이벤트 기간은 7/21~8/22로 변경했고, 에어마일 중지·에어캐시 오픈 설정이 OFF이면 주행을 완료해도 적립되지 않는다는 제약이 공유됐다.
- **오퍼월 상용 전환**: 오퍼월 적립 URL을 상용서버로 바꾼 뒤, 상용 오퍼월이 form-urlencoded 컨텐츠 타입을 지원하지 않아 902 오류가 나는 문제를 차기 서버 패치에서 수정하기로 했다. iOS에서 오퍼월 웹페이지의 확인 버튼 후 에어 서버로 요청이 들어오지 않거나, 구독 참여형이 구독해도 미구독으로 처리되는 현상은 원인을 특정하지 못했고 OS 정보·광고 ID·시각 등 단말 정보가 필요하다고 정리했다.
- **상품 정산 확인**: 연동사 정산 문의로 실제 상품 구매 이력을 확인했고, 비타500 건은 바코드 번호가 길어 엑셀에서 마지막 한 자리가 잘린 것으로 확인되어 재공유했다.

- **10/18 일정 점검**: 신호등 규격 상용 반영 10/25, 에어캐시 활성화 푸시는 응용 검토(10/20), 트럭향 규격(NaviSDK) 10/25 개발 완료 목표. 높이제한 구역 안내 옵션은 AOS/iOS 모두 기본 Off로 확인했다. 활성화 푸시는 11월 서비스로 본다.
- **출시 후 모니터링(11/2 스레드)**: Auto 길안내 중 백그라운드 이동 후 알림 클릭 시 비정상 종료(OS 12/13 단말, 19명 34건)는 Pending Intent 플래그 변경이 원인이라 수정했다. iOS 16.1 이상 사운드 이슈(175건, 87명)는 openal 설정 부분에서 발생하며 신규 음성 매니저에서는 해소될 것으로 봤다. 출시 단계적 배포 비율을 90%에서 30%로 조정했다.
