# Slack #01_inavi_air 대화 (2025 하반기)

에어(Android Auto, Apple CarPlay 포함) 앱 개발·배포 비공개 채널의 2025년 7월~12월 기록이다. 이 기간 채널 메시지는 86건이고, 답글이 달린 스레드 43개를 모두 열어 내용을 반영했다. 프로젝트 개요는 [[inavi-air]], 같은 해 운영 이야기는 [[air-operations-2025]], 버전별 변경은 [[air-app-version-notes-2025]], 개발자 채널은 [[air-nsdk-dev-slack-2025]]를 본다. 대화 전사가 아니라 주제별로 묶었고 사람은 역할로 적었다. 서버 주소, 키, 링크는 원본에 있으나 미수록이다.

## 한눈에 보기

- Android 15 대응(EdgeToEdge, 16KB 페이지)이 7~9월 Android 비정상 종료와 UI 어긋남의 원인이 되어 핫패치가 이어졌다.
- Android Auto 업데이트 이후 차로 정보가 잘리는 문제를 비트맵 리사이즈와 밀도 반영으로 개선했다.
- 에어봇 API 키 노출(9월) 후 서버 발급 구조로 바꿨고, 응답 생성 실패가 이어져 11월 28일 서비스를 종료했다.
- 통합로그인을 AES256으로 전환(12월)하면서 개발서버에서만 동작하는 기간이 있었고, 12월 18일 이후 상용에 반영했다.
- 위수지역 회피 탐색(10~11월), SKB CDN 이관(9월 30일), Orda 팝업 중단(7월 29일) 등 서버 쪽 연동이 병행됐다.

## 앱 안정성·OS 대응

### Android 15 대응과 비정상 종료
- 8월 4일 테스트 배포(03.05.55)에서 Android 15 대응을 확인했다. 변경점은 Activity를 AppCompatActivity 기반으로, 테마를 NoTitleBar에서 AppCompat으로 바꾸고 EdgeToEdge를 활성화한 것이다. 함께 Maps SDK 0.20.1, DP 엔진 1.1.0, 포인트 홈 1.3.2.103, 메인 엔진 16KB 대응이 들어갔다.
- 가로 모드 주행 화면에서 좌측 펀치홀이 있을 때만 우측 패딩을 주고, 우측 펀치홀 가로 모드에는 패딩을 따로 주지 않았다. 겹침이 거의 없고 불편이 없다고 판단한 의도된 동작이다.
- 16KB 메모리 이슈는 사전 출시 보고서 오류이고 구글 정책상 11월까지 유예되어 있어, 먼저 프로덕션 검증을 진행했다(7월 8일). 이후 지도 SDK 0.20.1(16KB 대응), 안내 엔진 16KB 대응 버전이 7~8월에 전달됐다.
- 03.05.53 프로덕션 출시 후 Firebase에서 특정 단말(Galaxy 계열)의 비정상 종료가 발견됐다. 원인은 WindowInsets 리스너가 빠르게 응답하면 TopBarLayer의 View가 아직 초기화되지 않아 레이아웃 파라미터를 못 가져오는 것이었다. 내부 Null 체크로 고쳐 핫패치했고(사용자 84명, 이벤트 204건에서 132명, 290건으로 증가하던 시점), 03.05.54로 정리됐다.
- 03.05.55 출시 후에도 비슷한 종류가 또 나왔다. 초기 시스템 상태바 높이 값을 동적 콜백으로 받아 View 상태를 바꾸는데 UI 스레드 보장이 없어 발생했고(Poco F1, Galaxy A32, Android 15 단말), runOnUiThread로 수정해 03.05.56으로 패치했다. 03.05.55의 비정상 종료는 사용자 392명, 이벤트 603건까지 올라갔다.
- 03.05.55 검증 중 지도검색 위치핀 오류와 내장소 지도보기가 최소 레벨로 축소되는 문제가 보고됐다. 원인은 Android 15 대응으로 추가한 InsetPadding 때문에 레이아웃 크기가 다시 바뀌면서, 최초 1회만 받던 크기 콜백 값이 어긋난 것이다. 리스너 제거 후 영역이 바뀔 때마다 핀 영역을 갱신하고, 바텀시트 콜백의 View로 패딩을 적용하도록 고쳤다.
- iOS 쪽은 내부 지도 엔진(MMC)의 백그라운드 비정상 종료가 확인됐다. 03.05.31에서 백그라운드 진입 시 기존 MMC stop과 위치 측위 stop을 모두 하던 것을 위치 측위 stop만 하도록 바꿨다. 유입률 33%에서 65% 구간 동안 GPS 읽기 계열 크래시가 100건 안팎 남아, 사용자 모르게 10분 뒤 강제 종료되는 시점에 MMC 스레드가 끝나지 않아 생기는 것으로 보고 개선 검토를 이어갔다.
- iOS DP 엔진 크래시 비율 증가(7월 24일)의 원인은 엔진이 쓰는 concurrentqueue 라이브러리의 오래된 버전으로 추정됐고, 최신 버전으로 올려 디스플레이 엔진 1.1.0에 반영했다. 코드 쪽 의심 부분은 추가 확인 항목으로 남았다. ^[inferred]
- 11월 14일 iOS 한 임원 단말에서 인트로 화면에서 100% 앱이 종료되는 문제가 있었다. 서버 로그상 역지오코딩 호출까지 간 뒤 멈췄고, 롱탭 메뉴 진입은 정상이었다. 재현해 보니 OS 함수에서 크래시가 나는 것 외에는 알 수 없었고, 해당 단말의 지도 설정이 항공지도였는데 기본지도로 바꾸자 재발하지 않았다(다시 항공지도로 바꿔도 재현 안 됨). 백업한 지도 파일로 추가 테스트 예정이었다. ^[ambiguous]

### Android Auto / CarPlay
- 8월 14일 Android Auto 업데이트로 컴포넌트가 작아지면서 차로 정보가 좌우로 잘렸다. 차로 정보 View를 비트맵으로 만들어 아이콘으로 쓰는데 비율을 맞춰 적용하지 않은 것이 원인으로 판단됐다. 비트맵 리사이즈로 대응했고(특정 너비 초과 시 배율 축소), 03.05.55 후속 빌드에서는 고정 px 대신 Density를 반영한 픽셀 값으로 비트맵을 생성하도록 개선했다. 5차로 이상은 좌우, 2차로는 상하가 잘리던 증상이 더 잦아졌다는 피드백이 있었다.
- 주행 컴포넌트 미표출(TBT 영역, 교통요약바, 카메라 심볼 등이 가끔 안 그려지고 재연결하면 정상)은 `UpdateMapUIRes` 시 리소스가 null로 갱신되는 로그가 단서였다. 재현 조건은 20km 이상 주행 중 에어 실행 후 Android Auto를 연결하는 것이다. 원인은 앱 초기 실행 직후 주행 모드 플래그가 바로 들어오면 지도가 두 번 생성되고, 리소스가 두 번째 지도에 제대로 추가되지 않는 타이밍 문제로 판단됐다. 주행 모드 상태 수집 시 지연을 넣는 수정을 하기로 했다.
- 수해 지역 VMS 테스트(7월 7일)에서 Auto의 효과음이 안 나오는 문제가 있었다. VMS View가 GuideLayer로 이벤트를 보내는데 Auto는 EventHandler를 쓰지 않아서였고, VoiceManager를 직접 호출하도록 고쳤다.
- 11월 25일 시인성 개선 요청에서는 비활성 차로 이미지가 배경색과 비슷해 시인성이 낮아 리소스를 재전달받았고, 메인 화면의 집/회사 소요시간과 거리 글자 색(시간 파랑, 거리 초록 계열)도 함께 검토했다. 차로 색은 Default로 적용하기로 했다. 이 개선은 Android Auto에만 적용되어 iOS 출시 노트에서 AA/CP 표현을 분리했다.
- 9월 BMW에서 Apple CarPlay HUD가 안 나온다는 문의가 있었다. 별도 차종 구분 로직은 없고 iOS 26의 HUD 관련 API/타입(Maneuver type, Lane angles) 변경도 없었다. Xcode 26 빌드와 이전 빌드의 차이가 있을 수 있어 테스트 플라이트로 배포해 확인하기로 했다. 에어 연동 시와 다른 앱 연동 시 화면이 다르다는 정보도 있었다. ^[ambiguous]
- 9월 토요타 전국 실차 테스트에서 에어를 마지막에 쓴 상태로 폰 프로젝션을 연결하면 CarPlay에서 오디오 포커스를 잡고 있어 다른 소리가 안 나는 현상이 보고됐다(다른 내비에서는 없음). 분석이 필요한 상태로 남았다.
- 8월 7일 iOS에서 CarPlay 실행 시 로그 `CARPLAY_SETTING_A`가 두 번 들어오는 문제가 있었고, `/userEvent`로 로그 API를 두 번 호출하고 있었다.
- 11월 24일 안내 엔진을 전달받아 과속카메라 시간대별 가변 제한속도 이슈에 대응했다. Android 테스트에서 단말 시간을 낮으로 바꾸면 30km, 밤으로 바꾸면 50km로 확인했고 iOS도 정상이었다.
- 디스플레이 엔진은 v1.0.2(7월 8일, AOS), v1.1.0(7월 29일, iOS/AOS), v1.2.0(11월 12일, 아파트 명/동호수 POI 주기 표출, 에어는 on으로 적용)로 전달됐다.
- Maps SDK를 쓰는 국내 커넥티드 앱에서 0.20.1 적용 후 로그인 화면 크래시(navController 미초기화)가 잡혔는데, 앱 네비게이션 쪽 문제로 지도 SDK 오해였다(난독화 때문). ^[inferred]

## 서버·연동

### 통합로그인
- 12월 초 통합회원 로그인 오류 보고(고객 계정에서 로그인 후 에러 이미지). 로그인 후 웹페이지가 커스텀 스킴으로 앱을 호출해 onNewIntent로 로그인 정보를 받는 구조인데, 로그인 후 뒤로가기 시 리다이렉션이 안 되는 것으로 판단됐다.
- 12월 16일 통합로그인 AES256 전환을 논의했다. 기존 AES128에서 키 길이만 바꾸면 되는 줄 알았으나, 문서의 키가 44바이트인데 복호화 시 32바이트로 잘라 쓰는지 확인이 필요했다. 패딩은 AES/CBC/PKCS5로 확인했고 복호화는 앱에서 하여 서버로 전달한다. 코드를 받아 AOS/iOS 모두 정상 동작을 확인했다.
- `snsLogin`, `snsTransLogin`에서 통합회원 서버의 회원 정보 조회를 호출하고, 매일 새벽 스케줄러가 활성 통합회원 목록을 동기화(원본에 서버 주소 있음, 미수록). 토큰 유효성 검증 플로우는 없다고 확인했다. 로그인 페이지 URL은 DB 값(CRM URL 목록 테이블)이라 상용 배포 없이 변경 가능하고, 개발서버에서 먼저 테스트했다.
- 개발서버에서는 정상이지만 상용 서버는 AES256 대응 전까지 로그인이 안 된다는 점을 12월 17일 Android 내부 배포 때 공유했다. 상용서버 반영은 12월 18일 이후 즉시 가능했고, ServiceGate의 `memberLoginUrl` 변경까지 확인되어 정상 동작이 확인됐다.

### 에어봇 종료와 키 노출
- 9월 8일 에어봇 API 키가 외부 노출되어 비활성화됐다. 키가 하드코딩되어 있어 공유된 프로젝트로 노출됐을 수 있다고 분석했고, 키 재발급 후 Agent(ServiceGate)에서 `airbotAuthKey`로 받는 구조로 바꿨다. 개발서버 적용 후 상용 반영(키 값은 DM 전달, 미수록).
- 상용 에어에서 사용 불가 상태라 `gen_ai_flag`로 비활성화했고(앱 AOS/iOS AI 기능 Off 확인), 패치 후 재활성화를 요청했다.
- 11월 24일 응답 생성 실패가 반복되고 관리 인력이 없어 지속 필요성이 낮다고 판단해, 사업부와 협의해 11월 28일 에어봇 서비스를 종료하기로 했다(ChatGPT API 비용은 내년 예산 미반영). `common.properties` 항목을 OFF로 바꾸는 작업이라 재기동 없이 `gen_ai_flag`가 false로 내려가는 것을 확인했다.

### 탐색·위수지역·기타
- 10월 16일 업체 요청으로 탐색엔진에 위수지역 회피 탐색과 고도 정보 반영 탐색이 들어간다고 공유됐다. 고도 정보는 일정이 불명확하고 요청/응답 설계도 필요해 이번에는 위수지역만 하기로 했다. 탐색엔진은 개발서버에만 있고 상용에는 11월 4일 적용, Agent/NaviSDK는 10월 중 마무리를 요청했다. Agent 규격은 `userSetting`의 `mevasion`(위수지역 회피 사용) 항목을 일반 경로 탐색, 경로 재탐색, 요약결과 경로 탐색 API에 추가했고 개발서버에서 `/findMultiRoute` 요청이 정상 전달됐다. 상용 반영 일정을 수립하기로 했다.
- 9월 30일 SKB CDN 이관으로 개발서버 연동 CDN을 전환해 개발서버 이용이 불안정할 수 있다고 공지했다. 11월 5일에는 CDN 전환 후 gzip 설정이 안 되어 있어 적용되면 방면정보와 확대도 동작을 확인하기로 했다.
- 7월 4일 `saveConfig` 쿼리 튜닝을 위해 호출 케이스를 확인했다. 총 13종으로 보였으나 실제로는 iOS 기준 34개 설정과 push 설정을 합친 35개를 올린다. 튜닝 반영은 다음 주 월요일 오후에 진행했다.
- 7월 29일 Orda 연동에서 목적지 도착 시 Orda 팝업을 Specout하기로 했고, ServiceGate의 `orda_flag`를 false로 내려 air-prod 1~4에 적용했다. 7월 30일 15시부터 미표출이고 Android, iOS 모두 확인했다.
- 8월 5일 포인트 파트너 쪽에서 TLS 1.0/1.1 지원 종료를 공지했다. 서버는 JVM 옵션으로 TLSv1.2를 강제하고 있어 영향이 없다.
