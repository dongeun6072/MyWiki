- **판교역 현장 시연 모드(14:45, `89fcc130`, 38개 파일)**: 시나리오 1번은 실외 안내로 판교역 엘리베이터까지 간 뒤 실내 안내로 넘어가고, 2번은 실내에서 출발해 실외로 나와 최종 목적지(실외)에 도착한다. 경로 결과의 도착지가 시연 엘리베이터면 1번으로 보고, 도착지를 바꾸면 일반 길안내로 돌아간다.
  - 시연 장소 검색 목록과 시연 전환 스위치, 통화 중 안내 음성 무음, 경로 탐색 재시도, 1번의 실외 도착(전환 지점)에서는 도착 음성을 내지 않는 처리를 넣었다.
  - 주행 기록을 zip 하나로 묶고 저장 여부를 스위치로 고른다. 개발자 옵션에 실내 전환 상태판과 로그 주행 오버레이를 추가했다.
  - 기존 디버그용 1번(재생)과 주행 재생 화면은 지웠다. 시연 도착 음성·재시도·검색·전환 스위치와 안내 낭독 단위 테스트를 함께 넣었다.
- **「판교역 시나리오 테스트」(14:47, `50c0a2ec`)**: 배포 기록용 빈 커밋.

## 채널 논의

### 서울동행맵 dev → [[seoul-donghaengmap-dev-slack-tech-2026]]

- **판교역 시연 시나리오(14:00)**: 앱 리드가 구성 중인 판교역 시나리오를 앱 팀에 공유했다(Claude 아티팩트, 링크 미수록).
- **시연용 개발폰(16:24)**: PM이 다음 주 시연에 쓸 개발폰(가능하면 성능이 좋은 단말) 대여를 셀장에게 확인 요청했고 셀장이 준비하기로 했다.
- **ODsay 역 기준표(16:06)**: 서버 담당이 앱 리드·이동은에게 파파야 실내 POI 매핑용 ODsay 역 기준표(410행, 첨부 미수록)를 공유했다. 서울시 지하철역 등급체계 현황의 310개 역(노선별 410개)을 ODsay API로 매칭했고, 방향은 상하행 코드 대신 「다음에 서는 역」으로 정리했다. 길찾기 `passStops`로 승차·하차 승강장과 하차 출구를 찾는 방법, 분기역 8곳과 휠체어 경로 엘리베이터 문(좌표만 옴) 처리, 비고 5건, 서울시 밖 역 제외 여부, 파파야 전달 주체를 확인해 달라고 했다. 앱 리드는 출구번호까지는 필요 없고, 방면(다음 역) 정보가 멀티모달 탐색 결과에 내려오는지가 관건이라며 바뀌는 규격 확인을 요청했다.

### 서울동행맵 컨소시엄 → [[seoul-donghaengmap-consortium-slack-2026]]

- **지하철역 국문 역명·실시간 도착 역명 번역(13:43)**: 서버 담당이 브로디언에 역 상세 응답에 국문 역명(ODsay `stationNameKor`)을 항상 넣어 서울시 실시간 도착 API를 앱 언어와 무관하게 호출하자고 제안했다. 서울시 API의 종착역·방면 역명은 한국어로만 와서, 종착역 ID로 ODsay에서 언어별 이름을 받을 수 있는지와 OA-2751로 모자란 부분을 채울 수 있는지 검토를 요청했다. 브로디언은 확인하겠다고 답했다.
- **인근 편의시설 7종 문의(17:49)**: 서버 담당이 화면기획서 v1.2의 인근 편의시설 7종(반경 300m 목록·상세)을 어떤 API로 받는지 LBS테크에 물었다. AR-Navi `/pois/bounds`로는 일반 가게·기관과 출입구 접근성만 나왔다.
- **LBS테크 연동규격서 v120 회신(11-12 04:53)**: 노선 선형 `laneGeometry`가 route API에 합쳐졌다(lane API 제거). 계단 회피는 `avoidStairs`로 정하고, 지하철 승하차역에 `hasElevator`, 환승에 `accessibleTransfer`가 나온다(서울 밖 역은 키 없음 → 「모름」). 도착지는 `destName`(100m)·`destAddr`(30m)로 출입구를 고르고 출발·경유지는 좌표 한 곳으로 찾는다. 도보·환승 구간에 `stationId`·`stationName`·`facility`가 따로 나온다. **인근 편의시설 7종은 LBS테크에 데이터와 목록 API가 없어** 담당·범위 논의가 필요하다며 의견을 요청했다.
