# Slack #01_inavi_air 대화 (2023 하반기)

아이나비 에어 x Auto x CarPlay 비공개 채널의 2023년 7월 1일~12월 말 기록이다. 프로젝트 개요는 [[inavi-air]], 버전별 변경은 [[air-app-version-notes-2023]], 리소스 배포는 [[air-resource-deploy-log-2023-h2]], 개발 채널은 [[air-nsdk-dev-slack-2023-h2]]를 본다.

이 기간 채널 메시지 310건을 모두 읽었다(최신순 페이지 4회). 답글이 달린 스레드는 164개이고 164개를 모두 열어 읽었다(미열람 0). 배포 알림 봇 스레드와 허들 알림 스레드도 열었고, 내용이 없는 허들 알림 스레드 2개는 '확인함'으로 셌다. 약 100건은 앱 배포 봇 알림, 약 30건은 "A huddle started" 같은 시스템 메시지다. 스레드에서 확인된 보강 내용은 9절 뒤의 10절에 모았다. 서버 주소, 연락처, 키, 링크, 사용자 식별번호는 원본에 있으나 미수록이다. 사람 이름은 역할로 적었다.

## 1. AI 횡단보도·신호등 (대구시 연계)

- 7/14 안내 엔진이 후면 번호판 카메라, 주민보호구역, 장애인보호구역 안내를 추가했다. 후면 카메라는 7/19 지도 반영, 보호구역은 9월 MRData 반영이다(개발 서버는 먼저 반영).
- 7/21 AI 신호등 정보가 8월로 밀릴 것으로 보여, 해당 기능만 빼고 7/25 빌드로 7월 서비스를 진행하기로 했다. 공지, 연구소 문구 등 기획·디자인 쪽 수정도 요청했다.
- 7/25 정리: AI 횡단보도는 9월 내 서비스, 대구시 데이터 연동은 8/21부터 가능, 교차로 DB 포맷은 유지(안내 엔진 변경 없음). 신호등과 달리 횡단보도는 교차로 ID만 서버로 보내 교차로 내 모든 횡단보도를 받고, 그중 경로 방향에 있는 것만 안내한다. 같은 날 스토어 출시노트에서 횡단보도 문구를 빼고 연구소는 기존 문구를 쓰기로 했다.
- 9/6 인프라와 데이터 검증이 안 끝나 10월 중순 패치로 요청받았다. 대응: 상용 서버는 횡단보도 데이터를 내려주지 않게 하고 앱을 출시, 대구시는 9월 중순~10월 중순 개발 서버용 APK로 자체 테스트, 10월 중순 서버 값만 바꿔 앱 패치 없이 서비스한다. 앱은 데이터 유무에 따른 Crash를 점검한다.
- 9/26 대구시 테스트 중 "교차로 정보를 찾지 못하는 케이스"와 데이터 의미 파악이 이슈로 인입되어 10/5~10/6 시나리오 테스트(각도, 진행방향 확인)를 하기로 했다. 서비스 일정은 10월 중순 현재 상태로 서버만 적용 오픈, 10월 말 개선 버전이다. 대구시 요청에 따라 서비스 기획이 바뀔 수 있다.
- 10/5 실차 테스트, 10/12 실차 코스(1코스 6회, 2코스 4회 영상 녹화) 진행. 10/18 사업부 요청으로 우회전은 50m에서 서버 체크 후 25m에서 한 번 더 체크해 갱신하기로 했고, 안내 엔진의 신호등/횡단보도 교차로 탐색 로직을 개선했다(같은 교차로 중복 진입 시 마커 표출 확인 요청). ^[inferred]
- 관련 상세는 [[air-daegu-crosswalk-signal-2023]]를 본다.

## 2. 제보하기·에어캐시·SKP 쿠폰

- 8/9 제보하기 개선과 연구소 리뉴얼 기획 초안 리뷰, 8/22 제보하기 1.0 기획서 공유, 10/20 사용자 분석과 제보하기 정식 오픈 추가 기획(제보하기 v1.6).
- Agent API 구성(8/30): 제보하기 등록(앱 전용, 접수중으로 저장), 제보하기 상태 등록(Admin 전용), 제보하기 조회. 8/29 앱용 등록/삭제 규격서 완료. 저장 설정 API(/saveConfig)와 SNS 로그인 API에 `defaultRouteOption`(0~5), `issueReport`(0 off, 1 on) 필드를 추가하기로 했다. 조회 `progress`는 "완료/처리중/접수중" 문구이고 9월에 "중복" 상태가 추가되어 응답을 기반영 상태값으로 바꿨다(9/25 상용 배포, 입력 API의 ID 컬럼 시퀀스 전환).
- 캐시 정책 제안(8/30): 카메라 등록 50캐시(월 제한 없음), 기타 50캐시(월 5회), 기반영 10캐시(월 5회), 확인불가 미지급. 9/6 월별 횟수 제한은 사용자가 제보한 날짜 기준으로 센다. 9/22 장소 정보 제보가 베스트 제보로 처리되어 50캐시가 나가는 문제가 있어 절차 보완을 요청했다.
- 9/25 제보하기 v2.0 오픈 후 인입 추세는 큰 변화가 없고, 1회성 하단 팝업으로는 인지가 부족해 에어 연구소에서 On을 유도하는 시나리오가 필요하다는 의견이 있었다.
- 이벤트 페이지 캐시 적립: 로그인 사용자만 적립 가능해 Admin이 Agent 호출 시 `sns_key`를 같이 보내고, 미로그인은 별도 에러 코드를 돌려주기로 했다(8/29). 20캐시 배너 이벤트 중복 적립 케이스도 확인 요청(9/8).
- 8월 휴가철 프로모션(7/31): 메인 에어캐시 문구를 "OO쿠폰까지\000캐시" 형식으로 내리고 `\` 기준으로 흰색/주황색을 나눈다. 캐시 구간별 툴팁 이미지는 로그인 전, 0~1,599, 1,600~2,999, 3,000~4,499, 4,500~4,999, 5,000~10,000의 6단계다(7/12). 상품명이 길면 iOS에서 잘려 길이 제한 등록을 요청했다.
- SKP 광고 제휴(10/31~11/24): 실물 쿠폰은 연내 어려워 에어캐시 쿠폰 난수를 발급하기로 했다(500캐시 30만 개 논의, 이후 1,000캐시 5만 개와 500캐시 20만 개). 신규 가입자 첫 주행 캐시는 1,000에서 500으로 조정. 난수는 16자리 영문숫자 조합이고, 웹 이벤트 페이지에서 로그인 확인 후 난수를 입력해 캐시를 지급한다. Agent는 모바일 교환권 캐시 적립 API를 개발·검증해 11/27 상용 배포 예정으로 알렸다. 적립 스탬프 정보 API(`/cashStampInfo`)의 응답에 `skpEventInfo`(연동 URL, 기간) 객체를 추가했고 상용 반영 전에는 값을 비워 노출하지 않기로 했다. 교환 API(`/event/cash/voucherExchange`)는 오류 시 모두 999를 주던 것을 상황별 응답으로 바꿀 예정이다. 앱 테스트에서 임의 입력, 16자리 아님, 공백은 각각 실패 안내 문구가 나왔다.
- 11/16 에어캐시 어뷰징 확인(월 3,000캐시 이상 적립자 1회성 점검). 11/21 VOC 일련번호가 -1부터 등록되는 현상과 동일 VOC 재인입 확인 요청.
- 상세는 [[air-cash-stamp-release-2023]], [[air-partner-integrations-2023]]를 본다.

## 3. 폰트·리소스·디자인 개편

- 8/3 에어 폰트를 Pretendard로 바꾸는 테스트 제안(스레드 답글 21). 8/16 iOS 지도 초기화 시 폰트 파일명(확장자 제외)을 넘기도록 DP 엔진 시그니처가 바뀌었다(v0.0.5.8a). 8/28 iOS(377), 8/29 AOS 신규 폰트 버전을 배포했다. 운영 의견: 부분 리뉴얼이 아니라 폰트 시스템과 리소스를 로드맵에 맞춰 일관되게 정비해야 한다(8/16).
- 리소스 용량 개선(9/25): 일부 파일 30~50% 감소. 10/24~11/2 미사용 리소스 삭제 대상 목록을 확인했다. iOS 이미지 명칭 규칙은 `_g`가 `_g_tm`으로 바뀌었다(9/7).
- 이 기간 디자인 쪽이 전달한 리소스: 에어 연구소 리뉴얼과 제보하기(8/22, 8/29), 주변 검색 하단 텍스트(9/13), 내 장소 리뉴얼(10/17, 10/26, 11/3), HUD와 SKP 광고 연동(11/21), Auto 이미지 파일명 규칙(11/17, 메인 화면·주변 검색 xxhdpi).
- 스토어 사용자 리뷰 우선순위 정리(8/3). 8/23 스토어 댓글 정리는 보류하고 역할 정의를 논의하기로 했다. 9/14 스토어 댓글 관련 회의.
- 에어 연구소 경로 탐색 기본 옵션이 도입되었다(9월 패치, `defaultRouteOption`).

## 4. 내 장소·최근장소 리뉴얼

- 기획 리뷰: 9/5 피그마 전환 1차, 10/6 컨셉 수정, 10/11 v1.0 리뷰. 9/20 메인에 내 장소 바로가기를 두려고 하단 CCTV 버튼 사용량을 문의했다.
- 최근장소: 최대 50개를 넘으면 자동 삭제하되 탐색 빈도 상위 1~3위는 제외하고, 이번에 핀 고정된 장소도 삭제 제외로 기획되어 Android 반영 여부를 확인했다(11/1). 핀 값 저장 방식과, 내 장소 이름 변경 시 최근장소 연결 문제 시나리오도 점검 요청했다.
- 10/30 "내 장소 상단 고정"에 대해 최근장소 핀 마이그레이션은 하지 않기로 해, 기존 핀이 사라져 버그로 보일 수 있어 사용자 안내 여부를 문의했다.
- 11/1 운영 피드백: 에어 퀴즈 참여 후 피드백 없음, 신규 디자인 시스템 전체 적용 타임라인 필요, 내 장소 지도 핀 우선순위(AOS), 이름 변경 UI 차이, 최근장소와 즐겨찾기 중복 표출 개선. 11/9 최근장소 방문 날짜가 앱 업데이트 날짜 등으로 표시되는 Android 이슈는 수정이 필요하다고 했다.
- 상세는 [[air-my-places-renewal-2023]]를 본다.

## 5. HUD 연동과 12월 안정화 패치

- 11/14 HUD 매뉴얼과 BLE 연동 flow 공유, HUD 시리얼 인증이 목록 대조인지 규칙 기반인지 확인(스레드 15). 시리얼 암호화는 AES128이며 Connected에서 쓰던 방식이다(11/15, 키는 DM으로 전달, 원본 미수록).
- 11/21 HUD 연동 기획서 v1.0 공유. 11/22 서버에서 HUD 기능 제공 여부를 제어하도록 serviceGate API에 HUD flag 추가를 요청했다. 11/27 HUD는 QA팀이 12/4부터 2주간 검증하고, 결과에 따라 에어 업데이트 일정에 맞춰 베타 레이블을 뗀다.
- 12/1 12월 패치는 안정성 개선으로 진행: 시간이 걸려 미뤘던 항목(예: 통행료 테이블 파일 일원화)과 Auto 로그 저장 기능(임시 테스트 버전) 포함.
- 12/26 엔진(DP, 안내) 이슈 두 건을 Jira에 등록했다: 카플레이 화살표 개선, 길찾기 중 비정상 종료(findLinkAndNode). 1월 중순 HUD 정식 서비스 패치에 맞춰 카플레이 음성, DP 화살표, 안내 엔진 Crash를 묶어 진행하기로 했다.
- 상세는 [[air-hud-integration-2023]]를 본다.

## 6. 카플레이·Auto·DP 엔진

- **경로선 두께와 화살표(11/9~1/9, 스레드 41)**: 카플레이 대시보드는 경로선 두께 2.5를 쓰고, 지도 영역이 기존의 절반이라 경로선이 얇아 보이는데 화살표가 짧고 굵게 보였다. 앱 쪽 분석은 지도 영역 폭을 2배, 1.5배, 1배로 바꿔 보며 두께 변화를 확인한 것이다. 엔진 쪽은 메인에서 두께를 조작하게 하거나, DP가 화면 크기에 맞춰 scale을 갱신하는 두 방식을 제안했고, DP 인터페이스에서 viewport를 지정하는 방식을 적용했다. 이후 카플레이 화면과 대시보드 전환을 여러 번 하면 크기가 반으로 잡히는 현상이 남았고(대시보드 331x448, 카플레이 800x480 최종, 반 크기로 먼저 호출됨), DP에서 지도마다 scale 변수를 따로 갖도록 바꿔(기존은 앱용/카플레이용 정적 변수 2개) 지도가 3개 이상일 때의 문제를 해결하는 쪽으로 정리했다. 그러면 viewport 호출 유무와 관계없이 크기가 유지되는 것을 확인했고 특이사항이 없어 공식 배포를 요청했다. ^[ambiguous]
- 카플레이 시뮬레이터 테스트 환경은 Apple Silicon Mac 또는 T2 보안 칩 탑재 Intel Mac이 필요해, 엔진 개발자 PC로는 불가해 앱 개발자가 환경을 세팅했다.
- 9/12 iOS DP에서 메인 지도에 경로 표출 후 다른 화면에 작은 지도를 만들었다 돌아오면 경로선이 두꺼워지는 현상(카플레이에도 동일). DP 버전 0.0.5.9a에서 DP 크기 변경 시 경로선 두께 문제를 수정하고 허용 값을 0.4~2.5로 넓혔으며, 0.0.5.9b에서 0.4~4.0으로 넓히고 AOS 롤백을 포함했다(9/19~20).
- 11/2 iOS에서 지도 주기(표출 주기) 겹침이 특정 단말에서 지속 발생(스레드 27): 대부분 iOS 17 Pro급, 개발자 시뮬레이터에서도 재현. 원인은 텍스트만 있는 POI 타입에서 비트맵 이미지를 만들 때 `CGContextClearRect`를 호출하지 않은 것으로 보인다. DP v0.0.6.1a(11/20)에서 "텍스트 타입 POI가 다른 POI와 겹쳐 보이는 문제"를 수정했고, 함수 시그니처가 바뀌어(`setCarPos` 계열) 앱 호출부 수정이 필요했다. 삼성중공업 지도 캐시 문제는 AOS/iOS 모두 별도 확인 중이다.
- 12/20 VoE 제보 2건(스레드 13): USB 연결 시 앱이 반복 종료, 뮤직 앱 동시 실행 시 안내 음성 조절 불가·무음. 원인 분석 후 의심 구간(음성 종료 후 세션 초기화의 비동기 처리)을 원복해 테스트 배포했고, 원복 버전에서는 재현되지 않았다. 다만 음성 종료 후 1초 미만 UI 멈춤은 개선이 필요하다. 개발 서버 연동 이력이 있던 테스트 단말은 삭제 후 재설치를 요청했다. ^[inferred]
- 12/8 사당역 검색 후 길찾기 시도 시 비정상 종료가 `FindLinkAndNode` 호출에서 발생, 간헐적으로 고속도로로 체크되는 이슈도 있었다(AOS/iOS 공통). 12/22 iOS에서 카플레이 연결 후 경로 그리는 시점에 비정상 종료가 확인되어 엔진 검토를 요청했다.
- iOS 단축어(12/5): TMAP이 집/회사/최근 목적지를 지원하는 것을 참고해 에어도 집/자주 가는 곳 단축어를 테스트했고 구현에 문제가 없었다. 그 외 기능은 기획에서 먼저 정리가 필요하다.
- Auto 이미지 파일명(11/17)과 카플레이 내 장소 집/자주가는곳 아이콘(11/15) 규칙을 공유했다.

## 7. 서버·API·운영 이슈

- 리스트 탐색 시 탐색 옵션 배열 중간에 빈 문자열이 들어가 탐색 엔진이 옵션 파일 열기 실패(코드 18)를 돌려주는 문제(12/19). 서버는 빈 값을 제외하고 탐색하도록, 앱은 빈 문자열을 요청에서 제외하도록 개선을 요청했다(Android 03.05.33 발생).
- 화물 SDK(물류사) 경로가 좁은 길로 안내되었다는 문의(8/31, 스레드 25): 로그상 3번 탐색이 모두 트럭 옵션이었으나 도로 통과 높이·중량 제한 사용(`rheightlimit`, `rweightlimit`) 값이 false로 요청되어 발생한 것으로 보였다. 서버는 null이면 0으로 초기화하고, SDK 쪽 원인 분석 이슈(NSDK-94)를 만들어 다음 SDK 릴리스에서 true로 정상 요청됨을 확인했다. 10/13 같은 업체에서 트럭 경로가 산 오솔길로 안내되었다는 건도 파라미터 확인을 요청했다.
- 삼성중공업 SDK: 교통정보 데이터가 없어 탐색 요청에서 `headerType` 13, `trafficSetting.trafficUnflag` true로 교통정보 미사용을 지정해야 한다(7/12). SDK 헤더 전달 방식은 `servicePackage` 사용 대 신규 파라미터 정의 중에서 논의했다(7/6, 스레드 16). 10/18 안내 엔진에 경유지를 지나지 않고 주행 시 이탈 처리 로직을 추가했다. MMC(대만향) 엔진 수령 일정은 Android 7/28 발행, iOS 차주 금요일로 협의했고 iOS 빌드 지연이 있었다(8/4).
- 서비스 게이트 API: 아이나비 지도 도입으로 지도 인증키를 서비스 게이트 응답으로 내려받도록 추가 요청(10/24, 키 값은 미수록). 하단 팝업은 Agent가 Admin에 등록된 앱 버전 이상일 때만 배너 목록을 내려주는 방식으로 정리했다(7/12). 푸시는 내부 Web View 연동형 타입(push_type 3, url은 빈 문자열)이 추가되어 지원 앱 버전(AOS 03.05.12, iOS 03.04.10) 이상만 대상으로 한다(9/20).
- 에어 상품 Admin 적용(10/26): Admin에서 관리할 항목은 상품 ID, 브랜드명, 상품명, 상품 종류(개인화 툴팁용), 메인 개인화 이미지 텍스트, 판매가, 할인가(추가), 유효기간, 이미지 URL, 이용안내, 노출 여부. 관리 테이블이 Agent DB에 있어 Admin DB로 옮길지 논의가 필요하다.
- 기타 장애: 9/19 CCTV 서비스 정보 미제공, 10/26 상용에서 경로 주변 주유소 미표출(개발 서버는 정상, 경로 주변 API에 주유소 정보가 내려오지 않음), 11/9 저녁 에어 슬랙 알람 다수 확인 요청. 7/10 AOS에서 "업데이트가 있다고 뜨는데 스토어에 업데이트가 없다"는 사용자 리뷰가 다수 인입되었다. 7/11 개발 서버 접속 불가 후 재기동.
- 신규 OS 대응 프로세스(9/27): Alpha/Beta/RC/Stable 단계를 모니터링해 Beta부터 일정 수립, OS별 1~2대에 베타 프로그램을 설치해 공용 테스트, 릴리스 노트로 deprecated API 확인, 서비스 버전(스토어 앱)과 개발 버전(Xcode/TargetSDK 업데이트) 각각 기능·GUI·Auto/CarPlay 테스트, Critical 이슈는 긴급 패치 준비, Minor는 백로그.
- 9/22 지도 SDK 검토 중 광고 캐시버튼 라이브러리와 지도 SDK 0.9.3이 난독화 후 동일 클래스명(a.a 등)으로 충돌(스레드 20). 해결 방안으로 중복 종속성 exclude 또는 SDK 난독화 시 repackageclasses 옵션이 제시되었다. 제보 지점 지정 지도를 기존 지도에서 지도 SDK로 바꾸는 검토였다. ^[inferred]
- 신규 음성(9/4): 기존 클래식 음성은 유지하고 "발랄한 음성"과 "차분한 음성"을 신규 녹음하기 위해 성우 후보 8명의 샘플을 검토했다([[air-new-voice-preference-2023-09]]).
- 에어 퀴즈 1차 결과(12/8, 약 3주 진행), 사용자 설문 회의(10/24), 반복 업무 개선 회의(10/25: 리소스 자동 적용, Admin 상품 관리).
- 8/17 교통정보 품질 개선을 위해 탐색결과 링크 speed와 실시간 교통정보 speed를 비교했더니 항상 동일해 Agent 매칭 여부를 확인했다(스레드 10).

**제보하기·에어캐시·SKP 세부**
- progress 상태는 접수중, 처리중, 완료, 기반영, 확인불가 5가지가 필요해 규격 필드명을 `progressType`으로 바꿨다(8/31). 캐시 정책은 미로그인 제보는 완료 처리하되 캐시 미지급, 베스트/인기 제보 선정 제외로 확정, 기획서 v1.4.
- 이벤트 캐시 적립은 일정상 pkey만으로 지급하고 차기 앱 패치에서 `sns_key`를 넘기는 방식을 요청했다. 20캐시 배너 이벤트 중복 성공 건은 eventId가 달라 다른 이벤트로 판단해 정상으로 확인했다(9/8). 이벤트 적립 API는 1회 적립, 성공/실패/기지급 응답이 요건이고 개발은 8/23~8/25였다.
- 최초 로그인 보상 변경(1,000에서 500)은 서버 프로퍼티와 미로그인 툴팁 문구를 함께 바꾸기로 했다. 에어캐시 어뷰징 점검 결과 9~11월 특이사항 없음, 평균 속력이 200km/h를 넘으면 서버가 어뷰징으로 보고 적립하지 않는다. 9월 적립 상위자 급증은 추석 무제한 적립 이벤트 영향으로 봤다. ^[inferred]
- SKP 쿠폰은 계정당 1회 사용이며 난수 25만 개(1,000캐시 5만, 500캐시 20만), 유효기간 12/31. SN 암호화 값은 URL 인코딩 차이(`+`, `=`)만 있을 뿐 AOS/iOS가 동일함을 확인했다. HUD S/N 인증 API는 시리얼 존재 여부만 확인하며, 신규 HUD용으로 `hudType` 파라미터를 추가하고 값은 `air`로 정했다.
- serviceGate 응답에 `hud_open_type`(기본 true)이 추가되었다(11/22). 아이나비 지도 인증키는 키 유출 시 교체를 쉽게 하려고 `inaviAuthKey`로 서버에서 내려받게 했고 상용은 11/1 적용 작업과 함께 반영했다.
- 장소 정보 제보 50캐시 문제: 우선 운영해 보고 불필요한 지급이 많으면 10캐시 등으로 조정하기로 했다(9/22). 제보하기 "중복" 상태는 Admin과 공용인 VOC 테이블을 바꾸지 않고 Agent 예외처리로 응답을 기반영으로 바꾸기로 했다.
- 하단 팝업/푸시 아웃링크: Admin 이벤트 타입(A9)을 활용하면 Agent·Admin 패치 없이 아웃링크가 가능하다(9/20). 7/28 하단 팝업 미노출은 Admin 표출 시간을 8/1로 잘못 설정한 것이 원인이었다. 하단 팝업은 Agent가 등록 앱 버전 이상일 때만 배너 목록을 내려주며, 전체 등록 시 AOS 03.05.28, iOS 03.05.06 이상 사양이다.
- 에어캐시 푸시(7/17): 21시 푸시를 없애고 10시로 옮기는 안을 냈으나 도달률 하락 우려로 사업팀이 원복을 요청해 기존 21시/12시 사양으로 되돌렸다. 문구는 스탬프 적용 버전과 룰렛 고도화 버전 두 벌이다.
- 7/18 연구소 기능 ON 사용자 수 추출: 신호등 잔여시간 안내가 약 27.5만 명으로 가장 많고, 메인카드 2배 더보기 약 1.6만, 기본 안내 금지 모드 약 5천 명이다. 9/20 하단 CCTV 버튼 PV/UV는 월 단위로 7월(10일간) 7,790/5,089, 8월 26,224/13,361, 9월(21일간) 16,924/8,406이다(서버 로그가 3개월만 보관됨).

**엔진·DP·카플레이 세부**
- 폰트 변경: Pretendard 6종 16.5MB 대신 Bold/Medium/Regular 3종만 쓰기로 했고(기존 2.3MB), 앱 용량이 10MB 이상 늘었다. DP 엔진은 Android가 init으로 넘긴 Typeface만 쓰고 iOS는 엔진이 폰트 파일을 직접 읽어 인터페이스 추가가 필요했다. Android Auto 남은 거리 숫자는 24/26/30dp를 비교해 26dp로 정했다(8/3).
- 9/12 iOS 경로선 두께: 두께 계산이 전체 화면 크기를 쓰고 싱글턴 값이 갱신돼서 생긴 문제로, 최초 DP 생성 시 크기 기준으로 제한하도록 엔진을 고쳤다. 카플레이는 앱에서 ratio를 조정했다(대시보드 1.7에서 3.0, 카플레이 0.85에서 2.0). 두께 허용 상한이 2.5라 3.0이 2.5로 잘리는 점 때문에 상한 확대(최대 4.0)로 이어졌다.
- 11/9 내부 테스트: 최근장소 날짜 오류는 기존 사용자의 Java Calendar 기반 timestamp 월 값 변환 문제였다. 카플레이 경로선은 엔진 변경으로 두꺼워져 대시보드 두께를 3.5에서 2.5로 낮췄고, 화살표가 짧고 굵게 보이는 문제는 엔진 파트와 별도 일정으로 개선하기로 했다.
- 12/26 findLinkAndNode 비정상 종료: 문제 mapdata에서 특정 링크의 vertex 개수가 비정상적으로 적게 읽혔고 수신 데이터 오류로 판단, vertex 이상에도 종료되지 않는 예외 처리 엔진을 12/27 발행하기로 했다. 발생 단말은 iPhone 13 Pro, 14, Galaxy S20+ 등이고 iPhone 15 Pro, 11 Pro 등은 미발생이었다.
- 후면 카메라 안내(7/14): 후면 과속(0x020000), 후면 과속/신호(0x040000), 장애인보호(0x080000), 주민보호(0x100000) 카메라 타입이 GuideCamOpt에 추가되었고 모두 true로 설정해야 안내된다. 신규 버전 앱과 개발 서버 조합에서만 안내되어야 한다. iOS는 시뮬레이터용 라이브러리 링크 오류를 release 빌드로 해결하고 Universal Library를 NaviSDK에도 적용했다.
- 백그라운드 배터리 소진(9/1, iPhone): 위치 수집은 멈춰도 내비 메인 스레드가 계속 돌 수 있다는 분석이었고, 약 20분 미동작 시 앱을 종료하고 알림을 주는 안이 나왔다. ^[inferred] 8/14 MMC 크래시는 불완전한 GPS 궤적에서 링크 데이터를 과다 로딩해 생긴 예외로, 로딩 범위를 제한해 예방했다.
- 9/19 CCTV 정보 미제공 원인은 링크 수신 데몬의 메모리 부족(OutOfMemory)으로 신규 데이터 갱신이 멈춘 것이었고 재기동으로 복구했다. 11/10 전날 저녁 알람은 클라우드 작업에 따른 검색엔진 인스턴스 재기동 중 통합검색 타임아웃이었다.
- 마창대교 4,5종 할인(10/5): 앱 미터기가 에어의 톨 테이블을 쓰며 중복 할인 문제가 생겼고, 앱에서 요금 계산 로직을 동기화하거나 앱 미터기도 원본 DB를 분리하는 두 방안이 제안되었다. 4,5종 주말/공휴일 할인이 정상 동작하도록 수정 검토가 요청되었다.
- 10/4 주변 인기 장소 응답의 보조 정보(`nearHotPlacesInfo.poi.ExtraInfo2`)가 UNKNOWN으로 나온 원인은 신규 카테고리(키즈카페)의 일반/단축 명칭이 미지정이라 단축 과정에서 Unknown 처리된 것이다.
- 지도 SDK 충돌(9/22): 난독화 패키지 prefix를 적용한 0.9.4-beta3에서 정상 동작이 확인되었고 이후 0.10.0이 정식 배포되었다. 적용 후 Release APK는 약 128MB에서 159MB로 늘었는데 지도 AAR와 의존 라이브러리, 시뮬레이터용 SO 포함이 원인이라 정상으로 판단했다.
- 화물 SDK 문의: 12/19 건도 같은 원인(높이·중량 제한 false)이었고 SDK 0.6.2 요청이었다. 서버는 SDK가 보낸 userInput이 null이면 0으로 초기화하며, 재탐색(이탈 재탐색, 교통정보 재탐색)에도 header type 3 값이 동일하게 입력된다.
- 리스트 탐색 빈 옵션(12/19): 두 번째 탐색 옵션이 비면 앱이 기본 옵션을 넣고, 서버는 빈 값 옵션을 제외하며, Agent는 `routeList`의 `option_type`에 요청 옵션을 그대로 전달한다.
- 최근장소(11/1~11/8): Android는 50개 초과 시 핀 고정 장소를 제외하고 오래된 것부터 삭제하며, 핀 구분 키는 좌표 조합이고 iOS도 같은 방식으로 맞췄다. 이름 변경 후 연결 문제는 사양 확정 뒤 수정하기로 했다. 핀 버튼은 내 장소 추가, 목적지 변경 등에서 hidden 처리한다. 상단 고정 마이그레이션 미적용에 대해서는 공지로 안내하고 일회성 푸시를 검토했다.
- 신규 음성(9/4): 발랄한 음성은 후보 1번과 3번, 차분한 음성은 2번 선호가 많았다. 의견은 Confluence에 모아 취합하기로 했다.
- 카플레이 계기판 연동(10/18, iOS 03.05.10 388): 실차 테스트에서 계기판 연동과 TBT 표출이 안 되어 모델과 차량 설정을 추가 확인하기로 했다.
- 11/2 타이밍 겹침(지도 주기) 스레드와 iOS DP 이슈는 6절 내용 외에 개선 이슈 시트 39번 건이며, iOS에서만 재현되고 QA 단말에서는 재현되지 않았다.
