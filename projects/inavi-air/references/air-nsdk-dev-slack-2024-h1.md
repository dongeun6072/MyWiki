# Slack #001_air_nsdk_dev 개발 대화 (2024 상반기)

이 페이지는 에어·NSDK 앱 개발자들이 쓰는 비공개 Slack 채널의 2024년 1~6월 대화를 정리한다. 프로젝트 개요는 [[inavi-air]], 앞선 기록은 [[air-nsdk-dev-slack-2023-h2]], 하반기는 [[air-nsdk-dev-slack-2024-h2]]에 있다.

이 기간 채널에는 팀장(PL), iOS 개발자, Android 개발자(이동은), 기획 담당(수석)이 주로 참여했다. 같은 시기 스크럼 기록으로 [[air-hud-launch-stabilization-scrums-2024]](HUD), [[air-skp-ad-scrums-2024]](SKP 광고), [[air-usability-improvement-scrums-2024-h1]]가 있다. 버전별 변경 내역은 [[air-app-version-notes-2024]]에 있다.

**현재 반영 범위: 2024-01-01 ~ 2024-06-30.**

## 2024-01: HUD 라이브러리 교체와 메모리·발열

### HUD 라이브러리 (외부 HUD 업체 로드피아)

외부 HUD 업체가 iOS용 HUD 라이브러리(`HUD_ios_YYMMDD.zip`)를 거의 매주 새로 보냈다. 파일명 날짜는 240109(01-10 전달), 240111, 240112, 240116, 240118, 240123, 240125, 240131, 240201, 240214다. Android 개발자는 업체가 테스트할 에어 APK(Release, 03.05.34 B301360~B301362)를 01-17, 01-18, 01-23에 따로 보냈다.

- **빌드 호환성**
  - 240109판은 12월에 났던 것과 같은 빌드 오류가 다시 나서 재전달이 필요했다.
  - 240111판은 그 오류는 사라졌지만, 다른 Swift 컴파일러(5.9.0)로 만든 `BluetoothLibrary.swiftmodule`이라 Xcode 15.2에서 빌드되지 않았다. Clean Build Folder와 재부팅으로도 해결되지 않았다.
  - 240112판은 업체가 Xcode 15.2에 맞춰 다시 만든 것이다. 빌드가 정상이었고 develop에 넣었다.
  - 240116판은 framework 형태로 바뀌었다. Xcode 15.0에서 빌드, HUD 연결, 속도·회전지점 거리·구간단속 속도와 거리 표출을 확인한 뒤 팀장 지시로 별도 브랜치 작업 후 develop에 바로 merge했다.
- **거리 소수점 표시 수정**
  - 업체가 거리 소수점을 표출하는 사양으로 바꿨다. 이전에는 구간단속 남은 거리가 1km 이상이면 소수점이 잘못 찍혔다.
  - Android(01-10): 1.2km→`.1`, 17km→`1.7`이던 것이 1.2, 10.6으로 정상 표출됐다.
  - iOS(01-12, 240112판): 1.3km→`.1`, 13.5km→`1.3`이던 것이 1.3, 13.5로 정상 표출됐다.
- **스쿨존 심볼과 필드(01-18~19)**
  - 업체 요청으로 Android가 스쿨존 필드(`isSafeZone`)를 추가한 테스트 APK(B301361)를 보냈다. 팀장은 카메라 여부도 함께 봐야 하고, 실버존은 빼고 스쿨존만 체크해 새 필드에 넣으라고 했다.
  - 스쿨존에 들어가면 안전운전 거리와 속도가 0으로 넘어갔다. iOS도 240118판에서 같았다. QR220 단말은 CH4000과 달리 빨간 원이 표시되지 않았다. 팀장은 업체가 잘못 이해하고 있는 것으로 봤다.
  - iOS는 safeCode가 `SAFE_SCHOOL_ZONE`인데도 단속 카메라 심볼이 떴다(Android는 보호구역 심볼만 표시). 업체 수정판에서는 이 문제가 사라졌지만, 단속 카메라와 보호구역 심볼이 함께 떠야 할 때 보호구역만 표시되는 새 문제가 생겼다.
  - `isSafeZone` 필드는 02-01 테스트 APK에서 다시 원복했다.
- **CH4000 프로토콜 변경(01-22~01-31)**
  - CH4000 단말을 지원하면서 HUD 프로토콜이 바뀌었다(Android `HUD_AOS_20240122`, iOS 240123판). 두 OS를 비교한 결과 Android 쪽 이슈는 없었고, iOS에서 다음이 확인됐다.
    1. 단속 카메라와 보호구역 심볼이 함께 떠야 할 때 보호구역만 표시됨
    2. 어린이보호구역에서 빨간 띠가 깜빡이고 신호등 표시가 켜짐. 과속한 뒤 점멸이 꺼지지 않는 경우로 확인됐다.
    3. 버스전용차선에서 제한속도가 표출됨. 팀장 확인 결과 iOS가 정상이고 Android 라이브러리에서 고칠 사항이었다.
    4. 단속 카메라 심볼이 표출되지 않을 때가 있음
    5. 회전지점 거리 `4.0`, `3.0`에서 '.'이 빠짐
    6. 어린이보호구역 심볼이 깜빡임(보호구역 출발지에서 시작할 때)
  - 240125판에서는 5번만 고쳐졌다. 이 판은 분석용 로그 출력 버전이어서 상황별 로그를 업체에 전달했다.
  - 240131판에서 2번과 6번이 고쳐졌다. 업체는 "1, 3번 케이스는 신호과속 카메라에 심볼을 표시하지 않는 것이 사양"이라고 답했다(Android에서 수정). 번호가 어느 목록 기준인지는 원문에 없다. ^[ambiguous]
  - 240201판: safeCode 1102(어린이보호구역)와 1099(주정차 단속카메라)일 때 속도제한을 표시하지 않는다. iOS에 적용해 확인했다.
- **01-31 빌드 결정**
  - 팀장은 이날 빌드에서 HUD를 서비스 중인 버전으로 되돌리기로 했다.
  - iOS는 03.05.14(410)으로 빌드했다. HUD 연결과 데이터 표출, 도로명 '지하' 수정을 확인했다.
  - 01-30 빌드(409)의 테스트 노트 항목: 할인 가격 정책 적용, 스텝형 주소검색 "지하" 추가, CarPlay 회전 화살표 표시 개선, Bug Fix(HUD 이슈, 위젯 표출). 410은 같은 내용에서 HUD 항목만 "HUD 서비스 버전으로 변경"으로 바꿨다.
  - TestFlight에서 408→409, 409→410으로 업데이트하면 첫 실행 때 크래시가 다시 났다. Google 광고 SDK가 원인이 아니라는 뜻인지 iOS 개발자가 물었지만 결론은 없었다. ^[ambiguous]

### iOS 메모리 증가

- **증상**: 주행 시간에 비례해 메모리가 계속 늘었다. 01-15 develop 기준 첫 확인(iPhone 11 Pro, Instruments)에서는 CarPlay 없이 주행해도 늘었다.
  - DP `inaviair3_v0.0.6.2b`, iPhone 11 Pro, CarPlay+로그주행: 2분 386MB → 1시간 7분 781MB → 3시간 27분 1.2GB. RAM이 넉넉해 앱 리프레시는 없었다.
  - iPhone 6s(iOS 15.8): 2시간 43분에 1010MB. 리프레시는 없었지만 TBT, 경로선이 갱신되지 않고 안내 음성이 나오지 않았다.
- **`feature/map-memory-leak` 브랜치(01-25)**: 증가 폭이 크게 줄었다(1시간 27분 496MB, 다른 경로 1시간 55분 508MB). 지도만 띄운 상태로 1시간 두었을 때는 늘지 않았다.
- **01-26 팀장 분석**
  - 메모리가 초당 약 0.1MB씩 늘었다.
  - DP 엔진을 빼도, 광고를 빼도 늘지 않았다. 광고를 대략 5개 이상 미리 받아 두면 늘었다.
  - OpenGL Render를 쓰는 DP와 광고 쪽 문제로 추정했다. Context를 일정 수 이상 점유하면 메모리가 정상 해제되지 않는 것으로 봤다. ^[inferred]
  - 엔진 코드도 받아 봤지만 전부 확인할 수 없었고, 초기 텍스트 표출 때의 1회성 leak만 확인됐다.
- **01-26 대응**
  - 처음에는 메인 화면용 광고 3개만 미리 로드한다(Google 메인, Google 경로취소, Kakao 비즈보드). 경로취소는 팝업 표시 지연 때문에 미리 로드한다.
  - 나머지 광고는 화면에 들어갈 때 요청하고 화면을 벗어나면 해제해, 주행 중 광고를 3개 이하로 유지한다.
  - 광고 영역 표시 방식은 기획 담당이 2안(영역을 숨겨 두었다가 로드되면 표출)을 선호했다. 앱은 광고 쪽만 고치고, 분석 내용은 DP 담당자에게 공유하기로 했다.
  - 이 수정을 develop에 merge한 뒤 다시 측정하니 1분 370MB → 1시간 16분 480MB였다. 광고가 붙은 화면(안내종료 팝업, CCTV, 에어캐시, 쇼핑하기, 쿠폰함)을 반복 진입해도 이상은 없었다.

### 발열과 백그라운드 종료

- **발열(01-22)**
  - 테스트 빌드 03.05.14(408)의 DP 엔진은 발열과 CPU 문제가 분명했다. 출근 20km 미만 주행에 배터리가 100%에서 42%로 줄었다는 보고가 있었다.
  - 수정된 DP `inaviair3_v0.0.6.2b`는 상용 03.05.13(401)과 비교해 발열과 CPU 점유율 차이가 없었다(CarPlay 유무 30분 이상 주행, 다른 앱과 동시 실행).
- **백그라운드 종료(01-16)**
  - 증상: 안전운행모드나 경로안내 중 백그라운드로 보내면 앱이 종료됐다. 빌드 408에서 iPhone 11 Pro와 13 Pro(iOS 17.2.1)는 100% 재현됐고, 6s(iOS 15.8)에서는 나지 않았다.
  - 원인: 커밋 전후를 빌드해 비교한 결과, DP 엔진 `inaviair3_v0.0.6.2a` 적용 커밋(AIR-1450) 이후 생긴 문제였다.

### iOS 출시·스토어 이슈

- **ITMS-90626 경고**
  - Siri custom intent(GoDriveMode, GoFavorite, GoHome)의 ko_KR 현지화가 없다는 경고가 3.5.14(404) 업로드 뒤 다시 왔다.
  - 원인으로 추정한 부분을 고쳐 별도 브랜치에서 405로 업로드해 보았다(배포 없이 메일 수신 여부 확인용). intentdefinition 비교, localization 재추가, Siri Suggestions 옵션 끄기, ipa 내부 `Localizable.strings` 확인을 했지만 같은 메일이 왔다. 외부 Q&A에 질문을 올렸다(AIR-1497).
- **iOS 13 이하 분기 정리(AIR-1502)**
  - `#available(iOS 13.0, *)`와 iOS 11·12 분기를 일괄 제거했다. Objective-C 쪽 `@available` 분기는 다음 스프린트로 미뤘다(01-30).
  - 이때 변수가 중복 선언돼 02-07 develop 빌드가 깨졌다. 수정하면서 `mgr`를 `carplayManager`로 이름을 바꿨다.
- **위젯 미표출(AIR-1538)**: TestFlight로 받은 408·402에서는 정상이었고, Xcode 15로 직접 빌드해 설치하면 재현됐다. Xcode 15와 iOS 17의 containerBackground 변경 때문이었다. iOS 17 분기로 고쳤고, 위젯 좌우 여백도 함께 없앴다(라이트·다크 모드, iOS 17.2.1과 15.8에서 확인).
- **검색 크래시(01-02)**: `indexOfWordInString`에서 lowercased 문자열로 구한 range를 원문 문자열의 distance에 써서 iOS 15 이하에서 크래시가 났다. lowercased 문자열로 통일한 코드가 iOS 15 이하에서도 정상 동작함을 확인했다.
- **할인가**
  - 01-22 할인 가격 적용 PR: 상품 상세가 로딩되기 전에 정가가 보이던 부분을 '-'로 바꿨다.
  - 01-26 구매 단계에서 할인가가 아닌 정가가 보였다. Android는 이미 정상이었고(잔액관리상품 테스트 구매), iOS를 고친 뒤 구매 테스트에서 정상 차감을 확인했다.
  - 캐시상품 Admin 연동(할인 포함)은 앱 개발이 끝났고, 개발 서버 구매 테스트 뒤 Admin 상용 반영을 요청하기로 했다.
- **기타**
  - CocoaPods 1.15.0으로 `Podfile.lock`을 갱신했다.
  - 01-18 1500원 쿠폰 등록 오류: 쿠폰 유효기간을 2023년으로 잘못 지정한 것이 원인이어서 서버 담당이 2024-01-31로 바꿨다. 쿠폰 입력기한 만료 팝업은 Admin 고정값 대신 Agent가 내려주는 메시지로 띄우기로 했다.

### Android

- **이미지 미표시(01-30)**: 쇼핑 상세에서 이미지가 가끔 안 보였다. Release 빌드에서만 간헐적으로 났다. Glide 콜백에서 비트맵을 메인 스레드가 아닌 곳에 세팅한 것이 원인이었다. 메인 스레드에서 세팅해 해결했다.
- **도로명 "지하"(01-19)**: '산'처럼 띄어쓰기 없이 붙여 쓰도록 했다. iOS에서는 "지하"를 입력한 뒤 커서를 옮겨 '하'만 지우면 반복 입력되는 예외가 확인됐고(01-30), 410 빌드 전에 고쳤다.
- **신규 음성 테스트 APK(01-02, 03.05.34 B301360)**: 길안내 음성 순서는 발랄한 음성(기본), 차분한 음성, 아이나비 클래식이다.
- **Jenkins 로그인 불가**: 01-30 Jenkins에 로그인되지 않아 빌드가 늦어졌다.

### SKP 광고 첫 검토 (01-29)

- **Planet AD(SKPAdBenefit)**: Native 배너형이 따로 없다. 미디어 1200x627과 CTA View 등 최소 크기가 크다. Native·Feed 바로 적립형 광고는 기존 오퍼월과 같은 서버 연동이 필요하다.
- **AD Network 상품**: 기존 Google AD와 Kakao AdFit 구조에서 unitID만 바꾸면 된다. Planet AD 상품을 넣으면 더보기·피드·하단 팝업 같은 기획이 추가로 필요하다.
- **추가 문의(02-06)**: 에어캐시 정책상 로그인한 사용자만 보상을 받는다. 그래서 팀장이 unitID별로 보상형과 비보상형을 설정할 수 있는지 SKP 문의를 기획 담당에게 요청했다.

## 2024-02: SKP 광고 1차 개발과 3.5.15

### SKP 광고 연동 (AIR-1536)

- 항목별 결과:

  | API 분류 | 해당 | 처리 |
  |---|---|---|
  | File timestamp | 에어 코드 | 에어 manifest에 추가, 테스트 빌드 후 메일 지적 사라짐 |
  | User defaults | 에어 코드 | 에어 manifest에 추가, 테스트 빌드 후 메일 지적 사라짐 |
  | System boot time | Alamofire, Firebase Crashlytics | 에어 manifest에 추가 시도 |
  | Disk space | Firebase Crashlytics(재확인 후 발견) | 에어 manifest에 추가 시도 |
  | Active keyboard | 해당 없음 | - |

- Alamofire는 5.9.0, Firebase는 10.22.0부터 자체 manifest를 포함한다.

### 캐시버튼·포인트홈 (Android)

- **06-19~21 캐시버튼(아바티) 적용 흐름**
  1. Application 클래스에서 `CashButtonSDK` Builder로 초기화한다. AppID와 AppSecret이 필요하다. 설정하는 옵션은 포인트 테마(`setPointType`), 알림 아이콘, 스토어 평점 유도 문구, 버즈빌 연동 여부(`setUserBuzzProfile`)뿐이다.
  2. 포인트 전환 콜백에서 받은 transactionID로 에어캐시 전환 API(Agent)를 호출하고, 결과를 `CashButtonExchangeConfig.onCompleted(isSuccess)`로 돌려준다.
  3. 기본 버튼이 없어 커스텀 View 가이드로 버튼을 만든다.
  4. 에어캐시 적립 후 다이얼로그에서 확인이나 뒤로가기를 누르면 캐시버튼 대시보드를 띄운다.
  - 신규 포인트홈 샘플 앱은 Android와 iOS 모두 없었다.
- **06-28 포인트홈 적용 이슈**
  - 흐름: Application에서 기존 캐시버튼 AppID/AppSecret으로 초기화 → 에어캐시 화면 진입 시 레이아웃 초기화(성공) → 포인트홈 슬라이드 열기.
  - 개발모드(DevelopMode)를 true로 두면 슬라이드를 여는 순간 대시보드 상태 리스너가 오류를 돌려줘 대시보드가 열리지 않았다.
  - false로 두면 대시보드는 열리지만 일부 기능이 동작하지 않았다(뒤로가기, 광고 맞춤설정 해제).
  - 가이드에 테스트 키는 없었고, 테스트하려면 발급을 요청하라고 돼 있었다. 아바티가 개발모드 테스트 앱을 만든 뒤에도 같은 오류가 났다. 개발모드 정상 접근은 7월에 확인됐다. 키 값은 원본에 있음(미수록).
- 이후 흐름은 [[air-point-home-new-cash-button-2023-2024]]에 있다.
