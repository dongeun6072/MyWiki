# SDK 스크럼 공통 항목 추적 (2025-10 ~ 2026-07)

2025년 10월 29일 NaviSDK 상품화 #1부터 2026년 7월 8일 SDK 유지보수 #2까지, 여러 스크럼에 반복해서 나오는 공통 블록(로드맵, 접두어, Style.json, 통계, 미완 항목, 에어 패치)의 처음 등장 시점과 상태 변화를 한곳에 모았다. 개별 스프린트 문서는 [[sdk-sprints-2025-2026-hub]]에서 찾을 수 있고, 전체 요약은 [[navisdk-confluence-sprint-timeline-2024-2026]]에 있다.

## 로드맵
| 시점 | 내용 |
|---|---|
| 10/29 ~ 1/14 | 25년 4분기: iOS NaviSDK 서비스 / 26년 1분기: MapsSDK 서비스 / 상시 대응(상용서버 전환, 업체 요청사항 대응, 미진한 항목 검토 및 개발: 차로 안내, 실차 개선 항목 검토 및 개발: 연결로 진입/진출 안내(특히 고가도로, 램프 구간 안내 강화), 회전구간 안내 강화) |
| 1/21 ~ 3/18 | 26년 1분기: 1) Map SDK 서비스(~3월 중), 2) Map SDK 가이드 작업(이미지, 마크다운 작업 등), 3) web Map SDK 연동 작업 / 상시 대응 동일 |
| 3/25 이후 | 로드맵 블록 삭제, 목표 문구로 대체(Orbis Navi SDK Truck 서비스, 국내향 Flutter 대응, SDK 유지보수) |

## 접두어
- 처음 등장: 1/21 Map SDK 상품화 #1 (공통 항목 안)
- 내용: navisdk = `inv`, mapsdk = `igm`(강조), 명칭은 inavi-global navigation sdk, inavi-global map sdk
- 1/28부터 "[ 접두어 ]" 별도 블록, 3/18까지 유지, 3/25부터 사라짐

## 인증과 Style.json
| 날짜 | 변화 |
|---|---|
| 1/21 | 인증: 국내 Navi/Map SDK 동일. 해외는 지도 스타일 하드코딩 - Step 1 NaviSDK와 동일한 CDN 하드코딩 접근, Step 2 해외향 인증 신규 API 추가 |
| 1/28 | Style.json 4종류(en light/dark, cn light/dark). 인증서버에 Navi/Map 구분 필요 |
| 2/4 | Style.json 1벌로 통일(언어, 테마) |
| 3/11 | "호주향 - Style.json 1벌로 통일"로 표기 변경, 7/8까지 매 스크럼 유지 |
| 5/27 | Web 기반 인증(Style) 적용(다국어, 다크모드) 시작 |
| 6/4 | Navi 1.0.4, Map 1.0.1 포함 예정 |
| 6/10 | Map 1.0.1 쪽 완료, Navi 1.0.4 진행 |

## 통계
- 처음 등장: 2/4 Map SDK 상품화 #3 - SDK 사용자 수 (Appkey당 사용자 수). NaviSDK/MapSDK 모두 Appkey, UniqueKey 전달, UniqueKey는 UUID
- 3/25부터 "진행 중" 표시, 7/8까지 유지(완료 표시 없음)

## 준상용서버, 버전
- 1/21 준상용서버 구축(앱: Agent Domain 변경 여부 확인), 2/4 완료. NaviSDK 1.0.1 준비(1/28~2/4)
- 3/11 Truck: 탐색 Lib 1.0.1.4 연동, 3/18 준상용서버에서 확인
- 5/20 Navi SDK 1.0.3 준비(route 1.0.1.6, MMC 0.0.6), 5/27 완료
- 6/4 Navi 1.0.4, Map 1.0.1 (Web 기반 인증)
- 지도 버전 분기(탐색엔진 분기): 2/11 처음, 3/11 Truck에서 구현 항목, 6/24 Orbis 신규 탐색엔진(v26220)에서 차후 구조 설명

| 6/17 | 이번 패치: 고속도로/지하차도/고가도로 목적지 팝업(경유지 유지, 문구 "일반 도로"에서 "주변 도로"로), 차기 패치: 지점 자동 변경 시나리오(지점 핀, LineTo) |
| 7/8 | 방안 3: smr 다운로드 상태는 현 사양 유지, 미다운로드 상태는 탐색 완료 화면에서 팝업 |
