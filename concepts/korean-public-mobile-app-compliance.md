# 공공 모바일 앱 준수 사항

[[seoul-donghaengmap]] 같은 공공 앱은 민간 앱과 달리 **법령·지침 준수 여부를 검증**받는다. 이 페이지는 그 중 분량이 작은 문서(지침 8쪽, 별표 5개, 디지털포용법 11쪽, 호환성 가이드 9쪽)를 정리한 것이다. 접근성 지침, 웹 접근성(KWCAG), UI/UX 가이드라인, 보안 점검 가이드는 분량이 커서 별도 페이지로 요지만 정리했다(아래 "관련 가이드").

## 1. 모바일 전자정부 서비스 관리 지침 (행정안전부예규 제366호, 2026-05-12 시행)

- **적용**: 국가기관, 지자체, 공공기관이 모바일 전자정부 서비스를 만들고 관리할 때(「전자정부법」 제16조)
- **기본 원칙(제4조)**: 모든 이용자가 보편적으로 활용(보편성), 신뢰성, 이동성·사용자 편의성·개인 맞춤, **정보 현행화와 주기적 점검**, 보안 대책 수립
- **구축 시 준수 지침 12종(제5조)**: 모바일 서비스 구축 가이드라인, 공통기반 활용, 웹 사이트 품질관리, **장애인·고령자 정보 접근·이용 편의 증진 고시**, 정보시스템 구축·운영 지침, **전자정부 모바일 표준프레임워크**, 도메인·IP 표준, 대민 모바일 보안공통기반, 모바일 활용업무 보안, **모바일 대민서비스 보안취약점 점검가이드**, 앱 소스코드 검증 가이드라인, 스마트폰 앱 접근권한 개인정보보호 안내서
- 사전 검토: 타당성, 효과성, 중복성, 상호 연계, 공동 이용. 사전협의 대상 사업은 영 제83조 절차
- **행정서비스**(내부 업무용)는 지원센터에 등록·검증(14일 이내 승인/반려, 반려 시 30일 내 재등록)·배포한다. **대민서비스**(국민 대상)는 이 지침의 등록·배포 절차 대신 보안과 성과 기준의 적용 대상이다. ^[inferred]
- 긴급 배포: 재해·재난, 현장업무 명백한 오류, 보안 약점으로 정보 유출이 예상될 때는 검증 전에 배포할 수 있다(반려되면 즉시 중지).

## 2. 별표: 보안 점검과 성과 측정

| 별표 | 내용 |
|---|---|
| 1 앱 보안취약점 점검기준 | 설치(반복 설치 오류, 비정상 파일, 과도한 설정), 삭제 후 안전성, 동작(기능 정상 동작, 악성 행위, **정보 외부 유출**, 자원 고갈), 플랫폼(루팅·탈옥 기기 동작, UID·GID, SharedUserID, 인텐트 권한), 식별·인증(인증 정보 강도), **암호**(중요정보 평문 저장·전송, 취약한 암호 알고리즘) 등 |
| 2 서버(웹·앱) 점검기준 | OS 명령 실행, SQL·XPath 인젝션, 정보 누출, 악성 콘텐츠, XSS, 약한 문자열 강도, 불충분한 인증·인가, 취약한 패스워드 복구, 세션 관리, CSRF, 자동화 공격 등 |
| 3 앱 보안약점 점검기준(소스코드) | SQL 삽입, 경로 조작, XSS, OS 명령어 삽입, 오버플로우, 취약한 암호 알고리즘, **평문 저장·전송**, **하드코드된 비밀번호·암호화 키**, 짧은 키 길이, 예측 가능한 난수, 주석에 시스템 정보 포함 등 |
| 4 모바일 행정서비스 성과지표 | 계획·기반(10점), **구축 보안대책**(30점: 위협분석, 시큐어코딩, 취약점 점검, 조치, 보고서), 운영 규정 준수(20점), **이용률**(30점) 등 |
| 5 모바일 대민서비스 성과지표 | **국민 이용 측면**(40점: 누적 다운로드 수, 전년 대비 증감률, 예산 대비 활용도, 서비스 지속 기간)과 **기관 관리 노력 측면**(60점: 관리 충실성 45점 = **업데이트 최신성** 20점(24개월 이상 미갱신 0점, 12개월 미만 20점) + 앱 만족도 15점 + 이용자 리뷰 답변율 10점, 접근 편의성 15점 = 하위 OS 지원 6점 + 복수 앱스토어 게시 9점). 총점 70점 이상 유지, 60~70점 개선, 60점 미만 폐기(국민 이용 측면 20점 미만은 유지에서 제외) |

**신규 앱 개발 시 챙길 점**: 별표 3의 하드코드 비밀번호·키 금지와 별표 1의 평문 저장·전송 금지는 코드 리뷰 체크리스트로 바로 쓸 수 있다. 기존 앱 진단에서 나온 "메모리 내 ID/PW 노출"도 별표 기준과 맞닿아 있다. ([[seoul-donghaengmap-app-vulnerability-reports]]) ^[inferred] 별표 5의 업데이트 최신성 항목은 정기 갱신이 성과 점수에 영향을 준다는 뜻이다.

## 3. 디지털포용법 (법률 제20672호, 2026-01-22)

디지털포용 증진과 관련 산업 육성에 관한 법. 이 프로젝트와 직접 연결되는 조항은 다음과 같다.

- **제3조 책무**: 국가와 지자체는 모든 구성원이 지능정보서비스를 이용할 수 있도록 한다. **제4조 대체수단 제공**
- **제12조 디지털포용 영향평가**: 국가기관 등이 지능정보서비스를 신규 도입·구축할 때
- **제19조 접근성 보장**: 국가기관 등이 웹사이트, **이동통신단말장치에 설치되는 응용 소프트웨어(앱)**, 무인정보단말기 등을 제공할 때 디지털취약계층이 어려움 없이 이용하도록 접근성을 보장해야 한다.
- **제21~22조 접근성 품질인증**: 접근성 품질인증 제도. 이 프로젝트의 **모바일 접근성 인증마크 획득** 요구(기술협상 7번)가 여기에 해당한다. ([[seoul-donghaengmap-negotiation-kickoff]]) ^[inferred]
- 제23조 접근성이 보장된 제품의 우선구매, 제14~18조 디지털역량 함양, 제20조 무인정보단말기(과태료 근거는 제37조)

## 4. 전자정부 표준프레임워크 호환성 가이드 (2026-06-22)

표준프레임워크(eGovFrame) 기반 프로젝트가 호환성 확인을 통과하기 위한 규칙이다.

| 규칙 | 내용 |
|---|---|
| 라이브러리 변경 금지 | `org.egovframe.rte`로 시작하는 실행환경 라이브러리(3.10 이하는 `egovframework.rte`)는 해시(MD5/SHA1)가 원본과 같아야 한다. 확장은 상속으로 |
| 적용 범위·버전 | 필수 4종(`ptl-mvc`, `fdl-cmmn`, `psl-dataaccess`, `fdl-logging`)을 같은 버전으로. 자동 적용되는 Spring Framework/Boot 버전은 바꾸지 않되 **패치 버전에 한해** 실행환경 적용 버전보다 최신 허용 |
| 설정 | 트랜잭션(AOP/Annotation), DB 커넥션 풀 설정 포함. XML 외 Java Config, Spring Boot 설정도 가능 |
| MVC 아키텍처 | Controller가 DAO를 직접 호출하거나 여러 저장소(NoSQL, MQ, Cache)를 호출할 수 없고, 비즈니스 로직은 주입된 서비스를 거쳐야 한다(예외 없음, Servlet은 일부 허용) |

신규 앱서버는 Spring Boot 4.1 + Kotlin이다. ([[seoul-donghaengmap-backend-env]]) 이 가이드는 Java 표준프레임워크 기준이므로 Kotlin/Spring Boot 4 기반 앱서버와 호환성 확인 대상인지, 어떤 규칙이 적용되는지는 문서만으로 알 수 없다. ^[ambiguous]
