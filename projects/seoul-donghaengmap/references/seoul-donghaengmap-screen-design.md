# 서울동행맵 화면기획서 v1.0과 메뉴 구조

아이나비시스템즈가 만든 **신규 앱 화면기획서**다. v0.6(2026-08-19)에서 v1.0(2026-09-30)까지 약 6주 동안 개정됐고, 2026-09-23 공유본(PDF)과 09-30 최종본(PPTX)을 읽었다. 앱 사업 전체는 [[seoul-donghaengmap]]이고, 기능 목록은 [[seoul-donghaengmap-functional-spec]], 시각 규칙은 [[seoul-donghaengmap-design-system]]이다. 작성자 이름은 적지 않았다.

## 메뉴 구조(IA) v1.0

- **온보딩**: 0-1 로그인, 0-2 회원가입(교통약자 유형 선택 → 닉네임 → 약관 동의), 0-3 비회원 시작
- **하단 3탭**: 1-0 홈, 2-0 길안내, 3-0 마이페이지
- **홈 6버튼**: 길안내(1-1), 인근 편의시설(1-2), 버스정류장(1-3), 지하철역(1-4), 택시 호출(1-5), 불편신고(1-6)
- **인근 편의시설 7종**(1-2-1~7): 지하철 내 수유실, 장애인 화장실, 휠체어 충전소, 엘리베이터, 접근성 정보 조회, 에스컬레이터, 청계천 이동약자 시설물. 표출 순서는 교통약자 유형별로 개인화한다.
- **길안내(2-x)**: 2-0 길안내, 2-1 장소 검색, 2-2 장소 상세, 2-3 상세경로, 2-4-1 실외 내비, 2-4-2 실내 내비, 2-5 버스정류장 정보, 2-5-1 노선 상세, 2-7 음성인식, 2-9 경로 리스트, 2-9-1 경로 편집
- **마이페이지(3-x)**: 교통약자 유형 변경, 내 마일리지, 즐겨찾기 관리, 저상버스 예약 내역, 공지사항, 1:1 문의, 이용약관, 오픈소스 라이선스, 로그아웃, 회원 탈퇴, 언어 변경(5개 언어)

## 개정 흐름

버전별 상세 변경, 일 단위 중간본의 차이, 번호 재부여 내역은 [[seoul-donghaengmap-screen-design-revisions]]에 따로 정리했다. 아래 표는 요약이다. 문서 안 개정 이력표 기준으로 v1.0의 일자는 09-28이고, 이 페이지가 읽은 09-30 파일은 그 뒤 수정본으로 보인다. ^[inferred]

|---|---|---|

| v0.8 | 09-08 | 길안내 경유지 **최대 1개**, **실내 내비 신설**, 검색 필터(정류장 내 주변 300m), 불편신고 입력 3종(유형·내용·사진), 마이페이지 글자 크기 2단, **저상버스 예약을 "승하차 예약" → "승차 예약", 4단계(예약 → 확정 → 탑승 준비 → 탑승 완료)** |

| v1.0 | 09-30 | 로그인·약관·토스트 정비, 홈 예약 현황 위젯, **버스·지하철 정보 화면 분리와 "차기·차차기" 폐기**, 택시 호출 4종 카드와 자격 고지·바우처 신청, 불편신고 상태 4종, **경로 리스트 2-9 독립**, **음성인식 2-7(마이크 권한 필수, 텍스트 입력 폐기)**, 마이 레이아웃, 언어 변경, 마일리지 내역 3분할, 1:1 문의 신설, 전역 정비("경유" 폐기 등) |

## 길안내 주요 규칙 (v1.0)

- **경로 리스트 2-9**: 지도 없이 리스트만. 행 = 소요시간, 도착 시각·요금, 전체 경로 바, 구간 요약, `[안내시작]`(하단 전폭). 탐색 기준·이동수단 태그는 제공하지 않는다.
- 필터와 정렬은 상단 고정 2종. 정렬은 "최단거리"/"최소환승" 단일 선택(해제 불가). **교통약자 유형이 필터와 정렬 기본값을 결정**한다.
- 새로고침: 하단 우측 플로팅은 도착 정보만 갱신, 리스트 최상단 당겨서 새로고침은 경로 재탐색. 두 동작은 혼용하지 않는다.
- 빈 상태 5종의 문안을 구분한다: 조건에 맞는 경로 0건(필터 자동 해제 안 함), 서울 밖 지점("서울 외 지역은 경로를 안내할 수 없습니다"), 필터를 모두 꺼도 0건(탐색 실패+다시시도), 조회 실패, 지점 겹침. 출발지가 현위치에서 100m를 넘으면 `[안내시작]`을 막고 팝업을 띄운다.
- 안내 중에 다른 경로를 선택하면 확인 팝업이 뜨고 묻지 않고 갈아타지 않는다.
- **상세경로 2-3**: 지도+바텀시트, 시트 3단계(최소·중간·최대, 기본 중간). 지하철 구간에 방면, "빠른 환승/하차", 승강장, 차기·차차기 도착(1분 미만 "곧 도착", 10분 미만 "N분 N초", 10분 이상 "N분")
- 도착 정보는 10초마다 자동 갱신하고 `[새로고침]`을 둔다.
- **실내외 전환은 seamless**: 실외 → 실내 → 실외 순환이 가능하고 도착은 마지막 구간에서 발생한다.

## 전맹(시각장애인) 모드와 음성

- 회원가입에서 전맹을 고르면 **시각장애인용 화면**으로 바뀐다. 화면 구성은 위에서 아래로 한 방향 배열, 스크린리더 포커스 순서를 고려한다. ([[seoul-donghaengmap-design-system]])
- 음성인식 2-7: 화면을 길게 눌러 말하면 장소를 찾고 경로를 설정한다. 진입점 3곳, 긴급 안내, 주변 안내 반경 50m.
- **NLU 의도 5종과 응답 규격**: ① 하차 알림 요청("하차 알림 해줘" → 하차 1정거장 전 알림, 결과 카드에서 즉시 해제) ② 잔여 정류장 문의 ③ 목적지 안내(임의 실행 없이 "안내를 시작할까요?"로 확인) ④ 주변 시설 문의("내 앞에 무엇이 있나요?" → 시계방향, 지형지물, 남은 거리) ⑤ 플랫폼 위치 문의(다음 행동 지시는 항상 한 개)
- **음성으로 제공 불가한 기능**: 버스 도착 "순서"(노드-링크가 정류장~정류장 1개라 신호 대기를 알 수 없어 ETA를 분해할 수 없음), 예약 취소(MQTT → 관제 → 차량 단말기로 즉시 전달되며 BIS에 취소 기능이 없음, 단말기 개조 필요), 예약 사전 발신(앱이 저장해 두었다가 사용자가 정류장에 있을 때 발신해야 함), 만차·혼잡도(이번 릴리스 범위 밖, 2027-01-04 이후)

## 아로정보기술 초안(v0.5)과의 관계

화면기획서는 먼저 **아로정보기술**이 v0.5로 초안을 냈고(메뉴 구조: 홈, 길안내, 대중교통, 편의시설, 불편신고, 마이페이지, 서비스정보), 아이나비시스템즈가 v0.6부터 이를 대체·재구성한 것으로 보인다. 초안의 회원가입 유형은 노약자·임산부, 휠체어·유모차, 경증 시각장애인, 중증 시각장애인(나중에 선택)이었다. ^[inferred]

## 개정 중 정해진 규칙 보충

- **회원가입 유형 분기**: 시각장애는 등급이 진단서로 정해지는 행정 등급이라 사용자가 스스로 판단하기 어렵다는 이유로 **저시력/전맹 2분기**로 한다(v0.8, 09-04본). 한 단계에서는 한 가지만 선택·입력하고, 애플 로그인은 iOS에만 노출한다. 비회원이 가입하면 닉네임은 승계하지 않고 새로 입력한다.
- **저상버스 승차 예약 4단계의 발신 주체**: ② 예약 확정(정류장 반경 50m + 2정거장 전)은 사용자 조작이 아니라 **조건 충족 시 앱이 관제 연계 시스템으로 발신**한다. ③ 탑승 준비 푸시 이후 정류장 반경 50m 이탈 시 탑승 확인 팝업을 예약 1건당 1회만 띄운다.
- 홈 초기 구상(디자인 초안)은 하단 4탭이었으나 기획서에서 3탭으로 확정됐다. ([[seoul-donghaengmap-design-concept-evolution]])
