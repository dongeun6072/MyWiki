# Slack #001_air_nsdk_dev 개발 대화 (2024 하반기)

이 페이지는 에어·NSDK 개발 비공개 Slack 채널의 2024년 7~12월 대화를 정리한다. 프로젝트 개요는 [[inavi-air]], 앞선 기록은 [[air-nsdk-dev-slack-2023-h2]]과 [[air-nsdk-dev-slack-2024-h1]]에 있다.

09-13에 팀장이 채널 이름을 "001_air3_dev"에서 "001_air_nsdk_dev"로 바꾸고, 채널 목적을 "NSDK, AIR의 성공"으로 정했다. 11월부터 iOS(KMP) 개발자가 새로 합류했고, 이후 대화의 절반 가까이가 NaviSDK 리뉴얼 이야기다. 리뉴얼의 상세 계획은 [[new-navisdk-plan-detail]]과 [[orbis-sdk]], 에어봇은 [[air-genai-scrum-2024]]와 [[air-genai-airbot-review-2024]], 운영 기록은 [[air-operations-2024]]에 있다.

**현재 반영 범위: 2024-07-01 ~ 2024-12-31.**

## 2024-07: 7월 패치, 홍수 VVMS, 캐시버튼 v3

- **7월 패치 항목(07-04)**: 홍수 관제 VVMS, '부드러운 음성'(기존 1·2 외에 타입 3으로 요청하고 캐시 파일 추가), 환경설정 '자주 묻는 질문'.
- **홍수 VVMS 안내 거리**
  - 안내엔진 소스에 VVMS 안내 거리가 700m로 하드코딩되어 있다. 팀장은 홍수만 2~3km로 하고 나머지 VVMS는 700m를 유지하는 쪽을 원했다.
  - 07-16 서버가 2km 안내 사양을 적용할 수 있다고 해 서버 2000m를 그대로 두었다. 엔진 700m가 더해져 실제로는 약 2.7km이고, 개발 사양은 "2.5km 안내"로 정리했다.
  - 07-17 상용 반영 뒤 침수 데이터가 내려오지 않았다. 홍수정보를 받아오는 서버 2대 중 1대만 켜져 있었던 것이 원인이었고, 둘 다 켠 뒤 해결됐다.
- **길안내 음성 순서(AIR-1482)**
  - 기획 없이 Jira 티켓에서 "발랄한 / 아이나비 클래식 / 부드러운" 순서로 정해져 있었다. 07-16 팀장이 "발랄한 / 부드러운 / 아이나비 클래식"으로 바꾸게 했다.
  - 환경설정이 index로 저장되어 있어, Android에 신규 안내음성 타입으로 옮기는 마이그레이션 로직을 넣었다.
  - 개발서버에서 부드러운 음성이 나오지 않은 원인은 방면 음성 캐시가 폴더로 구분되어 기존 다운로드 데이터가 재생된 것이었다. 앱 캐시를 지우자 정상 발성했다.
- **Android 03.05.40 → 03.05.41(301393)**
  - 07-18 Play 사전 출시 보고서에서 `NullPointerException`(Object.getClass)이 나왔다. 이용약관 화면의 "서비스 종료" 버튼 흐름에서 발생하고, AIR가 쓰지 않는 Google Play Wallet 쪽에서 난다. 보유 단말과 Pixel 8 에뮬레이터에서는 재현되지 않았고, Google의 알려진 이슈로 봤다.
  - Google Ads 의존성을 올렸다: `play-services-ads` 21.3.0 → 22.3.0, `play-services-ads-identifier` 18.0.1 → 18.1.0. 더 높은 버전은 Kotlin 버전 업과 targetSdk 34가 필요해 보류했다.
  - 07-22 AOS 검증이 끝났고, 팀장이 07-23 오후 AOS 100% 출시를 지시했다.
  - 07-23 VVMS 관련 비정상 종료가 여러 건 나와 03.05.40을 10%로 내리고 다시 빌드했다. 운영 규칙: 새 버전을 프로덕션에 올리기 전에 이전 버전을 100%로 바꾼다.
  - 같은 날 심사 실패에 대비해 현재 서비스 버전에 음성 DB만 바꾼 03.05.41(301393)을 내부 테스트 트랙에 임시 저장했고, 이 버전으로 바로 재검토를 요청했다.
  - 07-31 다른 회사가 먼저 심사를 통과한 것을 보고 Android Target을 바꿔 다시 빌드했다. Play Console이 Android 14 포그라운드 서비스 권한 선언을 요구해 "앱 시작 → 경로 탐색 → 안내 시작" 테스트 영상을 제출했다.
  - 팀장이 Firebase privacy manifest 안내를 공유해, 다음 패치에서 iOS SDK와 Android crashlytics 라이브러리를 최신으로 올리기로 했다.
- **캐시버튼 V3.0.4.304(Android, 07-05 검토)**
  - 알림창 상태바가 제거됐다. 연동 앱사의 Android 14 대응 부담 때문이고, 이제 라이브러리는 Notification View만 주고 나머지(알림 선택 동작, 포그라운드 서비스 지정, 실행 시점)는 앱이 구현한다.
  - 초기화 때 버즈빌 BuzzAdsPID 3종(main, feedContent, feedShopping) 세팅이 가이드상 필수가 됐다. 세팅하지 않아도 동작은 하지만 피드 적립의 광고·쇼핑 적립 배너가 사라진다. 키 값은 원본에 있음(미수록).
  - 상태바를 쓰지 않으면 아바티 영업팀에 알려야 한다. 이상이 없으면 7월 패치(07-19 이후)에 넣기로 했지만, 07-22까지 발급 키로 테스트해도 광고·쇼핑 피드가 표출되지 않았다. 사업부 피드백을 본 뒤 오픈하기로 했다.
- **포인트홈(아바티) 신규 연동 검토**
  - 07-01 문의 예정 항목: iOS는 appid·appSecretKey 발급, floating 버튼 위치 조절, 최신 2.0.0 기준 가이드, mintegral 가이드 누락. AOS는 기존 appid·appSecretKey로 정상 동작하지 않고, DevelopMode를 false로 하면 일부 기능과 버튼이 동작하지 않는다.
  - 07-23 Android 검토: 개발모드와 관계없이 대시보드에는 '네이버페이 포인트 전환'만 있고 기존 캐시버튼의 '에어캐시 전환'은 없다.
  - 앱 삭제 후 포인트홈 슬라이드를 처음 열기 전까지 사용자 프로필 조회 API가 `PointHomeError: 사용자 동의가 필요합니다.`를 반환한다. 한 번 열면 정상이다. 실패 시 UI 예외 처리는 해 두었다.
  - 흐름은 [[air-point-home-new-cash-button-2023-2024]]로 이어진다.
- **광고 Refresh**
  - 07-11 Android 메인·앱종료·경로취소 지면은 ServiceGate 이후 광고를 미리 할당받아 화면 표출 때 저장된 NativeAd를 세팅한다. 다시 할당(load)하는 것은 적립 가능 광고 갱신을 위해 로그인·로그아웃 때뿐이다.
  - 07-26 사업 쪽이 SKP와의 논의 끝에 메인 광고(Planet AD, Google) Refresh를 다시 요청했다.
  - 07-31 검토 사양: Google 광고 갱신 시점과 같게 갱신, 실패하면 기존 광고 유지, 최소 3초 간격. Bg→Fg 갱신은 적립 후 기존 광고가 사라지는 문제가 있어 넣지 않는 쪽을 제안했다.
  - 08-02 임원 협의 결과: 8월 서비스 목표로 Back 이동과 Bg→Fg 이동 때 Google과 SKP 모두 갱신한다(Bg→Fg 때 기존 광고가 사라져도 괜찮다). 검색 UI에는 광고를 넣지 않는다. Mediation은 8월에 개발 검토만 하고 서비스는 나중에 한다.
  - SKP 광고 흐름은 [[air-skp-ad-scrums-2024]]에 있다.
- **NaviSDK 외부 대응**
  - 07-18 두리텍 단말에 설치할 NaviSDK 샘플 APK를 전달했다. 같은 샘플을 LG U+에도 줬다. CJ대한통운 건은 NaviSDK에서 문제가 되는 부분이 없다고 다시 확인했다.
  - 07-23 AIR-1381(tolltable)은 AIR에만 반영되어 있었다. 이번 패치 기간에 SDK에도 같게 반영하기로 했다.
  - 07-30 NaviSDK 소개 영상을 08-08까지 요청받아, AOS 영상 초안을 08-02에 주기로 했다.
  - 07-31 팀장 개발폰(S9)에서 샘플 SDK의 교통정보(CTT) On/Off가 동작하지 않았다. SDK 개발자 단말에서는 재현되지 않았다.
- **기타**
  - 07-08 Android Auto 연결 시에도 HUD를 지원한다(기존부터 지원).
  - 07-31 중국 HUD 업체용으로 경로 탐색 출발지를 회사 위치로 고정한 Release APK를 버전코드를 올려 다시 만들었다. 앞으로 큰 파일은 Slack 대신 NAS 공유 링크로 준다.
  - 07-29 서울 보행자 신호등: 개발서버 `trafficLightList` 응답 529건 중 서울 8건, 나머지는 대구였다. 테스트 영상은 음성이 녹음되지 않았고, iOS는 개발서버 모의주행이 안 됐다. 미래초교 앞은 무단횡단 데이터가 없어 가상 데이터 작업을 요청하기로 했다.
  - 07-26 ChatGPT 무료 평가판이 끝나 API 한도에 걸렸다. 비용 조사 문서를 만들었다. 07-30 테스트용 API 키가 채널에 공유됐다(미수록).

## 2024-08: Android 14와 SKP 1.10.1, 계획 재편

- **Android 14 크래시(08-07 분석)**
  - Firebase 로그와 탐색 경로 이벤트로 보면 모든 사용자가 초기 흐름에서 비정상 종료됐다. 위치 권한(`ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`)이 없어 `SecurityException`이 난다.
  - 권한을 빼며 테스트해서는 재현되지 않았고, 앱 실행 후 백그라운드로 보냈다가 포그라운드로 오면 재현된다. Android 14 while-in-use 제한(백그라운드에서 위치 유형 포그라운드 서비스를 만들면 `SecurityException`) 때문으로 봤다.
  - Firebase에서 같은 이벤트가 10건 이상 보였다. 해결 방안은 이 기간에 정리되지 않았다.
- **SKP**
  - 08-07 '광고 보고 캐시 받기' 동영상 피드가 Android 14에서 비정상 종료하던 문제를 `skpad-benefit` 1.7.4 → 1.10.1 업데이트로 해결했다.
  - 08-29 1.10.1에 POP 기능용 포그라운드 서비스가 들어 있어 `FOREGROUND_SERVICE_SPECIAL_USE` 선언을 요구받았다. AIR는 POP을 쓰지 않으므로 SKP 가이드대로 해당 권한을 Exclude하고 다시 빌드했다.
  - 08-28 광고 매체사가 APK 검수 중 연동 버전이 최신이 아니라며 V2.1.0.13 업데이트를 요청했다. 버전코드 301398 → 301399 Release 빌드로 전달했다.
- **포인트홈 캐시 전환**
  - 08-09 최신 라이브러리에서 사용자 프로필 API에 `UserKey` 파라미터가 생겼다. 채널링을 쓰지 않아 null을 넣으면 정상이다. iOS 가이드에서는 optional인데 Android는 반드시 넣어야 해서, 채널링이 없을 때 넣을 값을 업체에 확인하기로 했다.
  - 08-22 개발모드에서 '캐시 전환' 버튼은 생겼지만 눌러도 동작이 없었다(iOS도 같다). 아바티에 문의하고 테스트 포인트 적립을 요청했다. 테스트용 번호 인증 정보는 원본에 있음(미수록).
  - `/INaviAir/cashButton/cashConversion` 호출이 `result_code 630`(캐시버튼 연동 오류)을 돌려줬다.
    - basicToken은 앱이 "basic"을 붙여 보내고, Agent가 중복으로 붙이던 문제는 Agent에서 고쳤다.
    - 남은 원인은 exchangeItemID가 DB에 등록되지 않은 것으로 추정했고, 업체의 ItemID 회신을 기다렸다. 확인되면 서버도 고쳐야 한다. ^[inferred]
    - 팀장 요청에 따라 ItemID를 바꿀 때 기존 앱에 영향이 없도록 기존 DB에 추가하는 방식으로 요청하기로 했다.
- **CarPlay HUD**
  - 08-20 사업부 임원·팀장 차량에서 CarPlay HUD가 지원되는 것을 확인했다. 카카오내비는 실험실에서 기능을 켜지 않아 동작하지 않았던 것이다.
  - TestFlight 외부 테스터로 테스트 빌드를 배포했고(외부 심사 약 하루), 08-26 재배포했다. 테스터 메일 주소는 원본에 있음(미수록).
  - 08-28 iPhone 연구소 화면에서 CP HUD와 온에어 항목이 붙어 나오는 레이아웃 설정 오류를 확인해 고치기로 했다.
- **NaviSDK 고객 대응**
  - 08-09 LG U+ iOS SDK의 App Key 오류는 업체가 키를 잘못 입력한 것이었다. iOS SDK는 시뮬레이터를 공식 지원하지 않는다. DP 엔진이 OpenGL 2.0 기반이라 시뮬레이터에서 버벅인다. Android에는 시뮬레이터 모드 함수가 있다.
  - 08-27 SDK에서 목적지명은 사용자가 넣는다. 출발지명이 빈 문자열이면 현위치 역지오코딩 결과를 쓰고, 실패하면 "현위치"로 채운다.
  - 08-29 두리텍 개발자가 연동에 어려움을 겪어 샘플 소스를 전달했고, 외부 Slack에 두리텍 채널이 생겼다.
  - 08-16 CL모빌리티의 Flutter 지원 가능 여부와 일정 검토를 요청받았다.
- **기타 사실**
  - 교통정보 자동 재탐색 주기는 스마트 재탐색과 같은 5분이다.
  - 예외요금·하이패스 할인: 메일로 받은 계산 로직의 "하이패스 할인정보"는 할인 비율 계산용이었다. AOS에는 예외요금, 을숙도 등 자체 판단 조건이 있어 iOS 담당과 맞춘 뒤 고치기로 했다(메일 회신 대기).

## 2024-12: NaviSDK 2차 목표 달성, 포인트홈 1.3.1, 교통정보

- **NaviSDK 리뉴얼 진행**
  - 12-03 현황 리뷰: 1차(지도 띄우기, 엔진 로드)는 12-02 목표로 끝났다. 2차(경로선 세팅: Core 메인 데이터구조, 통합검색, 길찾기, DP)는 12-26 목표다. 3차(주행 데이터 연동, 모의주행, 안내, MMC, 요금, 거리)는 일정 미정이었다.
  - SDK 구조도 보완 항목: Navi Core HTTP 항목 구체화, iOS static lib(xcframework) 연동 구조도, 내부 파일 저장 방법 설명.
  - 12-26 회의: 2차 목표(검색, 길찾기, 경로선 세팅)를 끝냈다. 3차 목표는 1-23까지이고, 기존 NaviMainThread 역할을 세분화해 구조화(동시성 문제 확인, MMC·안내 data flow 정리), 구조도와 프로젝트 구조 정리(INaviController 역할), Compose UI 검토를 한다. 3차가 끝나면 기능 Feature를 구현할 준비가 된다.
  - 같은 회의에서 1월 중 TomTom 자료를 받아 준비하고, 고객사 확대에 대비해 서버(WAS, DB)를 분리하기로 했다.
  - Orbis Map NaviSDK 예상 일정: 2025년 2월 킥오프, 여름 POC, 가을 현지 테스트, 전략팀 목표는 2025년 3분기 이후(7~9월 준비 완료).
  - 12-04 TomTom에 Search API·MapDisplay SDK의 인증키, 개발 가이드, 개발 지원 방법을 요청하는 초안을 만들었다. 12-05 TomTom 신규 지도 소개서를 공유했다. 상세 내용은 [[orbis-sdk]]에 있다.
  - 기술 결정과 이슈:
    - 12-03 SDK 개발자가 KMP↔Swift 연동 라이브러리 SKIE를 소개했다. iOS 개발자는 SKIE 없이 Flow 호출에 성공했다.
    - KMP에서 gzip 디코딩을 할 수 없어 expect/actual 구조로 바꿨다. iOS 쪽 `decodeGzipToJstr` 구현이 필요했다.
    - 12-02 develop 병합 충돌로 일부 코드(`SGuidanceAdapter.ios.kt` 등)가 사라져 복구했다. core xcframework는 `./gradlew assemblenavisdkXCFramework`로 만든다.
    - 12-05 iosApp을 SwiftUI에서 UIKit AppDelegate 구조로 옮겼다(지도 표출 때문). 지도 표출은 initlayout을 먼저 해야 한다. NaviSDKIOS 프레임워크는 core에 넣기 위해 추가된 것이다.

    - 12-10 iOS 빌드 스크립트를 넣었다. core와 navisdk가 쓰는 xcframework는 불필요한 커밋을 막으려고 당분간 로컬에서 ignore하고, static lib는 완성되면 다시 git에 올린다.
    - 12-11 iOS MMC·DP 엔진 static lib 통합을 1차로 끝냈다. OS별 차이(iOS 미구현 항목, Android 전용 기능, 리턴 타입 불일치)를 CF에 정리하고 인터페이스 수정 여부를 내부 회의로 정하기로 했다.
    - 12-12 SDK Core에 추가된 외부 maven 저장소 때문에 빌드가 깨진 적이 있다. atl.xml 파싱용 XML 라이브러리라 당장 뺄 수 없고, 다시 문제가 되면 대체를 검토한다.
