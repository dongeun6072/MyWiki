### seoul-donghaeng (신규 10건, merge 6건 제외) → [[seoul-donghaengmap-app-commit-history-2026]]

`feature/app-indoor-sadang-vendor` 브랜치에서 작업했고 **PR #70**(사당역 실내 도면·역별 실내지도 테스트(사당·시청·판교) 및 서버 규격 1.0.64 저상 운행 nullable 대응, 25개 파일)으로 17:00에 develop에 병합했다. 릴리즈 브랜치 `release/v1.0.0-20261110-1852`에 들어갔다.

- **업체 테스트 APK 준비(10:11~10:12, `91e4e7ef`·`ded76d33`)**: 저상버스 예약 내역 Mock 6건을 지워 앱 시작 시 예약 목록이 비어 있게 했다. 디버그 오버레이를 기본 꺼짐으로 바꾸고 개발자 옵션의 스위치를 뺐으며, 실내지도 테스트의 역사 범위(Rect) 테두리를 없앴다.
- **실내지도 테스트를 역별 3항목으로 분리(13:17, `ce1dda66`)**: 개발자 옵션에서 사당역(측위 출발), 시청역(도면 신규, 1F 고정 출발점), 판교역(develop 도면 이관, 좌표 길찾기)을 따로 고른다. 시청역·판교역 실내 geojson 7종씩을 `indoor/cityhall`, `indoor/pangyo`에 넣었다.
- **파파야 테스트 앱 배포(13:20, `29871f7e`)**: 배포 기록용 빈 커밋.
- **판교역 테스트를 develop과 맞춤(14:10, `f7cd01b9`)**: 판교역은 파파야 POI 목록(GS25 포함)을 도착지로 쓰고 POI ID로 길찾기한다. 사당역·시청역은 도면 POI 좌표 길찾기를 유지한다.
- **시청역 고정 출발점 제거(15:35, `c01d8b2a`)**: 세 역 모두 측위 SDK 출발점(현위치)으로 길찾기한다.
- **서버 규격 1.0.64 대응(15:40, `b1ba11d4`)**: 저상 운행 여부(`lowFloorAvailableYn`)를 nullable로 받는다. null(정보 없음)은 「저상 운행 없음」으로 표시하지 않는다(`Transit`, `BusStopRoute`, `BusStopScreen`).
- **스크린리더 낭독 문구 TC(16:02, `797d57a8`)**: `docs/checklist/screen-reader-test-cases.md`에 화면별 613개와 공통 규칙 13개를 작성했다. 11-09 낭독 테스트 보고서의 후속이다.^[inferred]

### 서울동행맵 dev → [[seoul-donghaengmap-dev-slack-tech-2026]]

- **시청역 실내 도면 테스트 보고(12:45)**: 이동은이 파파야가 준 시청역 도면으로 테스트한 결과를 PM에게 알렸다. 출발점을 시청역 출구 좌표(1F, B1)와 B1 POI로 바꿔 가며 B1~B3 POI(개찰구·출입구·승강기·계단)를 도착지로 요청했지만 모두 40005(길찾기 TO 정보 찾기 실패 - 도보 이용 불가)였다. 사당역은 정상이고 실외 출발 탐색은 아직 안 됐다. 시청역 보행 경로 데이터가 길찾기에 반영되지 않은 것으로 보고 파파야 확인을 요청했다(요청 좌표 미수록).
- **파파야 테스트 APK(12:53~15:56)**: 3개 역(판교·사당·시청)을 모두 넣어야 하는지 물었고 PM은 가능하면 3곳, 어려우면 시청역만이라고 답했다. 15:56에 3곳을 고를 수 있는 Debug 빌드(VersionName 1.0.0, VersionCode 1)를 공유했다(다운로드 링크 미수록). 좌표 기준은 Fusion SDK 샘플앱과 같고(탐색 출발지 `currentDeparturePoint`, 안내 전 현위치 location, 안내 후 `MarkerPoint`), 시청역에는 플랫폼 POI가 없다. 공유 시점에는 사당역·시청역 실외 탐색이 정상 동작했다.
- **1층 승강기 POI 요청(16:58)**: 앱 리드가 시연 시나리오 구성 중 파파야 데이터에 시청역 진입 지점(지상 1층 출입구)의 승강기 POI가 없다고 알렸다(다른 역사도 같음). 플랫폼 정보 추가 요청 때 함께 요청한다.
- **서울시 제공 오픈 API(15:54)**: PM이 서울시 문서에 있는 제공 가능 오픈 API 목록을 공유하고 사용할 수 있는지 확인을 요청했다(목록은 첨부 이미지, 미수록). 앱 리드·이동은·서버 담당이 수신.

### 서울동행맵 파파야 → [[seoul-donghaengmap-papaya-slack-2026]]

- **시청역 도면 공유와 길찾기 실패(11:59~16:26)**: 파파야가 시청역 실내 도면을 공유했다(첨부 미수록). PM이 위 테스트 결과를 전달하자 파파야는 처음에 실외 연계 미구현으로 답했다가, 출입구부터의 길안내는 실내 영역이 맞다고 정정하고 길찾기 API에 시청역이 반영되지 않아 모두 실패한 것으로 확인했다. 16:26에 시청역을 길찾기 API에 반영했고 실외 to 실내·출입구 포함 길찾기 테스트도 마쳤다고 알렸다. 실외 연계 로직은 늦어도 다음 주까지 반영한다.
- **승강기 POI(17:05~19:31)**: 서울시 시연 시나리오가 승강기 이용 경로인데 지상 1층 승강기 출입구 POI가 없다. 사당역은 「엘리베이터」, 시청역은 「승강기」로 명칭이 달랐다. 파파야가 지상 출입구 누락분을 넣어 시청역 데이터를 다시 주기로 했고, 명칭 통일(파파야는 「엘리베이터」 제안)은 PM이 검토 뒤 회신한다.
- **Android 테스트 앱 전달(16:17)**: PM이 실내 내비게이션 부분만 검토해 달라며 테스트 앱을 파파야에 공유했다(링크 미수록).
- **신도림·잠실 데이터 일정 조정(17:56)**: 도면은 11-17(화) 그대로, 센서맵은 늦어도 11-20(금)까지 전달한다. 11-20 시청역 서울시 시연 준비가 추가됐기 때문이다.

### 서울동행맵 컨소시엄 → [[seoul-donghaengmap-consortium-slack-2026]]

- **설계 변경 회의 공유(16:52)**: PM이 11-09 아로정보기술·파파야와의 회의 내용을 LBS테크에 알렸다. 실내 내비게이션 길안내는 시청·사당·잠실·신도림 4곳으로 1차 진행하고(Android 대상), 나머지 서울시 전체 역사는 실내 지도와 경로 탐색 기준의 요약 정보 안내(Android·iOS 공통)를 찾는다. 서울시 중간보고는 11-20(금)로 제안한 상태이며(미확정) 시청역에서 실외 도보~역 내부 실내~실외를 고정된 출·도착지로 이어서 시연한다. 사전 점검은 11-17~11-18이다. 실외 도보 구간의 개발 변경점은 없다.
- **계단 회피와 필터(09:33~13:20)**: LBS테크가 `option`은 생략을 권장하고 계단 회피는 교통약자 유형(`userType`)으로만 정해진다고 답했다(WS·SP는 회피, LV·TB는 회피 안 함). 서버 담당이 사용자가 켜고 끄는 「계단 회피」 필터를 위해 LV·TB에서 `option=short`가 계단을 피하는지, 아니면 별도 파라미터를 받을 수 있는지 다시 물었다. 내부 논의 결과로 필터는 경로를 빼지 않고 조건에 맞는 경로를 위로 올리는 방식으로 정했고(역별 엘리베이터 정보 유무 값 추가 요청), 이름은 백엔드 번역 없이 역 식별값·한국어 역 이름·출구 번호·시설 종류 코드를 나눠 받아 앱에서 언어별 문장을 만들기로 했다.
- **지하철 실시간 도착 데이터(09:24~10:58)**: 브로디언이 ODsay는 실시간 정보를 지원하지 않는다고 확인했다. 서버 담당이 서울 열린데이터광장 「서울시 지하철 실시간 도착정보」(OA-12764)를 후보로 공유하고 필요한 값과 응답 필드(`btrainNo`, `updnLine`, `arvlCd`, `recptnDt`) 대응, ODsay 역·열차 매핑 가능 여부 검토를 요청했다. 버스(BMS)는 연동 일정이 없어 가능 시점에 작업한다.
- **출입구 처리 문의(14:18)**: 서버 담당이 경로 탐색(v110)에서 출입구가 여러 곳인 장소를 좌표 한 곳으로만 찾는지, `destName`·`destAddr`가 어떻게 동작하는지, 출입구 좌표를 여러 개 보내는 방식이 필요한지 LBS테크에 물었다. 담당자 출장으로 회신이 늦어진다.
