# 한국형 웹 콘텐츠 접근성 지침 2.2

웹 콘텐츠 접근성의 한국 표준(KS X OT0003:2022)이다. 2005년 제정 이후 개정을 거쳐 W3C WCAG 2.1(2018)을 바탕으로 하되 국내에서 반드시 지켜야 하는 필수 항목 위주로 구성했다. 「지능정보화기본법」, 「장애인차별금지법」상 웹 접근성 의무의 기준으로 쓴다. 콘텐츠 제작기법 문서(약 350쪽)는 각 검사항목별 구현·점검 예시를 담은 해설서다.

## 1. 구조: 4원칙, 14지침, 33검사항목

| 원칙 | 지침과 검사항목 |
|---|---|
| 인식의 용이성 | 5.1 대체 텍스트(5.1.1 적절한 대체 텍스트), 5.2 멀티미디어 대체수단(5.2.1 자막), 5.3 적응성(표 구성, 선형 구조, 명확한 지시사항), 5.4 명료성(색에 무관한 인식, 자동 재생 금지, **텍스트 명도 대비 4.5:1**, 콘텐츠 간 구분) |
| 운용의 용이성 | 6.1 입력장치(키보드 사용 보장, 초점 이동과 표시, 조작 가능, 문자 단축키), 6.2 충분한 시간(응답시간 조절, 정지 기능), 6.3 광과민성 발작(3~50회/초 깜빡임 제한), 6.4 내비게이션(반복 영역 건너뛰기, 제목, 링크 텍스트, 고정 참조 위치), 6.5 입력 방식(아래 신규 4항목) |
| 이해의 용이성 | 7.1 가독성(기본 언어 표시), 7.2 예측 가능성(사용자 요구에 따른 실행, 찾기 쉬운 도움 정보), 7.3 입력 도움(오류 정정, 레이블 제공, 접근 가능한 인증, 반복 입력 정보) |
| 견고성 | 8.1 문법 준수(마크업 오류 방지), 8.2 웹 애플리케이션 접근성 준수 |

모바일 앱 지침의 명도 대비(UI 컴포넌트와 텍스트 3:1)와 달리 웹은 **텍스트 4.5:1**이다. 두 기준을 섞어 쓰지 않도록 대상(웹 콘텐츠, 앱)을 먼저 구분한다. ^[inferred]

## 2. 2.2에서 눈에 띄는 항목 (모바일·터치 환경과 관련)

- **6.5.1 단일 포인터 입력 지원**: 핀치 줌, 스와이프, 끌어놓기 같은 다중 포인터·경로 기반 동작은 한 번 누르기로도 할 수 있어야 한다(서명처럼 필수인 경우 예외).
- **6.5.2 포인터 입력 취소**: 단일 포인터로 실행되는 기능은 취소할 수 있어야 한다.
- **6.5.3 레이블과 네임**: 화면에 보이는 레이블 텍스트가 접근성 이름에 포함돼야 한다(음성 제어 사용자 대응).
- **6.5.4 동작기반 작동**: 기기 흔들기 같은 동작으로 작동하는 기능은 UI 컴포넌트로도 조작 가능해야 한다.
- **7.3.3 접근 가능한 인증**: 인증 과정이 인지 기능 테스트(기억, 퍼즐)에만 의존하면 안 된다.
- **7.3.4 반복 입력 정보**: 같은 정보를 다시 입력하게 하지 말고 자동 입력 또는 선택 입력을 제공한다.
- 6.1.4 문자 단축키는 오동작 방지 장치(끄기, 재설정)를 둔다.

## 3. 서울동행맵 적용 메모

- 앱 자체는 [[korean-mobile-app-accessibility-guidelines]]가 기준이다. KWCAG는 **웹뷰로 띄우는 화면, 관리자·운영용 웹, 안내 페이지**에 적용되는 기준으로 보는 것이 맞다. 어느 화면이 웹으로 구현되는지는 이 문서로 알 수 없다. ^[ambiguous]
- 공공 UI 컴포넌트와 패턴은 [[digital-government-uiux-guideline]]에서, 심사 체계는 [[korean-public-mobile-app-compliance]]의 접근성 품질인증에서 이어진다.
