# Slack #01_inavi_air 대화 (2026 1~10월)

아이나비 에어 x Auto x CarPlay 비공개 채널(2022-07 개설)의 2026년 1월~10월 기록이다. 프로젝트 개요는 [[inavi-air]], 같은 해 운영은 [[air-operations-2026]], 앱 버전 노트는 [[air-app-version-notes-2026]], 개발자 채널은 [[air-nsdk-dev-slack-2026]]을 본다.

이 기간 채널 메시지는 104건(최상위 메시지 기준)이고, 답글이 달린 스레드 47개를 모두 열어 읽었다. 메시지의 약 절반은 배포 알림 봇이다. 사람 이름은 쓰지 않고 역할로 적었다. 키·계정·서버 주소·링크는 원본에 있으나 미수록이다.

## 2. 안내엔진 (안전운행 데이터·카메라)

- **구간단속 안내 지속 이슈(03-24 ~ 04-23)**: 고객 제보로 강남순환 구간의 10km 이상 구간단속이 끝났는데도 안내가 계속 표시됐다. 원인은 종료 카메라를 지난 뒤 맵매칭이 오프로드가 아닌 상태에서 안내가 끝나지 않는 현상이었고, 04-23 엔진 전달본(GPS·MMC 복구 후에도 지나온 구간단속이 계속 안내되는 문제 개선)이 03.05.61에 반영됐다. 제보 GPS 로그에는 GPS 값이 없는 위치를 순간이동으로 건너뛰어 속도가 높게 계산된 구간이 있었으나, 실제 필드에서는 가상주행으로 표시되어 같은 증상은 없다는 분석이 있었다.
- **경로 없을 때 카메라 거리 불일치(05-07)**: 경로가 없을 때 카메라 거리가 사양과 다르게 안내되는 문제를 수정한 엔진을 전달해, 핫패치 전제로 해당 엔진만 적용해 테스트했고 카메라가 정상 표출됨을 확인했다.
- **후면 카메라 요청(05-06)**: 후면 과속 카메라가 늘었는데 통과음이 발성되지 않고, 타 내비처럼 통과 후 50~80m 동안 안내와 심볼을 유지해 달라는 요청이 있었다. 09-10 엔진에 80m 유지 기능으로 반영됐다.
- **안전운행 데이터 일원화(09-10)**: 안전운행 데이터를 기존 `AIR.zip`에서 `Ssangyong.zip`(AIR 외 모든 안내엔진이 쓰는 데이터)으로 통일했다. 요지는 다음과 같다.
  - 신규 데이터 11종: 신호과속 구간단속 시작·종료, 후면 구간단속 시작·종료, 후면 신호과속 구간단속 시작·종료, 후면박스, 갓길 단속, 적재불량 단속, 램프미터링 구간, 꼬리물기 단속.
  - 방향 flag(0 없음, 1 후면, 2 양방향)와 구간 flag(0 없음, 1 신호) 신규 필드. Android `JCamInfo`와 iOS `iCamInfo`에 추가. 종별은 기존 1, 2, 11, 12, 15 유지.
  - 종별 31~34 추가(갓길, 적재불량, 램프미터링, 꼬리물기). 설정 기본값 false, `SetCamInfoOpt` 비트 21~24 추가, 음성 인덱스 396~399 추가. 갓길은 발성하지 않고 나머지는 500m에서만 발성한다. 신규 4종은 AI 음성 안내와 터널 VVMS 대상에서 제외된다.
  - 후면 카메라(방향 flag 1이고 종별 1, 2, 12, 15)는 통과 후 80m까지 `GetCamInfo`가 계속 반환하며 거리는 0으로 전달한다.
  - 서버에 `Ssangyong.zip`이 반영되면 엔진을 갱신하지 않은 구버전 단말은 후면 카메라를 정방향 카메라로 안내한다(구 엔진이 flag를 읽지 못함). 따라서 서버 반영은 앱 출시 일정에 맞춰 협의가 필요했다.
  - 앱 측은 기존 후면 종별 설정 비트를 안 쓰게 되어 제거해도 되는지 엔진 담당과 논의했다. 설정 코드는 이전 추가 이력을 참고해 맞추기로 했다.
- **상용 반영 일정(10-07 이후 17개 답글)**: 앱을 늦어도 15일 전후로 출시하려는 목표와 서버 반영을 맞췄다. 검수(QA) 서버 테스트는 AIR는 담당자 테스트만 하는 것으로 정리했다. 스토어 게시 전까지 상용 서버는 `AIR.zip`을 유지하고, 게시 당일 `CameraGuidePoint.zip`을 버전업해 재발행(예 T14 -> T15)해 검수와 상용 모두에 적용하기로 했다. 당시 iOS는 검증 완료, Android는 검증 중이었다.

## 3. 탐색(경로) API와 서버 협업

- **oil 필드 정의 불일치(06-08)**: 앱은 휘발유 0, 고급휘발유 1, 경유 2, LPG 3, 전기 4로 보내는데 규격서는 0=ALL로 달라, 서버 담당자가 앱 기준으로 규격서를 현행화했다.
- **친환경 경로·수소 유종(9월 패치)**:
  - 탐색엔진 프로토콜 v2.2.11에 차량 연료 종류가 추가됐다. 앱이 이미 보내던 `oil` 값을 탐색엔진으로 전달하고, 수소(5)는 서버에 선반영됐다.
  - 친환경 옵션은 `/findMultiRoute` `searchOptions`에 `recommendation_eco`를 추가하는 방식이다. 응답 routeList의 친환경 항목에만 탄소배출량·연료소비량 필드(소수 4자리)가 추가된다. 재탐색(`/findRouteAgain`)은 `searchOptionOrg`에 같은 값을 넣는다.
  - 고도정보 탐색 Type(일반/정밀/고정밀)은 UI/UX 확정과 고도화 시점에 정해질 것이라 당분간 서버 프로퍼티로 제어하고 기본값은 정밀(2)이다.
  - 로그 API: 사용자 이벤트의 routeopt와 `/saveConfig`의 `defaultRouteOption`, 에어연구소 로그 업로드 API에도 친환경 규격이 필요했다. `saveConfig`는 oil_type 수소 5, 친환경 추천 경로 옵션 6, 사용자 이벤트 routeopt는 SGECO로 합의했다.
  - 에어연구소 로그 업로드 API는 상용·개발에 배포가 안 돼 있어 404가 났다. 조사 결과 2025년 LogAPI 신규 규격 작업 전체가 master에 병합되지 않은 채 특정 브랜치에만 남아 있었고, 이후 서버 작업이 master 직접 반영으로 바뀌면서 개발 서버에서도 빠졌다. 선행 LogAPI 상용에 2025년 규격이 반영됐는지는 확인이 필요하다 ^[ambiguous].
  - 앱 측 일정: 앱 발행은 9월 말 목표이고, 서버 상용 반영은 명절 이후 9/28~29로 잡혔다.
  - 디자인 리소스: 튜토리얼 유종 선택 화면에 수소 아이콘, 경로 기본옵션 화면에 친환경 옵션 버튼·예시 이미지가 추가됐다. Android는 xhdpi(160x160)만 사용한다.
- **커스텀 경로 반영 탐색(08-28)**: `/findMultiRoute`의 headerType 5(경유도로)와 별개 기능이다. 커스텀 경로열 포함 탐색은 headerType 10이며 지도버전과 도엽별 Node/Link ID 리스트를 쓰고, 현재는 특정 SDK 패키지 5종 요청에서만 동작한다. 테스트에서 엔진 응답 플래그가 0이라 일반 탐색으로 빠졌고, mapType은 Link ID일 때 1이어야 하며 mapVer은 YYYYMMDD 8자리여야 한다는 점을 교정했다. 출발지·목적지 링크는 리스트에서 제외해야 한다(포함 시 에러 35). 교정 후 플래그 1이 확인됐고, 탐색엔진 쪽 최종 확인을 공개 채널에서 요청하기로 했다. 고객사 요구는 보유한 경로 좌표를 SDK에 전달해 지정 경로로 주행하면서 속도제한·회전 안내 등을 유지하는 것이다.
- **재탐색 remainTime/remainDistance(05-20)**: 앱/SDK가 주행 탐색 기준으로 내부에서 남은 시간·거리를 계산해 전달한다.
- **CCTV C3000(07-15)**: `routeOtherInfo`의 `cctvOn`이 true면 에이전트가 내부적으로 C3000 카테고리로 검색엔진에 요청해 CCTV 데이터를 재가공해 반환한다.
- **개발서버 접속 실패(04-06)**: iOS에서 개발서버 접속 시 로딩 실패가 났으나 AOS는 정상이었고, 개발서버에 발행한 지도버전 2605a 문제로 추정됐다. ^[inferred]
- **상용서버 점검**: 06-25 행정코드 패치 후 `ReverseGeocoding` 응답이 옛 행정구역을 내려준다는 문의가 있었다. 해당 API는 에이전트가 다른 검색엔진으로 요청한 값을 그대로 전달(bypass)하고, 단축 행정계 요청 시 도로명 주소도 단축형이 되어야 하는지 논의했다. 개발·상용 응답이 달랐다.

## 4. 주소·행정구역 개편 (전남광주통합특별시)

- 01-19 삼성중공업 건에서 탐색 제한구역 데이터의 `limitFntm` 값이 시 2자리만 들어와 날짜 변환 오류가 났다. 서버 담당자가 `2300`으로 수동 변환해 정상화했고 재발 가능성이 높아 시스템 개선이 필요하다고 보고했다. 시작 시각 `limitSttm`은 시·분 4자리였다.
- 07-13: 서버가 내려주는 축약형이 "광주특별시"인데 "전남광주"로 표현할지 확인을 요청했다. 축약어는 "전남광주", 풀네임은 "전남광주통합특별시"로 협의됐고, 검색 서버에서 내려주는 방식이 적절하다고 봤다.
- 06-11 Play 검증 스레드: 스텝형 주소 검색 순서(서울 다음 전남광주, 세종 다음 경기도, 특별자치도 하단)는 `하위행정계` API 응답과 `admcode` 기준 정렬 결과라 순서를 바꾸려면 검색 쪽 협의가 필요하다고 정리했다.
- 02-13: 4월 지도 오픈일을 4월 1일(수)로 진행하는 것으로 확정했다(운영 업무가 기존 담당자에서 인수인계된 상태).

## 5. 고속도로 목적지 안내 팝업 (고객 VoC)

- 기획자가 제기한 항목: 고속도로 위 경로 탐색 시 TG(톨게이트), 휴게소 검색에는 팝업이 없는 것이 의도인지, 고가도로·지하차도에서도 되는지.
- 답: IC, JC, 분기점, TG, 톨게이트, 휴게소(카테고리 코드 일부 제외)는 사용자가 직접 검색해야 하는 상황이라 팝업이 예외다. 이번에 고가도로·지하차도까지 추가됐다.
- 통합검색 후 안내 시작에서 고속도로인데도 탐색이 진행된 사례는 최근 목적지 자동완성으로 탐색했기 때문이었다(최근 목적지·즐겨찾기 등 탐색 이력이 있는 장소는 팝업 미표출). 최초 1회 MR 수신 전에는 고속도로 여부 판단이 안 돼 팝업이 안 뜬다.
- 개선: 기존 Projection 체크는 유지하고, 실패 시에만 탐색 완료 후 1회 재체크해 팝업으로 변경 여부를 받는다. MR 다운로드는 경로 탐색 시간을 활용해 비동기 확보했다. 근본 해결은 아니고 1차 개발이며 다음 패치에서 반영하기로 했다. ^[inferred]
- 10-12 다음 에어 업데이트 후보 VoC: 과속 알림 제한 속도 설정(5km/h, 10km/h 등), 가로모드·Android Auto·CarPlay FoV 값 조정 등.

- **네이티브 크래시(03-09)**: 삼성전자에서 접수된 `libairmaps.so`의 SIGTRAP 크래시는 업데이트 안내 팝업에서 업데이트 버튼을 연타해 앱이 종료될 때 초기 다운로드 중 앱 종료로 발생한 double free로 추정됐다. 수정은 mapbox 제거 버전에 함께 내기로 했다. 같은 스택에서 `AirMaps.destroy()` 내부 블로킹 및 ANR 관련 로그도 있었다. ^[ambiguous]
- **Android Auto 3D 핀치줌(05-07)**: 24MM 14" 단말에서 경로가 있으면 뷰모드와 상관없이 핀치줌 감도가 떨어졌고, 경로 제거 시 정상이었다. 구 엔진 v1.2.0에서도 재현됐다. 원인은 렌더 호출 간격 사이 이벤트 스레드에서 대량 입력이 쌓이며 scale 값이 제대로 갱신되지 않는 구조로 보고, 인터페이스 함수에서 scale을 누적한 뒤 렌더 함수가 반영하도록 수정해 6월 배포 버전에 반영하기로 했다.
- **CarPlay 발열·배터리(08-03)**: 렌더링 로직 개선(60fps) 이후 2~30분 주행에도 발열과 배터리 소모가 심했고, CarPlay 연결 시 두 화면 모두 30fps로 제한이 적절하며 차기 버전에서 속도별 FPS 조정을 검토하기로 했다.
- **Toyota 단말 CarPlay 미러링(09-17)**: 미러링 화면에서 다른 화면으로 전환하면 지도 렌더링이 멈췄다. 백그라운드 진입 시 `setVisible(false)`를 호출하지 않고 렌더링을 유지하는 방안은 CarPlay 두 화면 동시 렌더링으로 발열·배터리 문제가 재현될 수 있고 그래픽 컨텍스트 무효화로 오류 로그가 쌓여 전면 적용을 권장하지 않았다. 대시보드·메인 화면이 미러링되는지 상태를 전달받을 수 있으면 조건부 유지를 검토할 수 있다. 지도 레벨 상한은 CarPlay 메인 지도 10~12, 클러스터·대시보드 10~13이다. 경로 생성 시 지도 레벨이 13, 14로 바뀌어 과도하게 확대되는 문제는 엔진 dpi 조정으로 일부 개선했으나 근본은 레벨 변경 때문으로 보였다. 제조사 구분은 iAP2 accessory 정보 확인 여부를 검토 중이었다.
- 04-13 내부 배포 빌드는 "DP 엔진 성능 개선 버전의 전 단말 확대"와 w3w 호출량 최소화를 먼저 테스트하기 위한 것이었고, 기획자는 제스처 사용성이 개선되었으나 지도 이동 드래그 끊김은 타 앱보다 남아 있다고 평가했다.

## 8. w3w(what3words) 스펙아웃

- 04-13: 4월 패치에서 w3w 호출량을 줄이기로 했다. 에이전트 연동 지점은 통합검색과 RGC(역지오코딩)이고, 에이전트 API로는 Sire 쪽 `/sire/revgeocoding`, `/sire/searchPoiDetail`(w3wYn 파라미터), `/w3w/autoSuggest`, `/w3w/wordSearch`가 확인됐다. w3wYn은 앱이 Scene별로 활성화하며 서버에서 세부 제어는 어려워 앱 우선 검토, 앱 패치로 결정했다. (원본에 API 키가 있으나 미수록)
- 04-23: 이번 패치에서 w3w 자체를 제거하는 것으로 정리됐고 통합검색에서도 제거가 필요하다고 공지했다.
- 05-06: w3w는 기능이 spec out되었고 계약도 종료됐다. 최신 앱은 w3w 예외 처리가 들어가 호출이 없을 것이나 구버전 호출 이력은 있을 수 있다. 에이전트에서 호출을 제거하고, 호출이 오면 통합검색으로 연결하거나 "검색결과 없음"으로 처리하도록 요청했다. 계약 종료·비용 절감이 목적이었으나 다른 서비스에서도 w3w를 쓰는 이유로 한때 AIR 스펙아웃은 홀딩이었다는 설명도 있어 최종 상태는 위 05-06 공지를 따른다. ^[ambiguous]
