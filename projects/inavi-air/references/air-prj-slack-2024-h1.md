# Slack #10_prj-inaviair 대화 (2024 상반기)

아이나비 에어 프로젝트 공개 채널 `#10_prj-inaviair`의 2024-01-02~2024-06-18 기록이다. 프로젝트 개요는 [[inavi-air]], 같은 시기 비공개 채널은 [[air-channel-slack-2024-h1]], SKP 광고 스크럼은 [[air-skp-ad-scrums-2024]], HUD 출시 안정화는 [[air-hud-launch-stabilization-scrums-2024]], 앱 버전 정리는 [[air-app-version-notes-2024]]를 본다.

이 기간(2024-01-01~06-30) 채널 최상위 메시지 91건(입장 알림 포함)을 읽었고, 답글이 달린 스레드 53개의 답글 368건을 모두 열어 읽었다. 첫 메시지는 2024-01-02 13:42, 마지막 메시지는 2024-06-18 11:54(KST)다. 사람 이름은 역할로 바꿔 적었고 서버 호스트, 링크, 연락처는 옮기지 않았다.

## 1. 2024-01

- **01-02 기본 음성 교체 테스트**: 기획 담당이 아이나비 에어 기본 음성 교체를 위해 테스트를 요청했다. "발랄한 음성"과 "차분한 음성"이 새 성우 음성으로 추가됐으나 발성이 아직 부자연스러운 부분이 있어, 신규 음성을 넣은 APK(AOS 전용)를 공유하고 의견 시트에 의견을 받기로 했다. 설정 경로는 환경설정 > 안내설정 > 길안내 음성이고, 발랄한/차분한이 신규, "아이나비 클래식"이 기존 음성이다.
- **01-03 로딩 문구 개선 요청**: 공지사항/이벤트에서 이미지가 있는 콘텐츠는 "서버와의 통신이 원활하지 않다"는 메시지 위에서 로딩이 도는데, 불안정해 보이므로 "잠시만 기다려주세요" 같은 문구나 다른 화면으로 대체해 달라는 요청(사업팀).
- **01-04 쿠폰 통계 요청**: 1/5 기준으로 기존 발급한 5만 개(1,000C)와 20만 개(500C) 쿠폰의 등록 유효기간이 종료된다. 1/6에 1,000C와 500C를 나눠 최종 통계를 요청했다. 항목은 쿠폰 발급자수(50,000 / 200,000), 사용자수, 사용자 중 신규/기존 에어 고객수, 신규 유입 비율이다. 지급량별 피드백을 확인하고 현재 이벤트와 비교하려는 목적이다.
- **01-09 도로명주소 "지하" 대응 안내(검색엔진 담당)**: 도로명 건물번호에 "지하" 명칭이 추가됨에 따라(예: 신반포로 200 -> 신반포로 지하 200) 검색엔진 입출력에서 "지하"를 쓸 수 있게 한다. 건물번호가 쓰이는 모든 API의 입출력에 반영되고, 구주소 '산' 지번과 유사하게 건물번호 위치에서 동작한다. 도로명/건물번호를 따로 입출력하는 경우 도로명은 변경 없고 건물번호만 "지하 200"이 된다. 특이사항이 없으면 1/18(목) 검색엔진에 반영한다. 스레드에서 에어 스텝형 주소검색에 "지하" 입력 방법이 필요하다는 요청이 나왔고, 개발 검색엔진 서버에는 수정 버전이 적용되어 테스트 가능하다고 답했다. 에어 개발 측은 급한 건인지 일정을 되물었고, 사업 측은 기능적으로 동작하는 부분이니 정기 패치 일정에 맞춰 적용하면 된다고 정리했다(산 지번 검색처럼 [지하] 입력 기능 기획 검토, 기획안 기준으로 다른 서비스 확대 적용 내부 논의).
- **01-12 입장 알림**: 신규 멤버 1명 참여.
- **01-15 설 이벤트 기획 의견 요청**: 2024년 설 이벤트로 (1) 에어캐시 무제한 적립, (2) 스탬프 2배(1회 -> 2회) 지급을 구상(2/8~12 5일, 발렌타인데이 14일까지 7일 연장도 고려). 10월 이후 이벤트가 없었던 점을 리텐션 관점에서 기획했다. 스레드: 서버 담당은 무제한 적립은 문제없으나 "스탬프 2배"의 의미(스탬프 flow 확인 필요)를 물었고, 스탬프 2배 이벤트는 이력이 없으며 이전 이벤트는 룰렛 2회였고 지난 이벤트는 1+2회로 총 3회였다고 정리됐다. 사업 측 설명은 무제한 적립은 설 연휴 기간만, 룰렛 2회는 2월 한 달간, 이미지도 2건으로 분리 제작 예정이다. 사업 측은 "생각을 잘못한 부분이 있어 최종 공지를 다시 드리겠다"고 했다. 이후 2월 설 이벤트 안(PDF)이 공유됐다: 2/8~12(5일) 무제한 적립 이벤트만 진행하고, 지난해 설 이미지처럼 띠(용) 이미지를 배경에 삽입. 배너용/공지사항 이미지를 목요일까지 요청. 2/8에 공지사항 이미지·배너 업로드가 완료됐고 서버 확인 결과 이상 없음, 당일 10:50경 116포인트를 지급받은 로그 이미지가 공유됐다. 2/7 사업 측이 1일차 모니터링을 요청했고(50캐시 이상 적립이 이상 없이 진행되는지만 확인하면 됨), 서버 측은 2/8 특이사항 없음으로 답했다.
- **01-16 1월 업데이트 일정 문의**: 사업 측이 레터에 활용하기 위해 1월 에어 업데이트 일자를 문의. HUD 일정을 확인해야 하고 HUD 일정이 밀리면 빼고 진행하므로 2월로 미뤄지지는 않을 예정(HUD 서비스 단말 정리는 HUD 담당이 다음 주 업체 미팅 후 공유). 1월 패치는 안정화 패치라 HUD 외에 레터에 들어갈 콘텐츠가 특별히 없다. 마케팅 담당은 월간 레터에 콘텐츠화 가능한 업데이트만 사전 공유해 달라고 요청했고, 1월 레터 발행은 25일 예정, 설명절 프로모션 콘텐츠는 레터 발행 하루 전(수요일)까지 제작 가능한지 조율했다. 사업 측은 23년 에어 블로그 마케팅 자료를 마케팅 담당에게 전달했다(2개 업체: 블로그 인플루언서 콘텐츠(앱테크 키워드), 블로그 리뷰는 작년 1·5·11월 3차례).
- **01-18 쇼핑하기 판매 수량 공유**: 지난해 6월~1/17까지 기간별 상품 판매 수량 데이터(PDF). 작년 신규 추가한 BBQ 치킨+콜라 세트와 올리브영 기프트 카드가 예상보다 많이 팔렸고, 치킨 판매금액 2만원대에도 수량이 높아 3만원대 상품 추가도 고려. 스레드: 높은 가격대 상품은 할인도 적용되지만 에어캐시를 5천~1만 원 이하에서 빨리 소진하지 않고 모으는 효과도 있다. BBQ 실제 매장 판매가는 22,500원, 공급가는 5% 할인 가격이고 BBQ 쿠폰 1개당 1,375원의 지출이 발생한다(공급가가 더 비싸 보이는 이유 문의에 대한 설명).
- **01-19 상품등록 가이드 / 푸시 지연**: 서버 담당이 "아이나비에어 상품등록 가이드_240119"를 사업 측에 전달. 같은 날 14:29 푸시 발송 시간 지연이 보고됐고, 서버 담당은 Air Agent 서버가 푸시에 Google Firebase FCM을 쓰는데 FCM 내부 지연으로 확인됐으며 동일 현상이 반복되면 횟수 제한 등의 조치가 필요하다고 답했다.
- **01-22 시장 기사 공유**: 2023년 티맵 검색 키워드 기사(1인당 검색 빈도 1위 '맛집', 최다 검색 장소 스타벅스, 주유소 2위, 다이소 3위로 전년 대비 검색량 20% 증가 등). 숙박예약 서비스 사용률이 출시 후 매월 평균 3배 이상 증가한다는 내용 포함.
- **01-30 로그 API 이상 / 1월 안정화 패치 일정**: 로그 담당이 LogAPI 입력 이상을 확인하고 당일 Agent 작업과 관련 있는지 문의. 서버 측: 에어 상용 패치 중 문제가 있어 원복했고, 15:06~15:25(원복 시점)에 영향이 있었다. 원인은 대량의 주행 로그 파일을 문자열로 변환하는 과정에서 서버 자원과 성능에 부담을 줘 병목이 발생한 것이며, 해당 코드는 파일 데이터 로깅 목적으로 작성한 것이라 삭제했고 재발 가능성 없음. 1월 안정화 패치 일정: 2/2 서비스 목표(스토어 검증에 따라 2/5로 변경 가능), AOS 03.05.35 / iOS 03.05.14. 수정내역은 상품관리 체계 변경(Admin 적용, 할인 기능 적용), 스텝형 주소검색 "지하" 추가, 앱 안정성 개선. HUD 정식 서비스는 3월로 일정 변경. 스레드: 2/2 검증 완료, 오후 서비스 출시 예정, 주말 앱 모니터링, 공지사항/선택업데이트는 2/6(화)경 요청. 사업 측은 설 연휴 전이라 신중하게 다음 주에 진행하겠다고 했고, 출시 후 "공지사항/선택업데이트" 요청, 선택 업데이트 팝업 등록 완료.

## 2. 2024-02

- **02-02 푸시 예약발송 이슈**: 에어 푸시 예약발송이 막혀 iOS 푸시는 삭제했고 AOS가 13:30부터라 즉시 발송 전환 여부 판단이 필요했다(사업 측). 푸시 담당이 확인 후 원인을 설명: 기존 HTTP 푸시 기능 지원 중단으로 HTTP V1 푸시로 마이그레이션되면서 멀티캐스팅 기능이 제거되어 단건마다 푸시를 요청하는 방식으로 바뀌었고, 소요 시간이 늘어 이전 작업이 끝나지 않으면 예약된 푸시가 밀린다. 기존 HTTP 푸시 기능은 2024-06까지 유효하므로, 현재 발송 중인 예약 푸시 완료 후 다음 예약부터 이전 방식으로 원복했다. 3회차 1만 건이 10시반부터 막혀 있었고 강제 종료가 불가해 선택 종료했다. 13:30 예약 푸시 정상 발송 확인, 2회차 발송 완료, AOS 전체 발송 완료. 사업 측은 차주 설 연휴 전 1회 추가 발송 예정이고, 2/8 전체 푸시(iOS 오전 / AOS 오후)를 사전 공유했다.
- **02-05 2월 지도 상용 오픈 장애**: 11시경 지도 오픈 후부터 에어/하이브리드 내비 탐색엔진 연동 시 타임아웃 에러가 발생해 가오픈 원복 조치했다(11시 오픈, 11:15 가오픈 상태로 원복, 2월 지도 상용 10:59 오픈). 알람은 간헐적이나 원복 이전 지도를 받은 사용자가 탐색하면 같은 이슈가 날 수 있어 지속 모니터링 필요. 원복 후 앱 재실행 시 탐색 요청은 모두 성공. 탐색 엔진 담당이 원인을 확인(15:51): 
  - RC: WhereMXI에서 '추천'과 '요약' 옵션을 동시에 요청하는 케이스가 신규 발생해 이를 수정하던 중, '추천' 옵션만 적용돼야 하는 곳에 '최소시간' 옵션도 같이 적용되도록 잘못 수정됐고, 해당 코드에서 미정의된 '최소시간' 옵션 처리 중 미할당 메모리 접근으로 엔진이 죽었다.
  - CA: '추천'과 '최소시간' 옵션이 기존처럼 서로 다른 루틴으로 처리되도록 수정. 2월 가오픈 서버에 적용 및 테스트 완료, 금일 릴리즈 여부 판단 요청.
  - 개발 서버 테스트에서 왜 발견되지 않았는지 물었고, 해당 케이스가 where 타깃에 별도 옵션을 주는 부분이라 에어 탐색 테스트 케이스에서 누락됐으며 앞으로 포함하겠다고 답했다.
  - 2/5 14:33 에어 총괄은 교통정보 서버를 원복하고(2401a 지도로 원복 완료), 상용은 가오픈 상태를 유지하며 원인 해결 후 개발 서버 -> 상용 서버 일정을 다시 잡겠다고 지시했다. 이후 장애대응 프로세스(공식화된 것)를 숙지하고 따르며 장애보고서도 작성하도록 했다.
  - 2/6 11:24 에어/하이브리드 상용 2월 지도 가오픈 -> 오픈 작업을 13:30에 재진행한다고 공지(교통정보 생성/전송 서버 업데이트 요청). 재오픈 완료, 탐색엔진 모니터링 요청. "하소록교" 탐색 시 탐색불가 이슈가 있었으나 해당 구간 통제를 재적용해 해결.
