# 아이나비에어 DP(지도 스타일) 고도화 1차 테스트 리뷰 (2022-07)

GIS 팀과 협업해 에어 지도 스타일을 개선하는 작업의 1차 테스트 데이터 리뷰 결과다(2022-07-07). 테스트 버전과 현재 서비스 버전의 **모의주행 비교 영상**도 공유됐다. 앱 전체는 [[inavi-air]], 앱 기능 이력은 [[inavi-air-feature-history]]다. 참석자 이름은 적지 않았다.

| # | 항목 | 내용 | 결정 |
|---|---|---|---|
| 1 | 상·중위 레벨 도로 레이어 | 2~7레벨 도로 스타일 개선 필요. 이 레벨에는 외곽선 레이어가 없어 outline 색만으로 외곽선 효과를 낼 수 있는지 문의 | **하위 레벨 도로 스타일에 맞춰 최상위 레벨까지** 스타일을 개선한 테스트 데이터 제작. 도로 형상은 스타일 변경 결과를 보고 수정 여부 결정 |
| 2 | 지하철 노선 시인성 | 일부 노선이 지나치게 도드라짐 | 튀는 노선만(예: 신분당선) 스타일 조정 |
| 3 | 건물 주기 연계성 | 기존보다 건물을 더 많이 표출 | **14레벨(최하위 레벨)에 표출되는 주기**를 기준으로 건물 표출 대상 결정 |
| 4 | 공원 레이어 | 스타일 개선 | 주변 지도 이미지에 맞춰 매끄럽게 수정 |
| 5 | **오르다(ORDA) 레이어 신규** | 등산로 데이터 추가. 등산로 입구(들머리) 주기 레이어와 심볼을 추가해 에어로 검색·안내 가능하게 | 지도 데이터 팀이 데이터를 모두 보유. 등산로(배경)와 들머리(주기) 적용해 테스트 데이터 제작 |
| 6 | 주기 폰트 | **두 줄 주기**와 글자 크기 축소 | 두 줄 주기는 데이터와 DP 엔진 모듈을 발행해 임시 테스트 앱을 만들 수 있지만 실제 데이터 유입 방식 파악이 필요. 다른 업무(NDS)가 끝나면 가능하고, **7월 15일까지 멀티라인 표출 현황을 공유**. 글자 크기 축소는 여러 번 테스트가 필요해 크리티컬 이슈가 없으면 7월 말 이후 |

## 해석

- 에어 앱의 지도는 **DP 엔진 + 지도 데이터(스타일, 주기 레이어)** 구조이고, 스타일 개선은 앱 코드가 아니라 지도 데이터를 새로 만들어 검증하는 흐름이다. ^[inferred]
- 오르다의 등산로 레이어는 에어 지도 데이터와 공유된다. ([[inavi-2022-new-services]]) 서버 API 쪽에도 `/orda/stamp`(가까운 스탬프 조회)가 있다. ([[inavi-air-api-detail-spec]])

## GIS 팀 1차 테스트 데이터 리뷰 슬라이드 (보강)

메일의 회의 결과와 짝을 이루는 6쪽 발표 자료(공간플랫폼개발그룹)다. 1차 개선과 추가 보완 요청으로 나뉜다.

- **1차 개선**: 서비스 데이터(도로폭 형상 정비, 불필요한 서비스 레이어와 경지계 삭제, 주기와 배경 매칭, 다중이용시설 표출 개선), 스타일과 표출 레벨(단지성 데이터 DP 레벨 조정, 국립공원과 등고선·지하철 노선 스타일, 교차점 심볼 삭제), **신규 레이어**(지하차도 지하부 폴리곤).
- **추가 보완 요청**: 상위 레벨 도로 레이어, 지하철 노선 스타일값, 건물 표출 대상 추가, 공원 레이어 스타일, **ORDA 관련 레이어**, 주기 폰트와 랜드마크·일반 심볼(타사 지도와 비교), 주기 카테고리별 표출 스타일 차별화. 위 표의 1~6번 항목과 대응한다.
- 이후 오르다 연계는 [[air-orda-stamp-integration-proposal-2025]]에서 이어진다.
