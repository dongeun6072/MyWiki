# 드로잉런 코스 생성 PoC 사전 검토 (2026-02 ~ 2026-03)

[[drawing-run-sdk]]의 출발점이 된 Confluence 페이지 3건이다. 삼성생명 "드로잉 런"은 사용자가 지도 위에 러닝 코스를 그리고, 그 코스를 따라 달리며 기록하고 공유하는 서비스다. 이 시기에는 **코스를 만들어 주는 PoC 앱**이 목표였고, 이후 2026-04에 기록 중심 SDK로 범위가 바뀐다 → [[drawing-run-sdk-launch-scope-and-data-items-2026]].

## 사업 내용 (2026-02-19, "코스생성 PoC 앱 구축")

- 사용자가 러닝 코스를 생성하고, 생성한 코스를 트래킹한다.
- 트래킹 대상은 직접 그린 코스, 공유한 코스, 공유받은 코스이며, 트래킹 중 경로 안내가 필요하다.
- PoC 사전 진행 항목은 (1) 코스 생성과 `.gpx` 다운로드 기능을 가진 **더미 앱** 개발, (2) 트래킹 중 방향 안내(내비게이션) 기능 추가다. 후자는 아이나비 스탬프 앱의 방향 안내 기능을 가져오는 구상이다. 코스를 만들 때 안내에 필요한 정보를 함께 담아야 한다.

## 코스 생성 방안 비교

| 방안 | 동작 | 논점 |
|---|---|---|
| 자유 그리기 | 지도에서 "그리기 시작" 터치 → 선 그리기 → "완료" 터치 | 그린 좌표열을 그대로 코스로 쓸지, 도보 경로탐색을 거칠지 |
| 점 이어서 생성 | 점을 찍어 잇는다. 자유 그리기보다 제한적 | 거리재기 기능 방식과 비슷 |
| 경로 탐색 | 출발지, 목적지, 경유지를 주소 검색이나 지도 핀으로 지정해 도보 경로를 탐색 | 경유지 개수 제한, 일반 경로탐색 UI 차용, 자전거 경로 탐색 후 GPX 내려받기 사례 |
| 다각형 생성 | 기본 사각형에서 시작, 선을 터치하면 보간 점이 생기고 이를 움직여 형상 변경. redo/undo/편집 종료 | "십자가 런" 같은 도형 코스 |

트래킹 쪽 참고 사례로 삼성헬스의 실외 자전거 주행(GPX 등록) 방식을 봤다. 안내 문구 예는 "00m 앞에서 좌회전/우회전" 알림이다.

## 2026-03-05 삼성생명 미팅

- **검토 중**: 지도 위 자유 그리기 + 도보 경로 탐색으로 **도보 네트워크에 맞는 안내 가능한 경로**를 만든다.
- **추가 검토 필요**: 도형(쉐이프)으로 경로 만들기. (1) 제공되는 프리셋 도형으로 사용자가 지정한 위치에 맞는 경로가 나오는지, (2) 빈 화면에 사용자가 그린 도형이 지정 위치에 맞는 경로가 되는지, (3) 도형에 맞게 지도 방위를 조정할 수 있는지.
- **시나리오**: 생성 성공 시 예상 거리와 달리기 시간을 보여주고 **최대 3개 코스**를 추천한다. 실패 시 에러 케이스(네트워크 오류, **정합성 70% 이하**로 생성 실패, 타임아웃 등)를 정의한다.
- **일정**: PoC는 대략 6월까지. 테스트와 결과 취합을 포함한 기간이고, 더미 앱과 안내 트래킹 기능 개발은 4~5월에 끝낸다.

## 2026-03-19 사전 기능 검토 결과 공유

| 검토 항목 | 결과 | 비고 |
|---|---|---|
| 지도 위 자유 그리기 | 구현 가능 | |
| 프리셋 도형 경로 탐색 | 구현 가능 | |
| 사용자가 그린 임의 도형 | 구현 가능 | |
| 안내 정보를 포함한 GPX 생성과 다운로드 | 구현 가능 | |
| 그린 도형과 생성 코스의 **정합성 판단(70%)** | 구현 가능 | |
| 코스 정보 표현 | 일부 구현 가능 | 거리와 시간은 가능, **고도 정보는 불가** |
| 경로 실패 에러 케이스 정의 | 구현 가능 | 앱 기능 정의 영역 |
| 코스 다중 생성 | 추가 검토 필요 | 탐색 엔진 개발이 필요 |
| 도형에 맞춘 지도 방위 자동 변경 | **구현 불가** | 사용자가 지도를 회전해 수동으로 조정 |

샘플로 프리셋 도형을 이용한 경로 생성 화면 캡처를 첨부했다(이미지는 옮기지 않음).

**향후 프로세스**: 삼성생명이 (1) 기능을 확정하고, (2) 화면 설계서 등 상세 앱 기획안을 전달하면, (3) 아이나비가 개발 환경을 구축하고 PoC 앱 제작에 착수한다.

**삼성생명에 확인을 요청한 사항**
- 구현 범위를 **단일 코스 생성과 GPX 추출 중심**의 핵심 기능으로 해도 되는지.
- 지도 방위 자동 변경은 불가하며 수동 회전으로 대체해도 되는지.
- 경로 생성 실패 같은 예외 처리는 앱 기획안 기준으로 진행해도 되는지.
- 상세 화면 설계와 사용자 시나리오가 담긴 기획안의 전달 일정.

## 해석

2026-03 시점의 핵심 리스크는 기술보다 **고객사 기획안이 없다는 점**이었다. 이 때문에 4월 초 "PoC → 론칭용 SDK" 전환이 일어났다고 볼 수 있다. ^[inferred]
