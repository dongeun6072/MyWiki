# 모바일 앱 접근성 지침 체크포인트

앱의 접근성 의무는 [[korean-public-mobile-app-compliance]]의 디지털포용법 제19조와 접근성 품질인증(인증마크)으로 이어진다. 이 페이지는 인증 심사에서 기준이 되는 지침을 앱 개발 관점으로 압축했다.

## 1. 문서 관계

| 문서 | 성격 |
|---|---|
| 미래창조과학부 고시 제2013-107호(2013-08-19) | 행정안전부 고시(2011)를 개정한 **법적 고시**. 목적, 용어(준수사항과 권고사항, 무리한 부담), 적용 범위(국가기관, 지자체, 공공기관이 앱을 구축·운영·개선·유지보수할 때)를 정함 |
| KS X 3253:2016 모바일 애플리케이션 콘텐츠 접근성 지침 2.0 | 지침 본문을 **한국산업표준**으로 정리한 것. 인식·운용·이해·견고의 4원칙, 18개 항목, 부속서에 사례. docx와 pdf는 같은 내용 |
| iOS / Android 제작기법 2.0 (2015.12, 한국정보화진흥원) | 지침 2.0(TTAK.KO-10.0634/R1)을 **플랫폼별 구현·점검 방법**으로 풀어쓴 문서. 항목마다 지침 소개, 개발 방법, 점검 기준(오류 유형), 점검 방법, 준수·미준수 사례 |

고시와 표준 사이의 세부 문구 차이는 대조하지 않았다. 심사 때 어느 판을 기준으로 하는지는 확인이 필요하다. ^[ambiguous]

## 2. KS X 3253 체크리스트 (18항목)

**인식의 용이성**

| 번호 | 항목 | 핵심 요구 |
|---|---|---|
| 5.1 | 대체 텍스트 | 텍스트 아닌 콘텐츠는 의미와 기능이 같은 짧고 명확한 대체 텍스트 |
| 5.2 | 자막, 수화 | 영상·음성에 동기화된 자막, 원고, 수화 중 하나 이상. 화면 속 의미 있는 문자는 별도 설명 |
| 5.3 | 색에 무관한 인식 | 색을 구별하지 못하는 사용자, 고대비 모드에서도 정보가 인식돼야 함 |
| 5.4 | 명도 대비 | UI 컴포넌트와 텍스트의 전경·배경 대비 **3:1 이상** |
| 5.5 | 명확한 지시 사항 | "빨간 버튼", "오른쪽 아이콘"처럼 모양·위치·색·소리에만 의존한 안내 금지 |
| 5.6 | 알림 기능 | 중요한 알림은 화면, 소리, 진동 등 여러 방법으로 |

**운용의 용이성**

| 번호 | 항목 | 핵심 요구 |
|---|---|---|
| 6.1 | 초점 | 의미 있는 컴포넌트에 초점이 가고 **논리적 순서**로 이동. 보이지 않는 요소로 이동 금지 |
| 6.2 | 누르기 동작 | 멀티터치, 팬, 드래그 같은 복잡한 동작에는 **단순 누르기 대안** 제공 |
| 6.3 | 응답 시간 조절 | 시간 제한은 연장·조절 수단 제공. 보안 등 불가피하면 사전·종료 안내 |
| 6.4 | 정지 기능 | 자동 변경 콘텐츠(캐러셀 등)는 이동, 일시정지, 정지 수단 |
| 6.5 | 컨트롤 크기와 간격 | 가로·세로 각 **9mm 이상** 권고, 외곽선이 없으면 중심 간 간격 충분히(OS 기본 컨트롤은 예외) |

**이해의 용이성**

| 번호 | 항목 | 핵심 요구 |
|---|---|---|
| 7.1 | 입력 도움 | 입력 서식의 용도 안내, 오류 내용 안내와 정정 수단, 오류 지점으로 초점 이동 권장 |
| 7.2 | UI 일관성 | 배치와 유사 기능 컨트롤을 일관되게 |
| 7.3 | 깜빡임 제한 | 초당 3~50회 깜빡임 회피. 불가피하면 사전 고지와 회피 수단 |
| 7.4 | 자동재생 금지 | 3초 이상 자동 배경음 금지, 쓰면 정지·음량 제어 |
| 7.5 | 예측가능성 | 화면 전환, 팝업, 다른 앱으로의 이동은 미리 알 수 있게 |

**견고성**

| 번호 | 항목 | 핵심 요구 |
|---|---|---|
| 8.1 | 폰트 기능 활용 | OS의 글꼴 크기 조절을 따르고 레이아웃이 유지되게, 범용 폰트 권장 |
| 8.2 | 보조기술 호환 | OS 기본 컴포넌트 우선 사용, 커스텀이면 보조기술로 쓸 수 있게, 기능을 바꿔 쓰면 안내 |

또 출시 전에 시각, 청각, 뇌병변, 지적, 지체 장애와 고령자 대상 **사용자 평가**를 하도록 권고한다(9장).

## 3. 플랫폼별 구현 포인트 (제작기법 문서)

- **공통 점검 방식**: 스크린리더(Android는 TalkBack, iOS는 VoiceOver)를 켜고 화면을 읽으면서 대체 텍스트, 초점 순서, 컨트롤 동작을 확인한다. iOS는 Xcode의 Accessibility Inspector도 쓴다.
- **대체 텍스트**: Android는 `contentDescription`, iOS는 `accessibilityLabel`(설명은 `accessibilityHint`, 요소 활성화는 `isAccessibilityElement`). 힌트에만 설명을 넣거나, "버튼 버튼"처럼 유형을 중복하거나, 라벨이 비어 "라벨 지정 안 됨"으로 읽히거나, 보이지 않는 형태로 숨겨 제공하면 오류다. 숫자 정보는 읽었을 때 뜻이 통하게(날짜 등) 쓴다.
- **장식 요소**: 의미 없는 이미지에 대체 텍스트를 달면 오류다. Android는 `importantForAccessibility`로 제외한다.
- **입력 서식**: 레이블과 입력 필드를 연결한다(Android `setLabelFor`, 힌트 지정). 오류는 소리, 텍스트로 알리고 초점을 이동한다.
- **초점 순서**: 접근성 초점은 터치 탐색, 쓸어넘기기 탐색 모두 논리적 순서여야 한다. 동적 화면 변경 시 iOS는 `UIAccessibilityPostNotification`(레이아웃 변경 등)으로 알린다.
- **컨트롤 크기**: 두 플랫폼 모두 단위(dp, pt)와 무관하게 실제 9mm 이상을 점검한다. dpi가 다른 기기에서도 충족하는지 확인하라고 안내한다.
- **글꼴 크기**: Android는 텍스트 크기를 `sp`로 지정해 시스템 글꼴 설정을 따른다.

## 4. 서울동행맵 적용 메모

- 이 앱은 시각·청각·이동 약자 이용자가 핵심이라([[seoul-donghaengmap-design-system]]의 접근성 우선 원칙) 18개 항목이 곧 검수 기준이다. 대비 3:1은 최소선이고, 디자인 시스템의 대비 목표와 맞는지 대조한다. ^[inferred]
- **지도 화면**은 캔버스 위 마커, 제스처 위주여서 6.1(초점), 6.2(단순 누르기 대안), 5.1(마커 대체 텍스트)에서 문제가 되기 쉽다. 목록 형태의 대체 경로가 필요한지 설계에서 확인한다. ^[inferred]
- 기술협상의 모바일 접근성 인증마크 요구([[seoul-donghaengmap-negotiation-kickoff]])는 위 지침에 대한 심사다. 인증 절차와 일정은 이 문서들에 없다. ^[ambiguous]
- 웹 부분은 [[kwcag-2-2]], UI 컴포넌트 기준은 [[digital-government-uiux-guideline]]을 본다.
