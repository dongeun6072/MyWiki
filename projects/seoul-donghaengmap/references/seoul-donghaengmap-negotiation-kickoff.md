# 기술협상서와 착수보고 결과

[[seoul-donghaengmap-rfp]]에 대한 제안 검토와 협상 결과(기술협상서, 2026-06, 서울시 의견 반영), 그 뒤 서울시가 정리한 착수보고 결과(착수보고 회의 2026-06-25, 결과 문서 07-01)다. 사업 전체는 [[seoul-donghaengmap]]이다. 담당자 이름과 연락처는 옮기지 않았다.

## 기술협상서: 요구별 협상 결과 (모두 수용)

| # | 영역 | 협상 내용 |
|---|---|---|
| 1 | 인프라·장비 용량 | GPU 최적화 추론 프레임워크와 벤치마크 시나리오를 마련. 대시민 동시 사용자와 AI 추론 부하로 서버 사양을 산정해 서울시와 협의 후 확정, 장비 구입·설치 |
| 2 | AI 대화형 서비스 기술 관리 | 폐쇄망에 설치되는 RAG 솔루션이 원칙. 오픈소스 혼합 시 기술 지원 책임 범위와 패치 체계를 명확히 한다. LLM은 폐쇄망 설치 가능한 솔루션으로 제안, 데이터센터 보안 정책을 따른다. |
| 3 | 실내 전파지도 수집 | Wi-Fi, BLE, 지자기 데이터를 동일 날짜가 아닌 **서로 다른 날짜 기준 최소 3세트** 수집해 환경 변화 오차를 줄인다. 센서 측위 오차는 **1.7m**이며 교통약자 테스트로 검증됐다. 정확도 향상 방안은 서울시와 협의. |
| 4 | 보행불편 신고 접수·관리 | 마일리지는 **티머니GO**를 통해 지급되므로 외부 시스템과 협의해 연계 방식과 데이터 형식을 설계에 반영. 외부 개발 일정에 따라 기능 일정이 변동될 수 있다. |
| 5 | 버스 플랫폼·BMS·단말기 연계 | 신규 개발 중인 **3기 BMS** 개발팀과 협의해 연계 방식, 데이터 형식, 표준을 설계에 반영 |
| 6 | 교통약자 유형별 버전 | 시각장애인 전용 모드 외에도 서울시 요구, 교통약자 자문단 의견을 수렴해 앱 전반의 기능을 재설계. 제안서의 페르소나와 여정은 예시. |
| 7 | 모바일 접근성 | 모바일 웹 접근성 기준을 준수하고, **모바일 접근성 인증마크를 획득**한다. 인증 비용은 수행사가 부담. |
| 8 | 정책 추진 일정 | 사업 기간 12개월. 시범 서비스 오픈 시기는 서울시와 협의해 결정 |
| 9 | 데이터센터 입주 | 독립된 폐쇄망(서울시 내부망). 입주 세부 정책이 보안 사항이라 비공개이므로 데이터센터와 반드시 협의. 설치, 네트워크 포설, 보안, 관제를 협의 내용으로 적용. 이관 중 기존 서비스 병행과 무중단 대책 협의. |

### 특별제안 2건

- **교통약자 의견수렴**: 자문단 운영(RFP 기본 요구), 서울연구원 정책과제 "교통약자 디지털 수용성 향상을 위한 플랫폼 활용 진단"의 설문과 연구 결과 반영
- **시스템 안정화**: 착수 후 3개월 이내 현행 동행맵 안정화. 유지보수 중 파악된 장애와 기능 개선을 전달받아 반영하고, 현 유지보수 업체와 인수인계. 추가로 **GTFS 데이터 오류 분석**으로 신규 서비스 오픈 전에도 올바른 경로를 제공하도록 수정

> 감리 보고서는 "기술협상서 특별제안 2건 삭제"가 회의록만 근거로 반영되고 있다고 지적했다. ([[seoul-donghaengmap-design-audit]])

## 착수보고 결과 (서울시 의견)

| 주제 | 내용 |
|---|---|
| 서비스 목적 명확화 | 기업의 지도 사업 목적과 서울시 서비스 목적을 구분. 서울시 목적은 "교통약자가 화장실을 찾고 버스·지하철을 원활히 갈아타는 수준(이동 경로 확보)" |
| 실시간 자동 업데이트, BMS | 기반·실시간·돌발 정보를 수동이 아닌 자동 업데이트 체계로 연계. 집회 등으로 인한 버스 우회 정보를 실시간 반영 |
| 혼잡도 기반 예약 | 저상버스 도입률 90%로 단순 예약의 실효성이 줄어, 출퇴근 혼잡도와 연계해 혼잡한 차량 대신 다음 차량을 안내하는 고도화 제안 |
| 불편 신고 | 기존 신고는 위치 지정 방식 등 불편으로 이용률이 낮아 프로세스 직관화, 티머니GO 마일리지로 활성화(제안요청서에 포함) |
| 진척 관리 | 주 1회 이상 회의로 파트별 방향 확정(7~8월) → 1단계 개발 완료(2026 하반기) → 의견 수렴·불편 반영(2027 상반기). 수행사는 "지하철 도면은 다음 달 10일까지" 같이 **구체적인 날짜를 정해 요구** |
| 자문단 | 시의회 자문인력, 교통위원회 인력 포함. 서울연구원 "디지털 약자 수용성 진단 연구"(관찰 조사 포함)와 연계 |
| 실내지도 단계 확대 | RFP는 10개 역 시범 후 전 역사 확대였으나 **1단계 평가 후 2단계 범위를 확정**하고, 전체 역사 구축이 불가능할 수 있어 설계 변경 가능 |
| 시스템 구성·GPU | 동시 접속자 산정 근거 보완(시각장애인 기준 순간 약 300명, 최대 700명 처리). 1·2단계 이관 절차를 데이터센터와 협의. BMS 사업에서 구매한 H200 활용 검토 |

## 해석

착수보고의 "혼잡도 기반 예약" 제안은 이후 화면기획에서 **혼잡도 표기**와 NLU 의도 설계로 이어진다. 다만 음성 챗봇의 "자리 있어?"는 이번 릴리스 범위 밖(2027-01-04 이후 고도화)으로 분류됐다. ^[inferred] ([[seoul-donghaengmap-screen-design]])
