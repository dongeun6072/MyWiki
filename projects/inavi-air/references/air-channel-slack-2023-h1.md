# Slack #01_inavi_air 대화 (2023 상반기)

아이나비 에어(Phone, Android Auto, CarPlay) 개발·기획·디자인·서버·QA가 함께 쓰는 비공개 채널의 2023년 1월~6월 기록이다(채널명은 05-13에 `01_air3`에서 `01_inavi_air`로 변경). 프로젝트 개요는 [[inavi-air]], 같은 해 버전 정리는 [[air-app-version-notes-2023]], 캐시 고도화 상세는 [[air-cash-advancement-planning-history-2023]], [[air-cash-stamp-release-2023]], [[air-cash-accrual-policy-discussion-2023]]를, SDK 쪽은 [[air-nsdk-dev-slack-2023-h1]]을 함께 본다.

이 기간 채널 메시지 363건(huddle 알림 포함)과, 답글이 달린 스레드 200개를 모두 읽었다(미열람 0). 배포 알림 봇 스레드도 모두 열어 이슈 보고·출시 결정이 있으면 반영하고, 내용이 없으면 확인만 했다. 아래 본문의 각 주제 절에 스레드 답글에서 나온 원인·결정을 합쳤고, 세부는 "스레드 상세" 절에 따로 모았다.

## 한눈에 보기

- 1~3월: 음성광고(온에어) PoC, 주행화면·그룹주행 리뉴얼, 에어연구소 통계, 안전운행 가변 제한속도.
- 2~5월: what3words(w3w) 제휴·연동 기획과 개발, 캐시버튼(아바티 SDK) 연동, 카카오 비즈보드 검토.
- 4~6월: 에어캐시 적립 개선(스탬프 9개, 미적립 캐시, 추가 캐시) 후 룰렛 포함 고도화, 6월 말 03.05.28 / 03.05.05 배포 준비.
- 전 기간: Auto(Android Auto)·CarPlay 사용성 개선, 안내엔진(DP 엔진) 이슈, 스토어 출시노트·이미지 절차.

## 음성광고(온에어) PoC

- 기획서 v1.0(01-09) → 1차·2차 리뷰 → v1.1(01-18) → v1.3(02-07) → v1.4(02-14). 02-14 사업부문 논의 결과: 음성 오디오 광고 PoC(사업팀이 광고 대행 계약·CPM·리워드 정책·정산 절차 정리), 광고 영역 추가(에어캐시 쿠폰함 하단 배너, 적립 완료 팝업 내 광고)를 차기 패치에 넣기로 함.
- 미로그인 사용자는 온에어 ON 시점에 로그인을 유도하기로 했다(기획서 v1.4).
- 서버 규격 협의: 음성 파일 조회 I/F가 개발서버 로그상 30초마다 호출되던 점을 확인(음성광고 수신 전 1회만 호출하면 되는지 문의), 하루 최대 광고 개수를 가져오는 I/F 필요(안내 시작 시 광고 타이밍 계산, 이미 n개 재생했으면 "최대-n" 전달), 온에어 ON/OFF 설정 I/F(`/onAirOnOffSetting`)는 협의로 제거, 개발서버에서 `todayAdPlayable`을 true로 내려 달라는 요청(`/onAirVoiceFileInfo`).
- 음성광고 적립캐시는 20캐시에서 3캐시로 변경(03-03). 광고 업체에서 받은 음성 파일 15개의 적립 캐시를 별도로 확정해야 했다.
- 코인 적립 효과음은 무료 도구로 시안 제작, 광고 종료 1초 뒤 동전 애니메이션을 띄우도록 iOS에 반영(02-28). 애니메이션 시점과 서버의 "음성 재생 완료" 호출 시점을 어디에 둘지는 미정으로 남음.
- 02-23 내부 테스트용 PoC 빌드를 배포했고 실제 PoC용은 다음 날 발행하기로 했다(03-08 빌드는 OnAIR Off).

## what3words(w3w) 연동

- **배경**: 02-14 사업 쪽에서 w3w와 협업을 구상(아시아태평양 담당과 미팅)해 에어에 적용을 검토. 목표는 양사 홍보와 모빌리티·물류·OEM 연결. 최소 시나리오는 검색창에서 `///` 검색, 상세정보에 w3w 추가, 위치 공유(SMS)에 w3w 포함. w3w 측 피드백: 자동완성(대한민국으로 한정), 정규식으로 `단어.단어.단어` 형식 감지, 입력 시 3단어 주소를 대표 목적지로 표시, 검색창 안내 문구, 상세 화면 전면 노출, 추천어에 현재 위치와의 거리 표시.
- **요금제**: 4/25 Business 플랜(월 3만 건)으로 결정, 사용자 증가 시 상향 가능. 개발 시작 시 무료(Starter) 키는 1,000건 제한이라 테스트가 막혔고, 유료 플랜 전환 후에도 키는 유지된다고 확인. 개발용(무료)과 상용(유료) 키를 구분해 받기로 함. 5/3~5/4 무료 한도 초과로 개발서버 추천어·검색이 멈추는 일이 있어 임시로 상용 키를 쓰고 되돌렸다.
- **API 제한과 대응**: "단어로 좌표 변환" API는 3만 건 제한이 있고 추천어 1회당 3번 호출된다. 제한 발생 시 서버가 변환 호출을 중단하고 `words` 외 필드를 `0`/빈 문자열로 내려, 앱은 `words`만 필수로 보고 나머지가 비어도 GUI가 깨지지 않게 개발한다(주소·거리 미표출). 이후 추천어 거리는 `distanceToFocusKm` 기준으로 바뀌어 m 단위 표출이 불가해졌고 0km 표시 방식을 기획에 문의했다(06-13).
- **서버 I/F**: `/sire/revgeocoding`, `/sire/searchPoiDetail`에 `w3wYn` 요청 파라미터 추가(05-11), `/w3w/autoSuggest`에 `posx`, `posy` 추가(05-04), 추천어 I/F 수정(`words`, `cut_address` 외 빈 값, `distanceToFocusKm` 추가, 06-12). 앱 요청은 iOS 기준 정규화 좌표(coordtype 0)만 사용한다.
- **정확도 이슈**: 추천어로 받은 좌표를 `revgeocoding`에 다시 보내면 w3w 키워드가 달라지는 문제를 조사했다. 원인은 검색엔진 응답 좌표의 소수점 손실과 정규화 좌표 변환 오차로 정리됨. 서버에서 소수점을 계산해 제공하는 방안과 요청 좌표로 대체하는 방안을 검토했고, 수정 후 개발서버 적용, AOS·iOS 모두 정상 확인.
- **w3w 측 제안(05-11)**: 검색어 앞의 `///` 입력 제거, 자동완성 호출 시점을 세 번째 단어 첫 글자 입력 이후로 변경. 이에 따라 공지사항도 `///` 제거 검색 형태로 고치기로 했다(05-15). 공지·홍보 이미지와 스토어 안내에서는 w3w를 다시 언급하지 않기로 했다(06-19, 이미 서비스 공지된 내용).
- **호출량 이슈(05-30)**: w3w 쪽 로그상 좌표 변환 호출이 자동완성 호출보다 많아 비정상이라는 문의. 호출 시나리오 확인을 요청(원인은 아래 "w3w 보강" 참고). 05-11에는 일 100만 건 이상 호출 문의도 있었고 길찾기 종점이 도로에서 끝나는 불편을 건물군 입구점·최적 지점 API로 보완하는 방안 검토를 요청했다.
- **UI 사양**: 최근장소/내장소에서 w3w 항목은 상세에 w3w 정보를 숨기고 "내장소 등록" 버튼 제거(05-08), 검색 결과가 없으면 추천어 첫 지점을 결과로 표시, `///` 밑줄 문제로 UI에서는 제거하고 복사 시에만 붙이는 안 검토(05-02), 공유 링크는 POI가 아니면 제목이 주소로 표시됨(05-09), 검색 실패 케이스 정의 요청(04-24).
- **Auto/CarPlay**: CarPlay에 w3w 추천어 리스트와 아이콘을 적용(05-31). 알려진 이슈는 추천어 리스트 스크롤 불가(CarPlay 버그)와 직접 탐색 시 타이틀이 결과까지 이어지는 현상. 시나리오 v1.1(06-15), 관련 리소스는 `car_` 접두 192x192(06-20).
- 강원도가 강원특별자치도로 바뀌어 단계별 주소검색 시/도 단축 명칭에서 "특별자치도"도 제거해야 한다는 건의(06-15).

## 캐시버튼(아바티) 연동

- 03-14 SDK 1차 검토: 개발자 사이트의 개발 키로 SDK 추가, 에어캐시 화면에 플로팅 버튼 표출 가능. 미검토는 캐시 전환 연동(서버와 함께 검토). 정리가 필요한 사양은 플로팅 버튼 vs 페이지, "문의하기" 버튼 노출, 스누즈(일정 기간 버튼 숨김), 캐시버튼 Notification. 문제점: 에어캐시 화면 프로그레스바 때문인지 버튼 생성 시 버벅임.
- 서버 연동 이슈: 검증 API 성공 코드와 취소 API 응답(`success`) 판정 기준 문의(05-03), 동시 요청(어뷰징 체크) 시 취소 API를 호출하면 앞선 정상 요청까지 취소될 우려 문의(05-04), 가짜 transactionID로 전환 API 호출 시 630 에러(05-09).
- 앱 처리 방침: 캐시 변환 성공 시 `cashInfo` I/F를 호출해 에어캐시 화면을 갱신(05-04). 캐시 전환은 `/cashButton/cashConversion` 사용.
- 04-11 Custom 버튼이 가능함을 확인. 05-12 업체와 직접 통화하며 사양이 조금씩 바뀌고 있었다. "응원하기" 팝업은 문구만 수정 가능.
- 카카오 비즈보드(04-11): 지원 버전이 3.12.x 이후이고 iOS 최소 타겟을 11.0에서 12.0으로 올려야 하며 최신 버전은 13.0이 필요(적용 버전은 3.12.7로 검토).

## 에어캐시 적립 개선과 고도화(스탬프·룰렛)

- **정책(04~05월)**: 적립 개선 기획 v1.0(04-25) → v1.1(05-12: 적립내역 컬럼, 적립 완료 뱃지, 스탬프 초과 적립, 오퍼월 중요도 조정) → v1.2(05-17: 미적립 캐시 1일 유효, "랜덤 캐시"를 "추가 캐시"로 용어 통일). 사업팀과 캐시 소멸 기간 2일, 9회 적립 시 추가 캐시 정책을 사전에 결정하도록 요청(05-15). 자정 이후 "00시 기준 초기화" 팝업은 정책 변경으로 제거 문의, 00시 기준 적립 버튼이 있으면 갱신 전 팝업 제공으로 보완(05-19).

- 01-05 Auto Lib 업데이트로 기본화면·경로선택·최근장소·내장소·주변검색 결과 화면에서도 지도 이동이 가능해졌다. 현위치·확대/축소 버튼은 앱에서 페이지별로 커스텀할 수 있다. 01-06 이동거리 누적은 현위치 기준이 아닌 화면에서 반복 이동하면 발생(현 서비스 버전에서는 미발생). 01-17 페이지별 현위치 사양: 메인·주행은 현위치 버튼, 지점표출·경로선택은 전체경로 버튼. 이번 리뉴얼에서 0원은 "무료"로 표기.

## 미해결 / 불확실

- 03-15 iOS 03.05.01 유입률의 두 수치(14%, 62%)는 시점이 불명확하다 ^[ambiguous].
- w3w 개발서버 키를 상용 키로 임시 바꿨다가 되돌린 시점이 스레드마다 달라(5/4 앱 배포 기준과 5/12 배포 기준) 하나로 정하지 않았다 ^[ambiguous].
- 4/13 이후 AOS 크래시·ANR 증가의 최종 원인과 안드로이드 오토 볼륨 사양 분리의 확정 여부는 이 기간 대화에서 결론이 보이지 않는다 ^[ambiguous].
- 일부 스레드는 서버·앱 개발자 간 구두(허들) 합의로 끝나 결과가 채널에 남지 않았다.
- 서버 주소, 테스트용 번호, API 키, 공유 링크, 사람 이름은 원본에 있으나 이 페이지에는 옮기지 않았다(미수록).
