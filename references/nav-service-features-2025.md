# 내비 서비스 기능 변경 (2025)

한 제품에 묶이지 않고 에어, 하이브리드(통신·비통신), KGM, 티머니 등 **여러 제품 엔진에 같이 들어가는 변경**을 모았다. 제품별 운영은 [[air-operations-2025]], 데이터 포맷은 [[inavi-mr-format-spec]]이다.

## 시간제 통행제한

- 03-21 지도 팀이 에어 개발서버용 **시간제 통행제한 테스트 발행**(2504a)을 올렸다. 서비스 적용 전 배경, 심볼, 작동, 표출 화면 확인용이며 `atl.zip`에 `smrroadblocking_time.bin`, MR 폴더에 `roadblocking_time.bin`이 추가됐다.
- 04-22 이 데이터 영향으로 **이슈**가 발생해 공유됐다(본문 없음).
- 08-29 QA 결과: DP 엔진 사양을 바꾼 뒤 에어(AOS 03.05.55, iOS 03.05.31)와 하이브리드 통신(MXI v2.6.0)·비통신 단말에서 **점선 표출과 기능 시험 모두 PASS**였다.
- 12-08 DriveThru 통행제한구역 오류 확인 메일이 있었다(본문 없음).

## 스마트 재탐색

- **속도막대 색상 오류**(06-11): 추천·최소시간 옵션 탐색이 7개 경로 비교에서 **3개 비교**로 바뀐 뒤 재탐색 시 속도막대 색이 이상했다. 원인은 스마트 재탐색 결과를 소켓으로 보낼 때 **host to network 바이트 순서 변환**을 거치지 않아 잘못된 값이 전달된 것이다. 에어 엔진을 롤백했다가 수정판을 개발기에 적용했다(2505a).
- **개선 요청**(08-19): 서울-부산처럼 먼 길에서 목적지 주변 교통 변화(퇴근 시간대)로 **경로가 자주 바뀌는** 문제다. 스마트 재탐색의 **경로 유사도 판단 로직**을 바꾸는 방향으로 8월 안에 검토 결과가 필요했다.

## 교통정보

- **소수점 단위 속도**(11-06): 경로기술개발팀과 교통정보개발팀이 ETA 고도화를 위해 **테이블 형식의 소수점 속도 교통정보**를 적용하는 개발을 마쳤다. 기존 방식을 그대로 두고 표출하면 새 정보로 만든 경로의 교통 색상과 화면이 달라 보인다. 에어, KGM, 티머니는 서비스가 분리돼 있어 **경로 엔진과 실시간 교통정보를 쓰는 모든 모듈이 함께 패치**돼야 한다. 부문장이 각 제품 담당에게 해당 모듈을 확인해 일정을 잡도록 요청했다.
- 12-13 이전 에어의 교통정보 관련 탐색/CTT 이슈 확인 요청(2024) 이후 같은 주제가 이어진 것으로 보인다. ^[inferred]

## 안내 음성·표출

- **스쿨존 음성**(07-08): 새 문구 '안전속도에 유의하세요'를 임시로 만들어 보니 특정 성우 음성의 TTS가 **끝음절 처리**에서 어색해 대안 '유의하십시오'를 비교했다. 데이터 오류로 보일 수 있다는 의견에 두 안이 나왔다. 1안은 도로 제한속도로 안내('안전속도는 N km 이하'), 2안은 단순 문구이다. 결론은 다음 정기 지도에서 **'어린이보호구역입니다. 안전속도에 유의하세요.'**로 기본 음성을 교체한다.
- **아파트명 POI 주기**(10-17): 아이나비M에서 '아파트 동/호수'와 '아파트명'을 동시에 표출해 달라는 요구가 와서, 이미 **지하철 출구번호와 역명**에서 하던 방식처럼 **주기 충돌 처리를 하지 않도록** DP 엔진에서 단독 처리하기로 했다. 위험 요소는 낮고 내비 앱과 Navi SDK에 공통 사양으로 넣는다. 표출 레벨과 동 번호 폰트 크기·색은 T맵·네이버와 비교해 벤치마크한다. 쓰는 SDK는 에어와 별도로 0.7.4 계열이어서 같은 SDK에도 반영을 요청했다.
- **결빙구간 안내**(12-28): 국토교통부의 결빙 우려·취약구간 정보를 표출하는 사양 확인이다. 위험지역 DB라서 **경로와 상관없이 표지판 심볼만** 나오고 음성은 없다. 개발 측에서는 경로가 있을 때만 심볼과 음성('전방에 결빙 주의 구간입니다')으로 안내하는 사양을 공유했다. 두 설명이 달라 사양 확정이 필요하다. ^[ambiguous]

## 재난·안전 정보 연계

- **민관합동 내비게이션 고도화 TF**(02-11 실무회의): 환경부 홍수 심각 정보, 여름철 태풍·집중호우 취약구간, 산사태 위험 알림, IoT 침수 센싱 정보, 소방 신고 정보 연계 등이 안건이었다. 정부 쪽은 **7월부터 가능한 서비스**를 가장 많이 물었고, 내비사 공통 답변은 ① 유형별로 각각 개발하기는 불가능하니 **데이터를 먼저 표준화**해 협의 ② 정부 권고 일정은 개발 리소스 확인이 필요해 즉답 불가 ③ 표준노드링크에 매핑해 제공해도 올해 활용은 보장 어렵다였다. 2~4월 표준화 협의, 6월까지 개발이 목표로 보인다.
- **돌발상황정보 API의 싱크홀**(12-17): 국가교통정보센터가 12-15부터 싱크홀 발생 정보를 돌발상황 API로 제공하고 재난상황 API도 추가한다며 내비사의 표출 계획을 물었다. 에어 답변은 **선별 표출**(전면 통제로 우회가 필요한 항목 위주), **제공 의향 있음**, 예상 시점 **2026년 3월경**, 싱크홀 우회 탐색까지 가는 것이 맞다는 의견이다.
- **킬로포스트(이정정보)**(06-04): 발주처 사업을 위해 이정정보 표출 앱 개발 검토를 요청받았다. 동적팀이 개발2팀에 CSV로 주는 DB 포맷을 쓰려는 것이고, 발주처 일정(원안 상반기)은 계약 협의상 재조정이 불가피하다. 개발 측은 DB 포맷 협의와 배포 일정이 정리돼야 공수를 낼 수 있다고 답했다.
