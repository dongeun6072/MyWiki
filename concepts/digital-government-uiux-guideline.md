# 디지털 정부서비스 UI/UX 가이드라인

공공 웹·앱의 UI/UX를 기관마다 따로 만들면서 생긴 불일치(같은 목적인데 절차·표현이 다름, 불명확한 설명)를 줄이려고 만든 범정부 기준이다. 「전자정부법」, 「행정기관 및 공공기관 정보시스템 구축·운영 지침」, 「전자정부 웹사이트 품질관리 지침」에 따라 행정·공공기관이 지켜야 한다. 1,000쪽이 넘는 문서라서 구조와 변경점, 앱에 필요한 부분만 정리했다. 서울시 공문 붙임 파일은 2025.08 개정본과 사실상 같은 내용이다(운영기관 식별자 설명 문구 일부만 다름). ^[inferred]

## 1. 적용 대상과 수준

- 공공기관이 구축·운영하는 **모든 웹사이트, 모바일 웹·앱**은 원칙, 스타일, 컴포넌트, 기본 패턴, 서비스 패턴을 지켜야 한다. 기관 유형(중앙행정기관 대표, 소속기관 등)에 따라 공식 배너, 헤더·푸터 같은 아이덴티티 요소의 적용 범위가 다르다.
- 서비스 패턴의 사용성 가이드는 **필수, 권장, 우수** 3단계다. 필수를 먼저 지키고 단계적으로 넓힌다.
- **모바일 앱 한계**: 이 가이드라인은 OS별 네이티브 컴포넌트와 앱 고유 탐색 모델을 다루지 않는다. 앱에 쓸 때는 "모바일 서비스의 UI/UX 개선" 절의 안내를 따른다. 원칙 6(다양한 상황 고려), 스타일의 반응형 그리드, 컴포넌트·패턴의 모바일 고려 사항, 표준 프로토타입의 모바일 화면을 참고한다. 네이티브 앱은 OS 가이드와 접근성 지침([[korean-mobile-app-accessibility-guidelines]])을 함께 봐야 한다는 뜻이다. ^[inferred]

## 2. 구성 (2025.08 기준)

| 편 | 내용 |
|---|---|
| 1 소개 | 배경·목적, 구성, 활용 방법, 범정부 UI/UX 디자인시스템(KRDS) 소개 |
| 2 디자인 원칙 7개 | 사용자 중심, 모든 사용자 포용, 공통 경험 속 개별 특성, 빠르고 간단, 쉽게 이해, 다양한 상황 고려, 신뢰 |
| 3 디자인 스타일 | 색상, 타이포그래피, 형태, 레이아웃, 아이콘, 엘리베이션, 선명한 화면 모드(high contrast), 디자인 토큰 |
| 4 컴포넌트 | 아이덴티티(공식 배너, 운영기관 식별자, 헤더, 푸터), 탐색(건너뛰기 링크, 메인 메뉴, 브레드크럼, 사이드 메뉴, 페이지네이션, 탭바), 레이아웃·표현(모달, 아코디언, 캐러셀, 탭, 표, 스플래시 화면 등), 액션(링크, 버튼), 선택, 피드백(단계 표시기, 스피너), 도움(도움 패널, 코치마크 등), 입력, 설정(언어 변경, 화면 크기 조정), 콘텐츠(접근 가능한 미디어, 숨긴 콘텐츠) |
| 5 기본 패턴 | 개인 식별 정보 입력, 도움, 동의, 목록 탐색, 사용자 피드백, 상세 정보 확인, 오류, 입력폼, 첨부파일, 필터링·정렬, 확인 |
| 6 서비스 패턴 | 방문, 검색(7단계), 로그인(7단계), 신청(7단계), 정책 정보 확인 |

## 3. 2024.02 → 2025.08 개정 요지

| 항목 | 2024.02 | 2025.08 |
|---|---|---|
| 분량 | 약 990쪽 | 약 1,180쪽 |
| 디자인시스템 | 언급 없음 | **KRDS** 소개 절 추가. 디자인 요소를 코드화한 디자인 토큰, 디자인 라이브러리, HTML 컴포넌트 키트를 연동 |
| 스타일 | 색상, 서체, 형태, 배치, 아이콘 5종 | 타이포그래피, 레이아웃으로 정리하고 **엘리베이션, 선명한 화면 모드, 디자인 토큰** 추가(9종) |
| 컴포넌트 | 아이덴티티, 탐색, 레이아웃·표현, 액션, 선택, 피드백, 도움, 입력 | **탭바, 설정(언어 변경, 화면 크기 조정), 콘텐츠(접근 가능한 미디어, 숨긴 콘텐츠)** 추가 |
| 서비스 패턴 | 기본 패턴까지 | **방문, 검색, 로그인, 신청, 정책 정보 확인** 서비스 여정별 패턴 추가 |
| 색상 접근성 | - | 명도 대비 기준을 매직넘버(40은 3:1, 50은 4.5:1, 70은 7:1)로 표현해 토큰 설계에 연결 |

^[inferred] 위 비교는 두 문서의 목차와 본문 일부를 대조한 것이어서 세부 문구 변경은 확인하지 않았다.

## 4. 자체 검증 체크리스트 (2024.11판)

- 가이드라인을 실제로 지키는지 **같은 방식으로 확인**하기 위한 항목별 검증 절차와 준수 기준이다. 하나의 가이드 항목에 체크리스트가 여럿이면 모두 충족해야 준수다. 기준을 충족하지 못하면 미준수(F)로 본다.
- **3단계로 단계적 개발 중**이고 현재는 1단계만 제공한다.

| 구분 | 1단계 범위(요소 수 / 체크리스트 수) |
|---|---|
| 스타일(색상, 글꼴, 형태) | 3 / 21 |
| 컴포넌트(아이덴티티, 탐색, 선택, 액션, 입력) | 5 / 170 |
| 기본 패턴(개인 식별 정보 입력, 입력폼, 첨부파일, 필터링·정렬) | 4 / 47 |
| 서비스 패턴(사용성 가이드 필수 항목) | 8 / 73 |

- 수행 순서는 검증 준비, 검증 수행, 검증 결과서 작성, UI/UX 품질 개선이다. 2단계(레이아웃·표현, 피드백, 도움 등)와 3단계는 앞으로 추가된다.

## 5. 서울동행맵에서의 쓰임

- 입력폼, 첨부파일, 필터링·정렬, 로그인 흐름은 1단계 체크리스트에 걸리므로 화면 설계 단계에서 항목을 대조해 두면 검수 때 수정이 줄어든다. ^[inferred]
- 서울동행맵 디자인 시스템([[seoul-donghaengmap-design-system]])은 접근성 우선 토큰을 따로 정의했다. KRDS 토큰·대비 기준과 어긋나는 값이 있는지 대조할 필요가 있다. 대조는 아직 하지 않았다. ^[ambiguous]
- 서울시가 공문으로 개정본을 붙임으로 보낸 것은 이 개정본(2025.08)을 기준으로 삼으라는 뜻으로 읽힌다. ^[inferred]
