# 서울동행맵 기능명세서와 백엔드·SDK 기능 정의

## 1. 화면별 기능명세 (v0.5, 2026-08-13, 앱·서버 62건)

아이나비시스템즈가 작성한 기능명세다. 앱과 서버 기능을 같은 표에서 구분한다. 프로젝트 전체는 [[seoul-donghaengmap]], 요구의 출처는 [[seoul-donghaengmap-rfp]]다.

| 영역 | 번호 | 주요 기능 |
|---|---|---|
| 공통·접근성 | 1~9 | 교통약자 유형 선택(최초 실행), 글자 크기, 고대비(4.5:1 이상, 색만으로 구분 금지), **음성·진동·화면 3채널 동시 안내**와 우선순위 인터럽트, 이벤트별 진동 패턴, **주의구간 사전 경고**(횡단보도, 계단, 공사, 우회, 급경사), 긴급 안내 우선 표출(끌 수 없음), 다국어 UI(한·영·일·중 번체/간체), 오프라인 대응 |
| 로그인·회원 | 10~13 | 카카오·네이버·구글·애플 + 비회원, 회원 관리 API |
| 홈 | 14~17 | 기능 진입 버튼 중심 홈, 하단 4탭(홈·교통약자 서비스·즐겨찾기·마이), 실시간 안내 카드, 주변 탐색 안내("내 앞에 무엇이 있나요?") |
| 지도·검색 | 18~24 | 지도, 장소 검색, 장소 상세 접근성 정보("정보 없음"과 "해당 없음" 구분), 정류장·역 정보, 검색·대중교통·접근성 연동 API |
| 길찾기·실외 도보 | 25~30 | 경로 옵션(저상버스 우선, 엘리베이터 우선, 경사로 우선, 계단 회피, 이동거리 최소, 환승 최소), 유형별 경로, **멀티모달 경로를 하나로 표출**(구간별 다른 SDK가 담당해도), 실외 도보 SDK 연동 |
| 지하철 실내 내비 | 31~34 | 실내 측위 SDK, 경로 이탈 자동 재탐색, 실내 경로 API, 실내 지도 타일과 층 피커 |
| 저상버스 | 35~39 | 예약·변경·취소(50m 접근 시 확정, 30분 미접근 시 취소), 상태·이력, 탑승 알림·하차 안내, 예약 중계(외부 예약 시스템), **혼잡도 기반 예약 안내** |
| 불편신고·마일리지 | 40~45 | 현위치 기반 신고(유형, 위험도, 접근 방향), 처리 결과, 마일리지 조회, **티머니GO 마일리지 지급 요청** |
| AI 음성 안내 | 46~48 | 폐쇄망 엔진 호출 대화형 안내, 주변 지물 탐색, **통신 끊김 시 온디바이스 음성 처리 전환** |
| 교통약자 서비스 | 49~55 | 서비스 목록, 접근성 정보, 청계천 시설물, 지하철 도우미 전화, 휠체어·유모차 길안내 프리셋, 엄마아빠택시, 콜택시(1588-4388)와 복지콜(1600-4477) 전화 연결 |
| 즐겨찾기·마이 | 56~62 | 즐겨찾기(경로는 저장 안 함), 설정 계정 보관, 마이, 언어 설정, 약관·공지, 개인화 동기화 API |

기능 35번의 예약 규칙은 "현행 앱 규칙 기준"이며 취소 연계 규격은 협의 중이다. ([[seoul-donghaengmap-existing-app-v2]])

## 2. 백엔드 기능 (LBS테크 정의, 23건 = 필수 21, 선택 2)

| 기능군 | BE-ID | 요지 |
|---|---|---|
| 보행 경로 API(현행) | 01~04 | 보행 경로 탐색 API 유지, 보행 유형별(시각장애인·수동·전동 휠체어) 맞춤 경로(계단 회피, 경사, 보도 폭, 점자블록), API 키(`x-api-key`) 발급·인증, 재탐색 응답 성능 |
| 통합 경로 서비스(신규) | 05~11 | 걷기+버스+지하철 통합 경로 API(기존 서버와 분리), **대중교통 어댑터**(지금은 ODsay, 본사업에서 아로 전용 API로 교체해도 어댑터만 교체), 도보 구간 스티칭(아로 경로의 도보 구간을 보행 엔진의 실제 길안내로 채움), 지하철역 출입구 좌표 변환, 교통약자 기준 경로 점수화, 응답 형식, 폴백(외부 장애 시 도보 단독 안내) |
| 보행 네트워크 데이터 | 12~14 | 교통약자 보행 지도 데이터(경사, 보도 폭, 계단, 점자블록, 표고), 접점 데이터(정류장 표준 ID), **보행 지도 갱신 체계 DAR-006**(시민 신고와 현장조사 검토·승인·롤백) |
| 연계·산출물 | 15~17 | 인터페이스 명세서 SIR-001, 데이터 연계 정의서와 데이터 모형, 파트너사(아로, 파파, 아이나비) 연동 |
| 운영·검증 | 18~19 | 고정 IP(ODsay는 등록 IP만 허용)·키 보관·로그·모니터링, **시범역 1곳(예: 시청역)** 통합 연계시험 후 확대 |
| 선택 | 20~21 | 실시간 정보(저상버스 여부와 도착 시간) 반영, 경로선 정밀 보정 |

역할 분담 전제: 경로 통합과 순위 결정은 LBS테크, 대중교통 계산은 **아로**, 실내는 **파파**, 서버 인프라 운영은 아이나비. ([[seoul-donghaengmap-lbs-collaboration]])

## 3. 내비게이션 SDK 기능 (FR-01~29, 필수 27 + 선택 2)

| 기능군 | 요지 |
|---|---|
| 경로 탐색·변환 | `GET /pathfinder`로 보행 경로, GeoJSON → `Directions` 도메인 변환, 유형 파라미터 `service`(blind/auto/manual), API 키 외부 주입 |
| 세션·경로 추종 | initialize/start/pause/stop, 위치 스냅-투-루트, 이탈 > 도달 > 접근 > 중간 안내 우선순위, 이탈 시 재탐색 |
| 안내 생성·3채널 | 안내 문구(UtteranceBuilder: Road×Maneuver×거리×시설물), TTS, 햅틱(좌 1000ms, 우 [100,300,100,300]), 시각·음성·햅틱 동시 fan-out, 다국어(ko/en) |
| 상태·진행도 | `StateFlow<NaviUiState>`, `SharedFlow<NaviEvent>`, iOS Flow 구독 브릿지(SKIE 또는 KMP-NativeCoroutines), 진행률·ETA, 기하·측지 연산 |
| 가이던스 UI | Android Compose, iOS SwiftUI |
| 지도(네이버, 경로선 전용) | PathOverlay, 현위치·방위, 카메라 추종 |
| 플랫폼·운영 | expect/actual 위치 소스, 시뮬레이션 모드, `NaviConfig` |

SDK는 **KMP**로 만든다(WBS 2.2). ([[seoul-donghaengmap-wbs]], [[kmp-cmp-adoption]])

## Open Questions

- 백엔드·SDK의 WBS 번호(2.3.x, 2.2.x)는 제안 상태이며 회사 WBS에서 확정이 필요하다고 원본이 밝힌다.
- 실외 내비 SDK의 지도가 네이버(경로선 전용)이고 메인 앱 지도는 별도인지는 문서에 명시되지 않았다. ^[ambiguous]
