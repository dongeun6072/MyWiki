# 대구 보행자 신호등과 AI 횡단보도 연계 (2023)

2022년에 대구 **교차로 신호등**(잔여 시간) 연동을 만들었고([[daegu-traffic-light-protocol]]), 2023년에는 **보행자 신호등과 AI 횡단보도**까지 넓혔다. 앱 쪽 기능은 "AI 안전통합 횡단보도 플랫폼 & 제보하기 리뷰"(2023-07~09)로 [[inavi-air-feature-history]]에 있고, 서버 API는 `/trafficLightList`, `/trafficLightStatus`, `/trafficLightWalker`다. ([[inavi-air-api-detail-spec]]) 담당자 이름과 서버 URL, 호출 키는 적지 않았다.

## 구성 주체

| 주체 | 역할 |
|---|---|
| 아이나비 선행기술 팀 | 대구 신호등 서버와 Agent 서버 규격(프로토콜), 데이터 유입 확인 |
| 아이나비 콘텐츠사업그룹 | 대구시 사업 창구. **테이큰소프트**가 구축하는 "AI 안전통합 횡단보도 플랫폼" 인터페이스 정의서(`AI2023-DD-02`)를 전달 |
| 모빌리티Tech그룹 | 에어 앱·Agent 개발 |
| 품질운영센터 | 실차 코스, GPS 로그, 영상 |
| 도로교통공단 | 신호 연계 서버 (신호 정보 원천) |

## 시간순

| 시기 | 내용 |
|---|---|
| 04-11 ~ 28 | **대구 신호등 안내 위치 추가**: 중복 지점을 정제한 **90건**(앞서 받은 건까지 총 91건, 대전 제외)의 교차로 데이터. 구축 커버리지는 대구광역시 중심(데이터 취득일 4/10, 4/18). 방향 코드가 **음수 값**인 예외 교차로 9곳이 따로 정리됨 |
| 06-29 ~ 07-06 | **신호등 알림 실차 출장**(코스, GPS 로그, 영상). 잔여 시간 안내 이슈 보고: 개발 쪽은 "직진"이 항상 내려올 것이라 가정했는데 `roadType`에 직진이 없는 경우가 있는지 확인 요청. 정상 케이스 가정은 `좌회전 + 직진 + 보행자`, `직진` 두 가지이고, 진행 코드 목록별 샘플과 기대 화면이 필요하다고 요구 |
| 07-04 ~ 12 | AI 횡단보도 플랫폼 인터페이스 정의서와 "횡단보도 전달 정보" 문서 수령. 문서에는 **남은 시간(`remainingTime`)** 이 빠져 있었으나 추가 요청해 현재 들어옴. 인프라가 덜 구축되어 속성이 빈 값인 상태로 호출만 성공하는 기간이 있었음 |
| 07-19 ~ 22 | 테이큰소프트가 준 URL에서 데이터가 들어오지 않음(7월 11일에는 유입 확인). 8월에도 테스트 URL, 운영 URL 모두 데이터가 없고, 키가 6/21과 7/20 두 개 전달된 것의 변동 여부 확인 요청 |
| 07-26 | **보행자 신호등 프로토콜 v0.7 → v0.8**: 응답 코드 추가, 응답 데이터 수정 |
| 08-22 | **v0.9**: 엔진 API 타입 변경으로 Boolean을 받던 구간이 **Integer**로 변경(문서에 노란 음영 표기). 테이큰소프트는 Integer 대신 **String**으로 응답 중이라 수정 요청 |
| 09-05 | 대구시 API 횡단보도 정보 정상 수신 확인, 횡단보도 목록(노드명, 노드 ID, 위도·경도) 확보 |
| 09-12 | **교통정보 상용 서버에 횡단보도 API가 없어** 10월 중순까지 Agent에 에러 로그가 쌓일 상황. 상용 서버에는 10월 중순에 "교통정보 서버"만 패치하기로 했고, 앱은 응답 코드가 999(에러)여도 문제없음을 확인. 그래서 Agent의 해당 호출 주석 처리 배포는 취소됨 |
| 09-21 ~ 22 | 도로교통공단이 **신호 관련 서버 7대 교체**(9/22 10:00~13:00)로 신호등 서비스 중단을 통보. 담당자 한 명에게만 전달돼 공유가 늦었던 사례 |
| 09-25 ~ 10-10 | 대구시 AI 횡단보도 정보 연계 **1차 필드 테스트(9/25)**, 내부 테스트(10/5, 센터에서 가상 데이터로 모의 주행), **우회전 보행자 정보 연계 기능 테스트 시나리오** 문서를 대구시 센터 시스템 개발사에 전달. 대구시 쪽 테스트 8회 중 **2회만 정상** → 추가 테스트 협조가 어려워 QA가 자체 확인 |

## 앱 동작 확인 (10월)

- 교차로 정보는 정상 계산되어 **교차로에 신호등 마커**가 표시된다.
- 좌회전이 아닌 한 교차로 정보가 표출되면 서버를 호출한다. 한 교차로에서는 "보행자 주의" GUI가 정상 표출되었고 다른 교차로에서는 표출되지 않아, 서버 호출 여부와 테스트 경로, 앱 종료·재시작 시점을 대구시 쪽에 확인 요청했다.
- 대구시 쪽 테스트 시 GPS 로그를 확보하는 방법(환경설정 → 버전 정보에서 숨은 터치 시퀀스로 로그 저장 팝업)이 안내됐다.

## 해석

- 연계 데이터는 **서버 규격 변경이 잦았다.** 응답 코드, Boolean/Integer/String 타입, 남은 시간 필드가 단계마다 바뀌어 규격서 버전(v0.7~v0.9)과 실제 응답이 어긋난 구간이 길었다. ^[inferred]
- 외부 시스템(대구시, 테이큰소프트, 도로교통공단)이 일정을 좌우해 서비스 시점이 10월 중순으로 밀렸다. 이는 [[seoul-donghaengmap]]의 외부 연계 일정 위험과 같은 패턴이다. ([[seoul-donghaengmap-design-audit]]) ^[inferred]

## Open Questions
