# 드로잉런 dev 슬랙 채널 연표 2026

[[projects/drawing-run-sdk/drawing-run-sdk]]의 내부 개발 논의 채널이다. 2026-02-23에 PoC 개발 논의용으로 열렸고, 구성원은 부문장급 리더, 프로젝트 PM, 앱 개발자 2명, 탐색 서버 담당 등이다. 사람 이름은 역할로 썼다. 서버 주소, API 키, 라이선스 키, 공유 문서 링크는 채널에 있었지만 옮기지 않았다.

기술 질의응답은 [[projects/drawing-run-sdk/references/drawing-run-sdk-integration-qna-2026]]에 따로 정리했다.

## 연표

| 날짜 | 내용 |
|---|---|
| 02-23 | 채널 개설. 기존 도보 탐색 문서를 공유하며 도보 탐색 서버 가동 여부, 최대 경유지 수, 좌표열을 인접 도로로 매칭(스냅)하는 기능이 가능한지 문의 |
| 03-05 | 삼성생명 미팅 결과 공유: 코스 생성은 "지도 위 자유 그리기 + 도보 경로 탐색"을 검토 중이고, 도형(쉐입)으로 경로 생성이 가능한지 추가 검토 요청. 개발 서버 접속 정보와 API 문서(개발 버전이라 갱신 필요)가 전달됨 |
| 03-13 | 탐색 테스트 중 "확장 가능 경유지 개수 초과" 에러(코드 1000)가 생김. 약 200개까지 탐색되는 것을 확인했고, 개발 서버 사양상 경유지 300개 이상이면 CPU·메모리가 위험해 **최대 200개로 조정**됨 |
| 03-19 | 고객사에 공유할 기능 검토 내용 정리 → [[projects/drawing-run-sdk/references/drawing-run-poc-course-generation-review-2026]] |
| 03-27 | 드로잉런 서비스 플로우(안) 공유: 혼자 달리기와 함께 달리기(챌린지), 준비 → 기록 → 결과 → 공유 4단계 |

| 04-07 | 삼성생명 본사에서 미팅(문서 반출이 어려워 현장에서 진행) |
| 04-08 | 1차 오픈 범위에서 **함께 달리기**(코스 트래킹, 코스 안내, 완주 판별) 제외 |
| 04-09 | 삼성생명용 Jira 스페이스와 Confluence 스페이스 생성, 제공 데이터 항목 검토 내용 공유 |
| 04-10 | 1차 범위에서 **지도 제외**(삼성생명 의사결정, 지도는 삼성생명이 구현). 직접 구현에 대비해 지도 API 스펙 사이트 공유 |
| 04-16~17 | 공수 등록 프로젝트 확인(Maps 플랫폼 서비스 공급 사업의 "걷기 서비스 고도화"), API 인터페이스 문서 초안 공유 |
| 04-20 | 개발 중 확인 사항 공유(고도, 랩 페이스, 페이스, 테스트 앱 기준) → [[projects/drawing-run-sdk/references/drawing-run-sdk-scrum-2026-04-to-05]] |
| 04-27~29 | 3rd party 데모 앱 준비(아이콘, 샘플 앱 배포, 테스터 초대), SDK 용량 확인 요청 |
| 05-13 | 고객사 테스트 문의: "기타 시간"이 항상 0이고 걸음 수가 "-"로 표시됨 |

| 06-05~25 | 일시정지 추가 요청과 구현, 난독화·포그라운드 서비스·경과시간 리스너 문의 → **1.0.1 배포(06-25)** |
| 07-02 | 프로젝트 PM이 교체됨. iOS 더헬스 앱 적용 시 위치 수신 문의, 서비스 오픈 목표일 7/7 |
| 07-03 | iOS **1.0.2** 배포(백그라운드 스레드 호출 시 위치 콜백 누락 수정). 고객사 앱 개발 담당자와 직접 소통하는 외부 채널 개설 요청 |
| 07-20~22 | 도보/자전거 경로선형 매칭, 도보 속도 상한 처리, 주기적 데이터 전달 문의와 pause 직후 stop 안전성 문의 |
| 07-28 | 삼성화재에서 GPS 수집·맵매칭 SDK 기능 추가를 계획 중(범위·일정은 9월 초 논의 예정) |
| 08-06 | 삼성생명이 SDK를 **스탠드얼론**으로 받아 더헬스 앱이 아닌 모니모 앱에 달리기 기능을 넣고 싶다고 문의 |
| 08-28 | 이 SDK를 쓴 서비스가 주중에 오픈됨. 초기 컨셉은 드로잉런이었으나 삼성생명 헬스사업부 방향이 바뀌어, 의료정보 데이터 서비스와 연동하는 **"맞춤형 달리기"**(사용자 건강정보 기반 달리기 루틴 추천)로 확정돼 오픈이 예상보다 크게 늦어짐 |
| 10-13 | 모니모 건강탭에 달리기 기능을 넣는 포팅 중인데 대상 앱의 최소 스펙이 Kotlin 2.0.0 / AGP 8.7.1이라, 전달한 SDK(Kotlin 2.2.0 / AGP 8.11.2)의 최소 버전을 낮춰 줄 수 있는지 문의 |
| 10-15 | iOS에서 `startTracking` 반환값이 들어오지 않는다는 문의(GitHub 샘플의 SDK에는 반환값이 있음). 사용 가이드 요청 |

## 읽을 점

- 이 프로젝트는 PoC(코스 생성)에서 SDK 납품으로, 다시 건강 서비스 연동 피봇으로 두 번 방향이 바뀌었다. 2차(안내 데이터, 음성 안내)가 실제로 진행됐는지는 10-15까지 채널에 나오지 않는다 → [[projects/drawing-run-sdk/references/drawing-run-phase2-voice-guidance-and-meetings-2026]].
- 후속 수요는 두 갈래다: 모니모 앱으로의 SDK 확장(스탠드얼론, 낮은 빌드 도구 버전)과 삼성화재의 GPS 수집·맵매칭 SDK.
- 담당 팀이 KMP로 만든 SDK라 호스트 앱의 Kotlin/AGP 버전과 맞물리는 문제가 반복해서 나올 수 있다. ^[inferred] 관련 경험은 [[concepts/kmp-cmp-adoption]].
