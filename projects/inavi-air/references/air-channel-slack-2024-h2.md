# Slack #01_inavi_air 대화 (2024 하반기)

에어 앱·서버·기획·디자인·안내엔진 담당이 함께 쓰는 비공개 채널(2022-07 개설)의 2024년 7월~12월 기록이다. 프로젝트 개요는 [[inavi-air]], 같은 해 운영 전반은 [[air-operations-2024]], 버전별 변경은 [[air-app-version-notes-2024]], 개발자 채널은 [[air-nsdk-dev-slack-2024-h2]]를 본다.

이 기간 채널 메시지 163건(2페이지 페이지네이션)을 모두 읽었고, 답글이 달린 스레드 84개를 전부 열어 반영했다(미열람 0). 이 중 배포 알림 봇 스레드의 답글은 주로 스토어 노출 확인, 단계별 유입률 모니터링, 검증 중 이슈 공유였고 해당 내용은 아래에 반영했다. 사람 이름은 쓰지 않고 역할로 적었다.

## 1. 앱 배포 이력

배포 알림은 App Tester(Android 내부), TestFlight(iOS 내부), Play Console(내부 테스트 트랙 등록, 내부 테스트 검증 제출, 검증 제출, 프로덕션 단계 출시), App Store(심사 제출, 출시) 순서로 올라온다. 한 버전 안에서 빌드가 여러 번 올라가며, 아래 표는 버전 단위로 압축했다. 앞의 숫자는 날짜(월-일)다.

- 패턴: 월 1회 안팎의 정기 패치. Android는 내부배포 → 내부 트랙 → 검증 제출 → 프로덕션 80~85% → 100%(약 2~3일 뒤)이고, iOS는 TestFlight와 같은 날 심사에 제출해 3~5일 뒤 출시된다.
- 버전 번호는 Android 03.05.40→47, iOS 03.05.18→24로 올랐다(빌드 번호는 원문 참조). 07-02~09-27 구간의 03.05.20(iOS)은 TestFlight 알림이 이 기간에 없다 ^[inferred].
- 출시 후 모니터링: 출시 알림 스레드에서 앱 담당이 단계별 유입률과 이슈 유무를 올렸다. iOS 03.05.18은 28%→67%, 03.05.19 65%, 03.05.20 7%→36%, 03.05.21 5%→37%→69%, 03.05.22 32%→69%→84%, 03.05.23 4%→45%, 03.05.24 38%→48%→69%(제보하기 하단 팝업 관련 신규 이슈 3건 발생). Android 03.05.42는 30%→42%→50% 후 이슈 없어 100% 진행, 03.05.43은 28%→31%→43%, 03.05.45는 39%→42%, 03.05.46은 32%, 03.05.47은 32%→50%로 모두 특이 이슈 없음으로 보고됐다.
- 03.05.40 검증 단계: 301388 내부 테스트 검증 중 모의주행과 무관하게 표출 테스트가 가능함을 확인했고, 301389에서 안정성 이슈(앱 종료 후 ANR, 로그상 Google Play Wallet 부분)가 올라와 같은 증상의 301390은 구글 관련 라이브러리 의존성을 갱신해 다시 올렸다. 출시 일정은 장마·태풍 기간과 외부 공유 일정을 고려해 정하도록 사업 쪽이 요청했다 ^[inferred].
- 03.05.40 출시(07-22) 후 터널 구간 AA 주행 중 화면이 멈추고 응답 없이 종료되는 현상이 같은 구간에서 2회 보고됐고, Firebase에서 같은 유형의 비정상 종료(사용자 40명, 이벤트 52건)를 확인했다. 원인은 주행 중 안내엔진이 VMS 정보를 받을 때 탐색 결과의 VVMS 리스트에 같은 ID가 없는데도 리스트 값에 접근한 것이었고, 예외 처리를 넣은 핫패치(03.05.41)로 해결했다. 구글 플레이 출시 비율을 10%로 낮춘 뒤 핫패치를 진행했다.
- 03.05.41 검증 제출은 Target SDK 34 미만 앱이 검증을 통과하지 못하는 문제 때문에 Target SDK를 34로 올려 빌드한 것이다. 모니터링 중 Android 14 비정상 종료(사용자 10명, 이벤트 40건)가 SKP 피드 화면(라이브러리)에서 재현돼 공유됐다. 이후 03.05.42 내부배포 한 빌드는 이 라이브러리가 Pop 기능에 쓰는 권한을 제거(에어는 해당 기능 미사용)한 버전이다.
- 03.05.19(iOS) 출시 후 HUD 추가분의 iOS 17.4 타깃 설정 누락으로 17.4 미만 단말에서 100% 비정상 종료(357건/38명)가 발생해 03.05.20에서 수정했다(앱스토어 검증이 끝난 것으로 보여 빠른 출시를 요청).
- 03.05.43 검증 시 에어봇 내부 베타 테스트 계획을 사업 쪽이 문의했다. 결제 수단(카드) 정보를 받으면 앱을 다시 빌드하고 의견은 기존처럼 구글 시트로 수집하기로 했다. 에어봇 지출결의는 10월분이 결재 완료됐고, 올해(10~12월)는 법인 결제 수단으로 진행, 내년에는 사업계획에 1년치 비용을 반영해 품의가 필요하다.
- 03.05.45 내부배포: 음성 끝이 끊기는 "틱" 소리 개선을 위해 오디오 음성 데이터 끝에 붙이는 스킵 사운드 BufSize를 1000에서 5000으로 늘려 재배포했다. 단말·BT·스피커·AA 에뮬레이터에서는 재현되지 않아 개선 여부를 직접 확인하지 못했고, 사업 쪽 확인 결과 거의 동일해 보인다고 했다. BT 연결 시 도입부 잡음은 개선됐다.
- 03.05.47 검증 시 Android Auto 안정성 개선은 최신 Car App Library(1.4.0) 적용이다. AA 주변 주유소/충전소 검색 결과에서 경로선이 두껍게 보이는 현상은 맵 상태별 MapView에 경로선 두께 공통값(0.7f)을 넣어도 선택 경로선 ID(`setDriveRoute` 또는 `SelectRouteline` 사용)가 없으면 반영되지 않기 때문이며, 지도 이동 시 엉뚱한 위치로 가는 현상은 장소 목록 가시성 콜백의 시작/끝 인덱스가 초기에 `-1, 0`으로 와서 생기고 목록을 스크롤해야 정상 값이 온다. 첫 항목으로 직접 이동시키는 방식으로 개선을 검토했고, 유사 건은 Jira 티켓으로 관리하기로 했다.
- 03.05.21 TestFlight 두 빌드는 각각 발랄한 음성 적용 버전(개발서버 확인용), 에어봇 사용성 테스트 배포였다. iOS 03.05.20은 CarPlay iOS 17.4 미만 단말 비정상 종료 수정을 담았다. iOS 03.05.18 TestFlight는 CarPlay HUD TBT 표출, 환경설정 자주 묻는 질문, 부드러운 음성, 자사 HUD 목적지 거리 표출 사양을 담았다(CarPlay HUD는 차량 미지원으로 음성 안내만 확인).
- 각 패치의 스토어 출시 노트는 기획·디자인 담당이 Confluence에 작성해 채널로 알렸다(07-17, 08-20, 09-12, 12-11, 원문 링크는 미수록). 12월 패치 이후 출시 노트는 AI 문구를 뺀 판본(10월)이 따로 있었다.

## 2. 에어봇(생성형 AI) 도입 결정과 운영

- 7월 25일 차기 패치 항목이 "메인화면 리뉴얼"에서 "생성형 AI(ChatGPT 연동)"로 바뀌어 기획·디자인 계획을 다시 세웠다. 8월 6일과 8월 8일 에어봇 리소스와 시나리오 JSON이 전달됐다(백그라운드 이슈로 수정본 재전달).
- ChatGPT API 과금을 위해 법인 결제 수단 확인이 필요했다(9월 19일). 전략팀은 가볍게 POI 문의에 답하는 수준을 기대했고 점진 확대로 정리했다. 사업 쪽 요구사항은 이번에 포함되지 않았다. 비용 산정을 전체 DAU 기준에서 일 적립자 약 3천 명 기준(월 약 108달러 수준)으로 조정했다.
- 10월 10일 결정: 에어봇이 고객서비스에 적합한지 검토하기로 하고, 10월 11일 패치는 AI 기능을 제외한다. 서비스 버전은 서버 `ai_flag=false` 유지, 내부 테스트 버전은 앱에서 `ai_flag=true`로 하드코딩해 빌드하고 의견 수렴 시트를 준비한다. 스토어 문구에서 AI를 뺐다.
- 10월 18일 에어봇 베타에서 링크 줄간격이 좁아 클릭이 어렵다는 의견이 나와 줄간격을 6pt 기준으로 시험 조정했다.
- 11월 14일 에어봇 포함 앱을 배포하면서 서버 에어봇 필드를 ON으로 변경(오전 11시 처리, iOS/Android 노출 확인).
- 11월 29일 오픈 후 수치: 요청 총 1,519회(11/14~), 일 최대 500회(11/15), 최근 일주일 일평균 64회, 총 비용 약 0.55달러, 일 최대 0.12달러. 오픈 후 2~3일 뒤 사용이 줄었고 앱에서 적극 안내하지 않은 영향으로 해석했다 ^[inferred]. GA 기준(11/14~11/29) 에어봇 페이지 조회 1,024회, 사용자 433명.
- 고객사 보고용으로 질문 로그(추천 질문 vs 직접 입력 구분)와 답변 로그가 로그 요청 항목에 들어갔고, 질의응답 로그는 질문 내용과 검색어 목록만 보내는 방향으로 정리 중이었다(12월).
- 12월 패치용 서버 항목: ChatGPT 모델 선택 필드 `gpt_model`(0: 4o-mini 기본, 1: 4o)과 최초 로그인 적립 캐시 필드 `first_login_cash`(기본 500)를 `/serviceGate` 응답에 추가(11-20 공유, 12월 중 개발서버 반영 후 상용 반영).

## 3. 아바티 포인트홈(신규 캐시 버튼)

- 7월 2일 iOS는 appid/appSecretKey 신규 발급 요청과 플로팅 버튼 위치 조정 문의, AOS는 기존 키로 초기화 시 포인트홈 일부 기능이 동작하지 않는 문제를 업체에 문의했다(키 값은 원문에 있음, 미수록).
- 7월 23일 에어캐시 전환 flow(`/cashButton/cashConversion`)를 다루는 긴 스레드(답글 58개)가 이어졌다. 요지는 다음과 같다.
  - 기존 전환 API는 클라이언트가 보낸 거래 ID를 아바티 검증 API로 확인하고, 응답의 교환 상품 ID에 따라 서버가 에어캐시를 적립하는 구조다.
  - 신규 연동 가이드는 검증 경로가 `verify`에서 `verifyV3`로 바뀌고 Basic 인증 토큰을 앱이 만들어 전달(appId와 appSecretKey 조합)하는 점이 다르다. 서버는 기존 규격에 버전 flag와 `basicToken` 파라미터를 추가해 V3로 연동했다.
  - 테스트 중 630(캐시버튼 연동 오류)이 반복됐고, 원인은 (1) 토큰 앞에 "basic "이 중복으로 붙은 점, (2) 교환 상품 ID가 서버 DB에 없어 지급 포인트가 null이던 점, (3) 데이터 입력 중 공백이 섞인 점이었다. 상품 목록은 상용/개발과 OS별 ID가 다르므로 둘 다 등록했다.
  - 전환 실패 시 취소(rollback) 호출도 V3에서는 `rollbackV2`로 처리하도록 서버를 수정했다.
  - 8월 초 서버 에이전트 상용 반영 완료(에어연구소 필드 추가 HUD/생성형 AI, 아바티 포인트홈 적용). 업체가 8월 말 전후에 에어캐시 전환 페이지를 추가할 예정이라 앱 업데이트 일정을 8월 말(20일 이후)로 잡았다.
- 10월 23일 사용자 통계 추출을 위해 "아바티 광고 에어캐시 적립" 관련 앱 호출 API가 무엇인지 서버 담당이 문의했다.
- 7월 12일 iOS 캐시 적립 내역 화면의 "7월 소멸 예정 캐시" 항목이 서버와 연동되지 않는 문제가 보고됐다(Android는 연동). 12월 10일에는 Android 개발폰에서 아바티 캐시 버튼이 동작하지 않는 현상이 나와 다른 단말 확인을 요청했다(iOS 정상).

## 4. 캐시 정책·푸시·로그인 유도 (10~12월)
