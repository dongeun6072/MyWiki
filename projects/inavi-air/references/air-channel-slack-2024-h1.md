# Slack #01_inavi_air 대화 (2024 상반기)

아이나비 에어 x Auto x CarPlay 비공개 채널(2022-07 개설)의 2024년 1월~6월 기록이다. 프로젝트 개요는 [[inavi-air]], 같은 시기 운영 기록은 [[air-operations-2024]], 버전별 변경은 [[air-app-version-notes-2024]], NSDK 쪽 채널은 [[air-nsdk-dev-slack-2024-h1]], SKP 광고 스크럼은 [[air-skp-ad-scrums-2024]]를 함께 본다.

이 기간 채널 메시지는 223건(허들 시작 알림 포함)을 모두 읽었다. 답글이 달린 스레드는 112개였고 전부 열어 읽었다(미열람 0개). 내용이 없는 확인 댓글뿐인 스레드(허들 알림, 일부 배포 알림)는 '확인함'으로 셌다. 사람 이름은 쓰지 않고 역할로 적었다. 11절까지는 본문 흐름, 12절은 스레드 전수 확인으로 보강한 내용이다.

## 1. 개발 조직·업무 방향

- 2월 12일~3월 8일 기획·개발 총괄이 출장으로 자리를 비워, AIR/NaviSDK 업무를 앱 개발 책임자 주도로 운영했다(02-08).
- 5월 7일 앱 개발 일부 인력의 에어 업무 비중을 줄이고 Connected, ACE 3.0 쪽 비중을 늘린다고 재공유했다(05-07). 4월 12일 총괄이 다른 곳으로 이동한다는 인사가 있었다.^[inferred]
- 스크럼은 주 1회 허들 또는 회의실에서 진행했고, 4월 초에는 공유 오피스(강남)에서 진행한 적이 있다.

## 2. DP(지도) 엔진 이슈와 배포

DP 엔진 담당자가 엔진 zip을 채널에 올리면 앱 개발자가 AOS/iOS에 적용해 테스트하는 흐름이다.

| 0.0.6.2b | 01-17 | iOS | 엔진 내부 스레드의 CPU 과점유 재빌드(이전 빌드만 usleep이 yield로 컴파일된 원인은 조사 중) |

### 2.1 메모리 증가 이슈(1~3월)
- 01-18 iOS CarPlay 주행에서 지도 정지 상태에서도 메모리가 계속 증가(2분 약 386MB에서 3시간 27분 약 1.2GB). 메모리 누수 여부를 DP 엔진 담당자에게 문의했다.
- 원인 분석: 지도를 이동하지 않아도 증가하며, 광고(구글 광고)를 일정 수(약 5개) 이상 미리 받아두면 컨텍스트가 정상 해제되지 않아 증가하는 케이스를 확인했다. 앱 쪽에서 광고를 일정 개수 이상 받지 않도록 개선했다. 엔진 제거·광고 제거 시에는 증가하지 않았다. 맥북 프로 환경에서는 이전 버전(5.7ab, 6.0, 6.2)에서도 증가하는 별도 현상이 있어 엔진 단독 해결에 한계가 있다고 봤다(03-13까지 논의). 빌드 03.05.15(414)로 엔진 코드를 받아 실행을 확인했다.

### 2.2 종료·초기 실행 크래시(4월)
- AOS에서 DP 관련 크래시가 유입(04-29, Crashlytics OS 8~14, 여러 기종). 앱 종료 시 호출하는 destroy 계열 함수에서 발생하는 것으로 보였고, 개발 단말에서는 재현이 어려웠다.
- 해결 방향: 0.0.6.3a에서 다운로드 스레드를 하나로 통합했는데 매니저 클래스보다 먼저 스레드가 제거되며 생기는 문제로 파악해 통합을 취소하고 스레드 개수만 줄였다(0.0.6.3c). 앱 삭제 후 첫 실행 크래시는 10회 이상 테스트에서 재현되지 않았다. iOS도 같은 최초 실행 크래시를 0.0.6.3b로 수정했다. 이후 AOS 상용 반영분 기준 Crashlytics 이벤트 약 1.2천, 사용자 약 1.1천 규모로 보고됐다.^[ambiguous]

### 2.3 경로선·화살표 개선(2~5월)
- 02-15 요청: 경로선 화살표를 경로선보다 작게(약 90%), 11레벨까지 표시, 차기·차차기 화살표 색 변경(타사 지도 참고). 스레드는 04-08까지 이어졌다.
- 02-20 AOS 기본 차량 크기 조정 값: 폰 3D 1.1, 2D 1.0 / Android Auto 3D 0.85, 2D 0.75.
- 4월 사용 후 평가(04-15): 주행 시인성은 개선, 2차 화살표 색은 흰색 계열 권장, 2D 회전/고정뷰 경로선 두께 축소, 11에서 10레벨로 바꿀 때 화살표가 길게 늘어나 경로선을 가리지 않도록, 화살표 끝이 원형으로 벗어나는 현상 개선을 요청했다. 이후 0.0.6.4a로 화살표 길이 축소·꼬리 처리를 반영했다.
- 03-27 교통정보 범례가 바뀌어 DP 엔진에도 범례 변경을 요청했다(04-05까지 논의).
- 차차기 화살표 외곽선 색은 디자이너가 차기 화살표와 같은 형태에 기존 차차기 색의 외곽선으로 정리했다(파랑 계열).^[inferred]
- 그림자 효과: 안드로이드 에어 기준 먼저 적용, iOS CarPlay에서 프레임 저하와 버벅임이 발생해 displaylink 타이머 적용을 시도했다가 2차 테스트에서 취소(기존 사양 유지)했다. 그림자 텍스처 1024에서 512로, 데이터 다운로드용 스레드 8+18개에서 6개로 줄였다. 항공지도 테마 사용 시 죽는 문제도 수정했다. 상세 일정은 정식 발행 후 개선 사항으로 넘겼다.

### 2.4 기타 엔진 질의
- 03-08 CTT(교통정보 라인) 표출 사양과 캐시 정책 확인, 03-11 AOS에 추가된 `getNearestVertexIndex`를 iOS에도 추가 요청(이후 iOS에 추가 반영, 05월 말 확인).
- 03-29 ADAS 적용 검토 중 DP 엔진 기술 검토 요청(ADAS 사양서의 일부 항목), 4월 1일까지 일정 회신 논의.
- 05-30 `setCarPos` 인터페이스 매개변수가 9개에서 11개로 바뀌어 컴파일 오류가 났고, 이전 경로선 전체 표시 이슈 수정 때 바뀐 인터페이스라는 답을 받았다.
- 04-04 CarPlay 주변검색 pressed 이미지는 시스템이 노말 이미지에 자체 효과를 주므로 색상 있는 pressed 이미지는 사양상 어렵다고 확인하고, 이미지 `_n`, `_p` 접미사를 없애고 하나로 통일하는 안으로 합의했다(03-22). 디자이너가 Auto/CarPlay 구분 리소스를 전달했다.

## 3. Auto / CarPlay 이슈

- 안드로이드 오토에서 교통요약바가 표출되지 않는 이슈와 고객 댓글(04-10), 전체 경로 보기 시 요약 정보 배경이 UI 영역과 맞지 않고 경로가 상하로 움직이는 현상 확인 요청.
- 01-12 CarPlay·Auto 모두 화면 영역 대비 표출되는 지도 영역이 작아지는 문제(대시보드 수준으로 전방 위치가 보여야 함)의 스케일 개선을 DP 엔진 담당자에게 요청, 스레드는 02-15까지 이어졌다.
- 04-04 VoE: Android Auto에서 고객사 헤드유닛 연결 시 현위치 직선거리가 1만km 이상으로 표시. 원인은 맵매칭 초기화 직후 좌표가 아직 세팅되지 않은 타이밍 이슈였다. 앱 실행 후 매우 빠르게 최근 장소 화면에 진입할 때만 재현되며, 좌표를 로컬 Manager(주기적으로 맵매칭 좌표 갱신)를 통해 계산하도록 바꿔 해결했다. 집·자주 가는 곳이 있으면 메인 화면 서버 요청 때문에 타이밍이 늦어져 정상 표출되던 점이 재현 어려움의 이유였다. 담당 연구원이 실제 헤드유닛에서 테스트·디버깅했다.
- 03-11 iPhone 홈 화면 위젯에서 집/회사 외 영역을 눌러 앱을 실행하면 지점 설정 팝업이 뜨는 문제 보완 요청. 01-24 직접 설치한 iOS 테스트 버전에서 위젯 정보가 표출되지 않는 현상 확인 요청.
- 02-27 USIM 체크 로직 검토: AOS는 SIM 상태 변경 계열 액션을 Receiver에 등록해 팝업을 띄우고 있어, 원인 액션을 특정할 수 없으므로 로직 제거 방향으로 검토하기로 했다.
- 01-16 iOS에서 새 엔진 적용 후 백그라운드에서 약 1분 내외로 앱이 종료되는 현상(iPhone 11 Pro, iOS 17.2.1) 보고, 02-21 iPhone XR에서 초기 실행 후 연속 2회 비정상 종료 뒤 정상 동작 사례.
- 02-12 안드로이드 쿠폰함 진입 시 비정상 종료: 쿠폰함 조회 API 응답의 `ProductName`이 null이어서 `Brand` 파라미터(null 불가)에 세팅하다 죽는 것으로 확인했다. 서버 원인은 사용자 쿠폰 테이블에는 데이터가 있으나 상품 테이블에서 해당 상품이 사라져 조인 결과가 null로 내려간 것(아이스카페 아메리카노 상품 코드 변경 이력 후 발생, admin에서 상품 삭제·변경 시 같은 이슈 재발 가능)이었다. 상품 테이블에 해당 상품 레코드를 추가해 해결하고, 서버에서 재발 방지 작업을 하기로 했다. 03-05 `/productDetail`에서 mdn이 내려오지 않는 케이스 확인 요청도 있었다.

## 4. SKP 광고·보상·캐시

- 배경: 광고 계약 지연 속에 앱 선 반영을 검토했다. 03-07 서버 1안(서비스메인 `/serviceGate`에 SKP 광고 활성화 flag 추가) / 2안(`/cashStampInfo` 응답에 flag 추가) 중 1안으로 정했고, 필드는 `skp_ad_status`(기본값 false로 상용 반영, 요청 시 true로 전환, 이후 기본값을 true로 변경 요청)로 ServiceGate API 규격에 추가했다. AOS는 ServiceGate 응답 이후 SKP 초기화, iOS는 `didFinishLaunchingWithOptions` 시점 초기화라 flag 기준으로 바꾸면 광고 할당 타이밍 확인이 필요하다고 보고했고, 결국 초기화는 그대로 두고 광고 요청만 flag로 구분하기로 했다.
- 02월: 보상형 광고는 오퍼월과 비슷하게 적립, 배너 형태로 표출될 때 필수 표시 정보 6가지가 있다. 적립 내역은 기존과 같이 '이벤트 참여'로 표기한다. Feed 화면에서 보상형 광고가 없을 때 상단 "0캐시 적립 가능" 영역이 남는 문제는 iOS에서 Feed 진입 시에만 판단 가능해 문구 대체를 협의했고, AOS는 영역 미표출 사양이다(02-27).
- 사업부 의견(02-07, 02-16, 03-12): 구글 광고를 카카오 비즈보드와 교체할지, 플래닛 광고를 최상단에 둘지, 메인 지면도 전면(Interstitial) 형태로 볼지, 메인 구글 광고 외 나머지는 SKP로 교체. 팝업 광고 디자인 추가 필요. 수익성은 구글이 더 낫다는 판단도 있었다. 상단 광고가 올라올 때 '광고보고 캐시받기' 이중 노출 우려도 제기(03-22).
- 02-19~02-29 SKP 포스트백 연동 가이드 협의(스레드 30건, 24건): 포스트백의 data 필드가 암호화(복호화는 개발용 키·IV 사용, 키 값은 DM 전달·미수록)되어야 하며, 복호화 결과에 `user_id`, `point`, `title`, `unit_id`, `event_at`, `action_type`, `transaction_id`, `extra`가 포함된다. 중복 방지는 적립마다 고유한 `transaction_id`를 쓰면 되고, `action_type`은 캠페인 유형 구분용으로 활용 계획이 없으면 무시해도 된다. 02-27 에이전트 상용 배포에 SKP 포인트 서버 연동(postback API), admin 상품 삭제·변경 부작용 처리, admin 캐시 상품 정렬과 앱 동기화가 포함됐다.
- 03-28 상용 테스트: 기존 광고는 정상, 신규 지면에서 적립 누락이 있어 test postback 요청 시 규격과 다른(암호화되지 않은) 값이 도착해 999 에러를 반환한 사례가 있었고, 신규 지면에는 암호화가 적용되지 않은 것으로 보고 SKP에 문의하기로 했다.
- 일정: 3월 SKP 스크럼과 개선·통계분석 스크럼 총 7주, 통계 1차 개선(전체/신규 사용자 수), 서비스게이트 SKP 광고 flag 필드, admin 정렬 필드, SKP 포스트백 연동을 일정 항목으로 정리했다(03-19).
- 6월 업데이트 항목: SKP Feed unit id 변경(동영상 광고 추가).

## 5. 캐시·포인트·상품

## 12. 스레드 전수 확인 보강

### 12.1 SKP 포스트백 연동 상세(02-19~03-05 스레드 2개)
- 연동 구조: 포스트백 수신 경로는 `/INaviAir/event/cash/postback`(개발/상용 호스트는 원본에 있음, 미수록)이고, 앱에서 SKP로 넘기는 사용자 식별(pk)은 기존 `sns_key` 암호화 방식과 같은 키로 암호화한 값을 userid로 등록한다. 에이전트 서버의 `voucherExchange`(웹용)는 보안 강화를 위해 AES로 한 번 더 암호화하는 방식이 있고, 오퍼월과 같은 구조로 진행하기로 했다.
- 규격: 요청 파라미터를 AES-256/PKCS7로 암호화하고 BASE64로 인코딩해 `data` 파라미터로 전달한다. 처음에는 다른 파라미터가 비거나 null로 오고 data에만 암호문이 오는 것이 맞는지 혼선이 있었고, 가이드 전달이 잘못되었음을 확인한 뒤 복호화 JSON을 요청 객체에 재매핑하는 로직을 에이전트에 추가했다. Content-Type은 urlencoded도 유효 규격이라 서버를 json과 urlencoded 모두 받도록 바꿨다. 응답은 HTTP status로 성공 여부를 판단하는 규격이다.
- 테스트: 개발 서버에서 postman으로 호출하면 지급은 되지만, 같은 광고 key인 `transaction_id`만 바꿔 재요청하면 반복 지급이 가능한 상태였다. 어뷰징 방지는 규격 참고(data는 위변조 방지용 컬럼으로 추정)이고, 암복호화 키와 샘플은 SKP에서 준비되면 전달받기로 했다. 적립 내역은 10캐시 두 번 추가됐는데 사용 가능 캐시에 10캐시만 노출되던 버그는 수정했다. iOS와 AOS 개발 서버 적립을 확인한 뒤 상용 암호화 키를 DM으로 받아 상용 배포(2024-03-05)했고, 03-19 일정 점검에서 상용 배포 완료로 정리됐다.

### 12.2 경로선 화살표 개선(02-15 스레드, 38건)
- 요청 3가지(90% 크기, 11레벨까지, 차기·차차기 색 변경)는 금방 가능하나 그림자 효과는 1주 정도 걸린다고 답했다. 디자이너가 차기·차차기 화살표 90% 축소와 그림자, 경로선 내부 화살표 90%, 경로선 아웃라인을 교통정보별 색(검정 기본)으로 정리했다.
- 엔진 담당자가 적용 후 수치를 조정했다(경로선 내부 화살표 80%, 차기·차차기 화살표 두께 70%, 경로선 색상은 기본색과 교통정보색 RGB를 0.4배로 어둡게). 그림자 높이는 처음 값 2를 두 배로 키웠다가 4, 3으로 조정해 3이 적정하다는 디자이너 의견을 받았다(2배는 너무 떠 보임).
- iOS CarPlay에서 그림자 적용 후 버벅임이 많았다. 원인은 displaylink 타이머와 내부 sleep(기본 60fps)의 이중 제어 및 CarPlay의 nstimer 사용이었다. displaylink로 바꿨다가 CarPlay와 앱 화면 두 개를 그리는 부하가 남아, 2차 테스트에서 취소하고 기존 사양을 유지했다. 건물·POI가 많은 지역의 부하는 개선이 오래 걸릴 것이라 했다.
- `setCarPos` 인터페이스가 9개에서 11개 인자로 늘어 AOS 컴파일 오류가 났고, Android Auto에서 안내 시작 시 크래시가 100% 재현됐다(Once_Common 태그 로그 요청 후 수정 버전으로 정상 확인). 04-04 항공지도 테마 크래시, 그림자 텍스처 1024에서 512, 스레드 8+18개에서 6개 조정이 같은 스레드에서 이어졌다. 0.0.6.3a 테스트 2차 후 iOS는 CarPlay 포함 이상 없음, AOS도 특이사항 없음으로 정식 발행(교통정보 범례 조정 포함) 요청까지 갔다.

### 12.3 DP·지도 사양 상세
- CTT 표출 사양(03-08): CTT 링크·속도 데이터는 5분마다 갱신하고 실패 시 5초 후 재시도, 옵션을 켜면 30초 후 갱신 시작, 기본은 off이며 `visible_ctt` 또는 `enable_traffic_data` 호출 시 갱신이 시작된다. 속도 색 기준(초록/주황/빨강)은 고속도로·도시고속 70/30/0 초과, 국도 40/20/0 초과, 일반도로 30/10/0 초과다. 링크 정보가 없으면 회색이다. 초기에는 메모리에 데이터가 없어 저장된 dat 파일을 먼저 읽기 때문에 실제와 다른 정보가 표시될 수 있고, 교통정보 버전이 DP와 다르면 현재 정보를 버리고 저장분을 다시 로드한다.
- 교통정보 범례(03-27): DP는 MT 기준 도로 타입, 메인은 MR 기준이라 자동차전용도로 타입은 색 표현이 어렵다. 자동차전용도로와 RoadPlus 범례에 해당하지 않는 도로, 속도 0인 도로는 회색으로 표시하는 안을 총괄이 승인했다.
- iOS 백그라운드 종료(01-16): 백그라운드에서 CPU 사용률이 높으면 OS가 앱을 종료하며, 발행본은 300% 이상이고 DP 스레드가 usleep이 아니라 sched_yield를 호출하고 있었다. 재빌드 버전은 사용량이 낮아 0.0.6.2a 재빌드로 교체해 해결했다. 같은 시기 iOS 17에서 CarPlay 턴 정보를 0.2초마다 생성·해제하던 것을 변경 시점에만 init하도록 개선했다.
- 위치 측위 종료 사양(01-12): 안전운행 모드가 아니면, 경로가 없고 백그라운드 모드가 꺼져 있거나 목적지 도착 모드이면 측위가 정지한다. 측위 정지 상태로 10분 background 유지 또는 속도 0 상태가 10분 이상이면 앱이 종료된다. 이번에 추가된 속도 0 10분 조건 때문에 기존 측위 정지 사양을 제거하거나 개선해야 하며(iOS 17에서만 종료되는 것으로 확인), 엔진 문의 후 처리하기로 했다.
- 01-10 CarPlay 배율 결정: 대시보드 경로선 120% 유지, 자동차 아이콘 90%, CarPlay는 경로선·아이콘 80%로 축소하고 화면 배율을 대시보드 수준으로 조정하는 개선을 엔진과 검토. 13레벨 제한을 12로 줄이면 아파트 동번호가 13레벨에서만 보여 확대 방법이 없어지는 문제가 지적됐다. 02-20 차량 배율은 iOS 3D·2D 1.2에서 1.08로, CarPlay 3D 0.8/2D 0.7에서 0.63으로 줄였다.
- Auto 자동 레벨(02-01): 속도 20km/h 이하 3D 13·2D 12, 20초과~110 3D 12·2D 11, 그 외 3D 11·2D 10. 턴 기준 우선 적용(차기 260m 이하, 고속도로 360m: 3D 13·2D 12 / 차차기 600m 이하, 고속도로 1000m: 3D 12·2D 11), 회전 정보가 없을 때만 속도별 레벨이다.
- Android Auto(04-10, 04-24): 교통요약바 미표출 등 세 원인. 전체경로 화면 배경이 UI 영역과 안 맞는 문제는 AA 프레임워크의 UI 영역 제어(타사도 동일)이고, 경로가 상하로 움직이는 문제는 전체경로 템플릿이 생성될 때마다 MapViewSize를 재설정해서였다(주행 데이터를 한 번만 세팅하도록 수정). 교통요약바는 ActionStrip이 보이지 않을 때 표출하는 사양인데 초기 실행 때 저장하는 높이값이 변해 표출 실패가 늘었고, 주행 화면 전용 가시영역 변수를 새로 만들기로 했다. 04-24 검증 제출 때 AA 주행 레벨은 12로 하되 사용자 조작 시 13, 14레벨까지 확대 가능해야 하고, AA 지도 보기 환경설정 연동, 휴게소 정보 미표출 확인을 요청했다.
- 03-11 getNearestVertexIndex는 경로선 화살표 개선 발행본에 포함해 iOS에 전달하기로 했다. 04-02 경로 탐색 아이콘은 에어(`inv_rt_bg_min_00`)와 CarPlay(`inv_car_rt_bg_min_00`)로 재배포, AOS에서 비트맵을 넓게 만들면 찌그러지는 문제를 검토했다. 04-04 주정차 안내는 속도 20km/h 이하, 안내 거리 100m, 음성 없이 심볼만이 현재 사양이다.

- 03-04 에어퀴즈 2차: 1차 수정본에서 common이 정상 노출되지 않고 버튼 액션별 ID를 못 찾는 버그가 있었다. ID가 겹쳐 로그인/미로그인 구분이 불가하다고 판단해 2차 수정본 맨 아래 isLogin을 true로 바꾸는 것으로 정리했고, AOS 이슈가 없으면 2차안으로 진행하기로 했다.
- 03-08 재탐색(tdata): 스마트 재탐색도 기존 재탐색처럼 앱이 전달한 Request Body 기준이며, 탐색엔진의 응답(resultCode=2)을 기준으로 생성한다.
- 01-03 최적경로 판단: 요청 파라미터 `remainTime`이 5분 이내이면 에이전트가 바로 121(목적지 부근, 재탐색 불필요)을 응답하고, 탐색엔진이 0x02(Smart 재탐색 적용 응답)를 주면 에이전트가 120(최적경로)을 응답한다. 이슈는 후자 사유로 120이 앱에 내려간 경우였다. 재탐색은 `/findMultiRoute`와 같은 파라미터에서 탐색 타입만 바꿔 `/findRouteAgain`으로 요청하며, 최초 탐색 때 엔진이 준 rdata를 rid에 매칭해 에이전트가 저장한다. 엔진이 0x02를 주면 rid/rdata를 갱신하지 않고 앱에도 내리지 않으며, 0x00이면 새 rid를 생성해 응답한다. 앱은 경로열을 넘기지 않는다. 앱(AOS)은 남은 시간 기준 임계치 오차를 1분으로 둔다.
- 쇼핑하기(01-16, 02-05, 01-26): 구매 요청은 상품 코드와 트랜잭션 ID(privateKey와 랜덤 숫자 조합)만 보내고 가격은 보내지 않으며, 에이전트에 등록된 금액으로 포인트를 차감한다. 할인 기능은 `/productList`, `/productDetail` 응답에 `discountPrice`(할인 판매가, `discountFlag`가 true일 때만 유효)와 `discountFlag`를 추가해 개발 서버에 반영했고, 구매 시 할인 기간이면 할인 금액으로 차감한다. 앱에 전달되는 상품 순서는 등록 순(`idx` 오름차순, 같으면 productCode 오름차순)이다. 개발 서버 구매 테스트는 잔액관리 테스트 상품으로, 할인가는 어드민에서 수정해 테스트한다. 03-05 `/productDetail`의 mdn은 쿠폰 구매(`/couponPurchase`) 때 등록되는 테이블에서 조회하므로 구매 이력이 없는 사용자는 내려오지 않는다. 01-19 주행로그 업로드 파싱 실패 로그는 SKP 모바일 상품권 유효기간별 응답 메시지 배포와 함께 상용에 반영하기로 했다.
- 03-27 NIA 홍수 API 규격: 응답은 `code`, `message`, `data[]`이고 항목에 `eventId`, `msfrtType`, `instt`(기관 구분), `dataClsf`(홍수경보 발령정보/댐 방류정보), `content`(이름, 좌표 ID, 좌표, 영향 영역 POLYGON, 내용, 시작/종료 일시)가 있다. `contentEndDt`가 없으면 해제 전까지, 있으면 그 시간까지 서비스하고, 수집 주기는 성수기 기준 1분에 1회, DB는 좌표 ID를 key로 관리한다.
- 03월 초 에이전트 상용 반영 항목은 택시 기사앱 탐색 옵션 변경, SKP 광고 활성화 flag 필드, admin 상품 예약기간 타입 변경 3가지였고, 이 때문에 월요일 반영은 위험하다는 서버 개발자 의견으로 원래 일정(화요일)을 유지했다.
- 02-05 경로탐색 918 오류: 탐색엔진 응답 timeout이 대부분이고 간헐적으로만 성공했다. 같은 날 11시 지도 오픈과 연관이 의심됐고 이전 지도에서는 정상이었다.
