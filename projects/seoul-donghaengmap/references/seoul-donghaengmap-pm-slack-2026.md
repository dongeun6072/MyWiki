# 서울동행맵 고도화 PM 채널 2026

사업 총괄 이사가 일정, 서울시 협의, 산출물 방향을 지시하고 공유하는 채널이다. 채널 설명은 "현재 서비스 중인 동행맵을 기초로 리뉴얼·고도화(연내 시범서비스 런칭, 2027년 4월 안정화)하며 음성 AI와 실시간 API 연계를 쓴다"이다. 내부 개발 이야기는 [[seoul-donghaengmap-dev-slack-process-2026]], 협력사와의 대화는 [[seoul-donghaengmap-consortium-slack-2026]], [[seoul-donghaengmap-papaya-slack-2026]]에 있다. 사람은 역할로 적었고 링크·계정·서버 주소는 옮기지 않았다.

## 2. 기획·디자인 문서 흐름

- **디자인 컨셉 v1.0**(08-20): 컬러 시스템을 현재 서울동행맵 컬러로 바꾸고 컬러 설명은 아이콘 스타일 중심으로 정리했다. 적록색맹 블러 처리 페이지는 제거하고 "전맹" 시안에 한 줄 설명을 달았다. 음성인식 화면은 제외했다(채팅형이면 다시 듣기가 가능하므로 추가 고민 후 반영).
- **메뉴트리·워크플로우**: 메뉴트리만으로는 길안내 같은 핵심 기능이 시나리오 중간에 나올 때 정보를 통합 제공하기 어려워, 전체 구조와 위치는 메뉴트리로, 기능 정보는 워크플로우로 분리해 한 파일에 담았다. 음성인식은 모든 화면에서 쓰기 어렵다고 판단해 기본 스크린리더로 동작시키고 음성은 진입점 기준으로 처리하기로 했다.
- **기획서 v0.7**(08-27): 25p에 "5종은 RFP '…등'의 예시이며 닫힌 목록이 아니다. 발화 변형·미인식 처리는 NLU 명령어 리스트(아로, ~10/26) 수령 후 확정"이라는 취지의 문구를 넣었다. 저상버스 예약은 MQTT→관제→차량 단말기로 즉시 전달되고 BIS에서 취소 기능이 없어 단말기 개조가 필요하므로, **앱이 예약 정보를 저장했다가 사용자가 정류장에 있을 때 발신**하는 구조를 검토했다.
- v0.8 보완: '자주 가는 곳'으로 용어 범용화, 인근 편의시설을 사용 빈도순으로 재배치하고 유형에 맞는 필터만 노출, '내비게이션' 표기 통일, [길안내 종료] 라벨과 전맹 버튼 신설, 도착지 용어, 인근 300m, 0건 필터 유지. 기획서에서 미결·검토 중 행은 빼고 잔여는 md와 ADR로 관리한다.
- 확인 질문의 답: 실내 내비는 이번에 추가, 지하철역에도 필터 추가, 불편신고 '기타' 유형은 제외, 즐겨찾기 프리셋 명칭은 삭제만 가능하던 것을 편집 가능하게 변경, 글자 크기 설정은 RFP 접근성 항목("텍스트 크기 조절")과 PRD "기본/크게"에 근거하며 RFP가 OS 폰트 조절로 충족되면 앱 내 옵션은 유지하지 않아도 된다. → [[seoul-donghaengmap-screen-design-revisions]]
- **v1.0**(09-23): 모든 화면 사양 정리. 다국어 누락과 해석하기 어려운 문구가 지적됐다. 내비 가로 모드는 기존 앱에 있어 추가했다가 필수 여부 확인 후 제외했다. 이후 문서는 CF 페이지 안에 추가해 배포하고 슬랙에는 요청이 있을 때만 올린다. → [[seoul-donghaengmap-screen-design]]

## 3. 감리·서울시 협의

- 감리 산출물과 지적 사항은 [[seoul-donghaengmap-dev-slack-process-2026]]에 정리했다. 이 채널에서는 지시가 이어졌다. 9-29 산출물을 NAS에 올리고 다음 주 감리를 준비, 10-12 진행 상황 공유, 10-26 최종 보고서 업로드와 컨소시엄 요청 사항 사전 공유.
- 10-7 앱 초기화 시 점검 공지·상태를 표출하는 서비스 점검 테이블에 대해 백엔드 협력사 대표에게 문의가 왔다. 아로정보기술은 관리 주체를 정해야 하고 사전에 몰랐던 사양이라 관리 포인트 증가에 민감하다고 해 **이번 감리에서는 제거**하고 나중에 다시 논의한다.
- 10-21 서울시 주무관·팀장 미팅 안건: 설계 변경안, 앱·서버 개발 진행 현황, 설계 변경 시 추가 구축 가능한 역사 범위(15개까지 가능한지), 교통과장 보고 준비. 교통과장 보고(11-16~)는 설계 변경 보고와 앱 시연 중심이다.
- 같은 날 아로정보기술과 향후 계획을 논의했다. 이 미팅의 일정은 10-27에서 10-28로 바뀐 것으로 보인다. ^[ambiguous]

## 4. 스토어·서울시 자료 (9-2~10-26)

- 서울시 확인으로 서울동행맵은 IRM 평가 대상이며 대국민 배포 채널이 포함돼 스토어 4종(현재 3종)을 지원해야 한다.
- 서울시가 전달한 방향: 개발사 계정을 스토어 콘솔에 초대, 배포 절차는 아이나비가 맡고(이전에는 두 주체가 관리한다고 알려졌으나 하나가 유리), 소셜 로그인 개발자 콘솔 소유자는 서울시 관리 계정으로 이관하거나 신규 생성. 세부는 [[seoul-donghaengmap-dev-slack-process-2026]].
- 서울시 유지보수 업체를 통해 전달받는 자료를 공유하는 CF 페이지, 리허설 자료, 시연 사전 영상(용량 때문에 이번 주까지만 공유)을 안내했다.
- 10-26 시점에 서울시가 준 빌드·배포 자료에 대한 추가 요청 사항을 금일 중 공유하도록 요청했다. 서울시의 답은 채널에서 확인되지 않는다.

## 5. 백엔드 협업 방식

- 9-21 백엔드 협력사 대표와 통화: **기술 문서 기준으로 진행**하고 베이스 프로젝트는 아이나비가 공유하며(또는 우리가 받아 검토), 형상 관리는 아이나비 Bitbucket에서 한다. 아로정보기술 개발 서버가 정리되면 이관 여부를 정한다.
- DB는 MySQL 8. 작업 인원은 3명으로 이야기됐다. 계정을 새로 만들면 비용이 드니 개인별 접근 토큰을 발급해 쓰기로 했다(유효기간 최대 1년, 최소 권한으로 작업자 구분이 가능).
- 9-7 컨소시엄 개발 회의 To-do: 개발 환경 요구사항과 DB 설계를 전달하고, API 목록에서 각자 맡을 기능을 나눈다. Spring Boot 베이스 프로젝트는 공통 모듈화된 템플릿(인증, 권한 제어, 암호화, 표준 응답·에러 핸들링, DB 설정, AOP 로깅)을 참고하라는 취지다. 한글 라이선스는 과제 예산으로 처리 가능한지 확인 중이다.
- 역할 분담안(10-20~27)은 [[seoul-donghaengmap-consortium-slack-2026]]를 본다. 임시 개발 장비는 사내 서버에 협력사 계정을 만들어 쓰는 안이 나왔다. 협력사가 현행 사내 서버를 공용으로 쓰려면 구동 환경 보장과 분석 내용·이력 비노출이 필요했고, 서버 책임자는 1~2주면 괜찮지만 한 달이면 별도 서버 제공이 낫다고 했다. AI 보안 점검에서 타 계정·루트 접근과 허가되지 않은 FTP 경로 접근은 불가로 통과했고, 리소스 제한, 외부 통신 제한, 구 OS 사용은 문제로 지적됐다. 방화벽을 열어 협력사 접속이 확인됐고 최종 방식은 채널에서 명확하지 않다. ^[ambiguous]
- 프런트엔드 개발 정보는 서울시에 전달하려고 정리했다(CMP/KMP, INAVI Maps SDK) → [[seoul-donghaengmap-dev-slack-tech-2026]].

## 6. Mapxus 검토 (9-28~10-8)

- 팅크웨어 주관으로 홍콩 실내 지도·내비 업체 Mapxus와 미팅했다. Apple IMDF 서드파티 목록에 올라 있고 센서맵 기반으로 iPhone 실내 측위도 지원하며 정확도는 평균 2~3m라고 한다(실제 검증 필요).
- Core·UI SDK 검토에는 API 키와 시크릿이 필요해 지원팀에 요청했다(값 미수록). 한국은 공공데이터 제공 대상 국가가 아니라 **NDA 체결 후** 진행이 가능하고, 체결 후 실내 측위 협력 방안·PoC를 안건으로 콘콜을 하기로 했다.
- 10-8 지시: Mapxus UI SDK를 적용한 테스트 앱을 준비하는 시점을 공유할 것. 연휴로 답변이 늦어져, 기술 파트너로서 준비되면 코엑스 기준으로 파파야와 비교 검증하려 한다. → [[seoul-subway-station-grade]]

## 7. 미해결

- 설계 변경안과 추가 구축 역사 수(15개)에 대한 서울시 입장(10-27 미팅 이후 공유 예정).
- 11-13 통합 점검 범위와 서버 실연동 범위, 11-11~12 시청역 사전 점검.
- 파파야 시연 앱 소스 이관 가능성. 사업 총괄 이사는 파파야가 정부 과제 시연용으로 만든 앱이라 어려울 것으로 봤고, 맵매칭도 가까운 위치에 붙이는 기본 로직뿐이라 참고할 수준이 아니라고 했다. 결과는 확인되지 않는다.
- 아로 NLU 명령어 리스트(~10/26) 수령 후 음성 의도 사양 확정.
- 한글 라이선스 처리 결과.
